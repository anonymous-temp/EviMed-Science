# 文档解析 API（解析团队服务，v1.0.0，2026-10-27）

本文是 EviMed 平台调用解析团队文档解析服务时依赖的约定的摘要，权威文档是该服务自己的 API.md。服务地址和密钥只来自部署环境（`OPEN_SCIENCE_DOCUMENT_PARSER_URL`、`OPEN_SCIENCE_DOCUMENT_PARSER_TOKEN_FILE`），不写进仓库。

2026-10-27 之前的路径 `/api/v1/extract/text/file`、`/api/v1/extract/text/url`、`/api/v1/parse/file` 已经下线，现在回答 404。

## 认证

除 `GET /health` 外，每个业务接口都要带：

```http
Authorization: Bearer sk-<secret>
```

密钥只能放在 `Authorization` 头里。每把密钥有权限范围：不要元数据时需要 `parse`，要元数据（`extract_metadata=true`）时需要 `extract`，两者各自足够，不要求同时具备。

成功响应带额度头：`X-Quota-Unit`、`X-Quota-Cost`、`X-Quota-Remaining`（有限额度时是十进制整数，不限额度时是字符串 `unlimited`）。

## 接口

| 路径 | 方法 | 输入 |
| :--- | :--- | :--- |
| `/api/v1/parse/engine-a/file` | `POST` | `multipart/form-data` |
| `/api/v1/parse/engine-a/url` | `POST` | `application/json` |
| `/api/v1/parse/engine-b/file` | `POST` | `multipart/form-data` |
| `/api/v1/parse/engine-b/url` | `POST` | `application/json` |
| `/health` | `GET` | 无，不需要密钥 |

引擎 A 和引擎 B 只是两种解析引擎，不是主备：服务不会在两者之间自动切换，调用方自己选。引擎 A 速度快、价格低，支持全部格式，正文里 PDF 按 `[Page N]`、演示文稿按 `[Slide N]`、电子表格按 `[Sheet: name]` 分隔，并且成功响应默认带 `parse_info`。引擎 B 质量更高，格式更少（不含 CSV、音频、视频），`format` 和 `media_type` 为 `null`，没有 `parse_info`。平台默认用引擎 A，由 `OPEN_SCIENCE_DOCUMENT_PARSER_ENGINE`（`engine-a` | `engine-b`）选择。

### 上传文件（平台使用的接口）

表单字段：

| 字段 | 必填 | 说明 |
| :--- | :--- | :--- |
| `file` | 是 | 文件，上限 100 MB |
| `checksum` | 是 | 文件字节的 SHA-256（十六进制） |
| `filename` | 否 | 原始文件名，只作格式提示；只含可打印字符 |
| `format` | 否 | `auto` 或格式提示，必须与文件内容一致 |
| `extract_metadata` | 否 | `true` / `false`，默认 `false` |
| `ocr`、`ocr_languages` | 否 | 仅引擎 A；平台使用默认值 |

```bash
curl -X POST "$PARSER_URL/api/v1/parse/engine-a/file" \
  -H "Authorization: Bearer $PARSER_KEY" \
  -F "file=@/path/to/document.pdf" \
  -F "checksum=<SHA256>" \
  -F "extract_metadata=true"
```

## 响应

外层固定为 `{code, message, uuid, timestamp, elapsed_ms, data}`，`code` 与 HTTP 状态码一致。

```json
{
  "code": 200,
  "message": "success",
  "uuid": "C78339AE-7D25-4948-8826-2641556A5A06",
  "timestamp": 1781164619,
  "elapsed_ms": 1000,
  "data": {
    "content": "[Page 1]\n文档正文……",
    "format": "pdf",
    "media_type": "application/pdf",
    "parse_info": {
      "parser": "native-pdf",
      "parser_version": "13",
      "page_count": 1,
      "ocr_pages": [],
      "warnings": []
    }
  }
}
```

开启 `extract_metadata` 后，`data` 另有 `metadata`（`title`、`authors`、`abstract`、`keywords`、`publication_date`、`source`、`doi`，缺失为 `null`）、`metadata_status`（`succeeded` | `not_found` | `failed`）和 `metadata_error`。元数据由模型读正文首尾各 8,000 字符得出，只是标注，不是证据。分析失败时仍是 HTTP 200，带完整正文，`metadata` 为 `null`。

## 失败

失败时 `data` 是 `{"error_code": "..."}`。平台先看 HTTP 状态，再看 `error_code`：

| HTTP | `error_code` | 平台的处理 |
| ---: | :--- | :--- |
| 400 | `missing_file`、`invalid_extract_metadata` 等 | 拒绝，不重试（`source_parser_rejected`） |
| 401 | `invalid_api_key` | 密钥不被接受（`source_parser_auth_failed`），不重试，PDF/Word/PPT/Excel 改用平台本地读取 |
| 403 | `insufficient_scope` | 元数据请求被拒时只要正文再请求一次，十分钟内不再要元数据；正文请求被拒为 `source_parser_scope_denied`，改用本地读取 |
| 404 | — | 接口地址变了（`source_parser_route_missing`），不重试，改用本地读取 |
| 413 | `document_too_complex` | 文件过大或过于复杂（`source_parser_payload_too_large`） |
| 415 | `unsupported_format`、`format_mismatch` | 格式不支持（`source_format_unsupported`），只保存原件，不重复读取 |
| 422 | `empty_content` | 读过了、没有文字：保存原件，不编造文字 |
| 422 | `corrupt_document`、`encrypted_document`、`parse_failed` | 读不出文字（`source_parser_document_unreadable`），不重复读取 |
| 422 | `checksum_failed` | 校验失败（`source_parser_checksum_failed`） |
| 429 | `quota_exhausted` | 额度用尽（`source_parser_quota_exhausted`），不重试，改用本地读取 |
| 429 | `rate_limited` | 按 `Retry-After` 等待后重试，最多 3 次，仍失败改用本地读取 |
| 500 | — | 重试 1 次（`source_parser_internal_error`），仍失败改用本地读取 |
| 502 | `download_failed`、`upstream_error` | 重试，仍失败改用本地读取 |
| 503 | `service_draining`、`parser_dependency_unavailable` 等 | 按 `Retry-After` 重试，仍失败改用本地读取 |
| 504 | `parser_timeout` | 不重试（同一文件会再超时），改用本地读取 |

401 响应带 `WWW-Authenticate: Bearer`。

## 健康检查

`GET /health` 不需要密钥，返回 `data.status`（`healthy` | `draining`）等。它不检查密钥或接口地址：密钥无效或路径下线时它仍然回答 200。平台因此另外用不带文件的请求探测引擎接口（密钥被拒是 401、接口下线是 404，好的密钥和路径是缺少文件的 400，参数错误不扣费），把结果放进就绪状态和指标，不影响平台就绪。

## 平台的本地读取

服务不可用时（未配置、401、403、404、额度、限流、5xx、超时），PDF、Word（`.docx`）、演示文稿（`.pptx`）和电子表格（`.xlsx`、`.xlsm`）由部署自己的一次性读取容器从原始字节读出文字：PDF 按页加 `[Page N]`，演示文稿加 `[Slide N]`，表格加 `[Sheet: name]`。没有文字层的扫描件读不出文字，只保存原件，不编造。旧版 `.doc`、`.ppt`、`.xls`、图片和电子书没有本地读取。本地读取在来源记录里的解析器名是 `evimed-local-reader`，类型 `local-fallback`。
