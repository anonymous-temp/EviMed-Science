**唯一今天原样就能发出去的一段**，是 RQ-09 的第 (3) 小段（FAERS 舌下制剂口腔感觉异常 ROR）和 B 类 RQ-30 的第一段（造影剂/负荷药过敏反应 ROR）——两者都只用到 `evimed_adr_signal_analysis` 的既有 schema（drug + adverseEvent，不分层）。但即便这两段，交付出来也**没有任何门禁核验过它的算术**（见第二部分 · 改动三）。

三个「数据侧到底行不行」的技术问题，实测答案与担心相反：

- **openFDA 的四格表不需要 count 接口，分母是精确的。** 四次普通 search 读 `meta.results.total` 即可：N=20,692,690；nitroglycerin × Dizziness 得 a=3,043 / b=50,764 / c=488,238 / d=20,150,645，其中减法算出的 d 与直接查 `NOT drug AND NOT event` 得到的 d **逐位相同**（20,150,645）。`skip` 上限 25,000 只管记录检索、不参与分母（实测 skip=25000 OK，skip=25001 → BAD_REQUEST）。真正会截断的是 count 接口：limit=999 可用、limit=1000 返回 API_KEY_MISSING、count 配 skip 返回 BAD_REQUEST「Should not use skip param when using count」——只有 RQ-26 这类事件优先全库扫描撞得上（Stress cardiomyopathy 的药物扫描正好返回 999 个词，已饱和）。
- **CTG v2 的分页在公网上轻松跑完。** 房颤×可穿戴（2010–2025）totalCount=4,142；收窄口径实跑 471 条 / 5 页 / 2.7 秒 / 累计 342,331 字节 / 单页峰值 73,428 字节，远在网关 16 MB、60 秒限额内。截断不是被 API 截的，是被我们自己的连接器截的。
- **WHO GHO 的 `$filter` 不会被 URL 编码搞坏。** 裸 `$filter`、`%24filter`、Node `new URL()` 规范化后三种写法全部 200；`odata` 参数化的 content-type 被网关按 `;` 切首段得 `application/json`，能过。GHO 的问题不在编码，在数据本身不存在（见第三部分）。

## 为什么「今天能跑」是零 —— 三层卡点，逐层都实证过

**第一层：取数工具够不着。** 每一族的公网链路我们都跑通了，平台的连接器却停在第一跳：

| 数据源 | 公网实测 | 平台连接器做到哪 | 差距 |
|---|---|---|---|
| openFDA `/drug/event.json` | 200，20,692,690 份报告，四格表精确 | 有 `adr_signal`，公式（ROR/PRR/χ²/IC/EVANS）属实 | 无国别、年龄、性别、第二种药、事件优先 |
| openFDA `/drug/enforcement.json` | 200，17,866 条召回，Class I 1,734 / II 14,427 / III 1,704 | **全平台没有任何连接器能调它**（grep `enforcement` 只命中 OOXML 噪声） | 整条能力缺失 |
| openFDA `/drug/label.json` | 200，261,760 份标签，`route:SUBLINGUAL AND generic_name:nitroglycerin` = 38 份 | `LABEL_LIMIT` 上限 3，无分页 | 普查不可能 |
| ClinicalTrials.gov v2 | 200，471 条 5 页 2.7 秒跑完，13 个字段齐全 | 单次请求、100 条、6 字段、无 `filter.advanced` | 普查退化为「第一页的 6 个字段」 |
| DailyMed | hop1 200（nitroglycerin 109 份 / 2 页），hop2 `spls/{setid}.xml` 200 / 58,579 字节（`.json` 返 415） | 只有 hop1 | 正文抽取无通路 |
| WHO GHO | `/api/{IndicatorCode}` 200，NCDMORT3070 + CHN 返 66 行 | 只查 `/api/Indicator` 名录 | 拿不到任何一个数据值 |
| gnomAD | POST 与 GET `?query=` 都 200，rs671 各群 AC/AN/hom 齐全 | 只接受基因符号，只回 `{gene_id, symbol}` | 变异级查询不存在 |
| PubChem | `assaysummary/JSON` 200（borneol 51,681 B / TMP 361,424 B） | 只有 `property` | 活性记录取不到 |
| GtoPdb | ligands → interactions → databaseLinks 三跳全通 | 只有 `targets?name=` | 配体活性取不到 |
| DGIdb | `drugs(names:[…])` 200，NITROGLYCERIN → 13 基因含 ALDH2 | 锁死 `genes(names:$names)` 且长度必须为 1 | 药→靶方向不可用 |
| STRING | GET `/api/json/enrichment` 200，130,922 B，394 条，自带 p_value 与 fdr | 只有 `json/resolve` | 富集不可用（但 GET 形态能过网关，是唯一零网关改动的一条） |

| OpenGWAS | `/api/status` 200（v4.0.0，50,055 个公开数据集），数据端点全部 401 | 连接器形状正确（`public_sources.py:2987` 用的是 v4 存活的 query-string 形式） | 缺一把钥匙 |

**第二层：路由把题送错门。** 四条正则都实证过：

- MR 线（`specialistRouting.mjs:49`）要求字面出现「孟德尔随机化 / mendelian randomization / two-sample MR」。分诊表里那 8 道 MR 题全是自然语言因果问句（「睡眠时长对房颤有没有因果影响」），一个都不匹配。
- ADR 线（`:45`）要求委托动词 + 「药物警戒/FAERS/openFDA/disproportionality/ROR/PRR/EBGM」之一。语义问句（「含服后头晕心悸有多常见」）落到 LLM 分类器 → `open-domain-answer`，那条线**根本没有 FAERS 工具**。
- 路由正则里没有靶点、通路、富集、网络药理、普查、等位基因频率任何一个词。
- 未命中时的兜底（`:185-190`）是 `clinicalSubjectMatch && explicitReportIntent` → `clinical-evidence-synthesis`，即**全平台唯一带 `evidenceClaimsTraceable` 的那条线**。

**第三层，也是最要紧的一层：门禁形状。** 逐个 `agent.yaml` 核对的 `completionChecks`：

| 专科线 | completionChecks |
|---|---|
| clinical-evidence-synthesis | requiredOutputsExist + citationsResolvable + **evidenceClaimsTraceable** + skillsLoaded |
| comprehensive-drug-evaluation / drug-selection / off-label-analysis | + citedSourcesRecorded（只查引的 URL 在不在快照里，不查数字） |
| adr-analysis / mendelian-randomization / meta-analysis / bibliometric-analysis / peer-review | 只有 requiredOutputsExist + citationsResolvable |
| dataset-research-scoping / research-topic-selection | + skillsLoaded |
| open-domain-answer | skillsLoaded + citationsResolvable + citationIntegrity |

于是原始数据分析只有两种下场，**没有第三种**：

- **送进 clinical-evidence-synthesis → 被拒。** `derived` 声明本身是为「算出来的数」准备的（`clinicalEvidenceQuality.mjs:21-47`，不要求原文引用，改要 method/assumptions/sensitivity），但 `:1657-1682` 强制 `derivedFrom` 链必须终结在一条非 derived 的 measured 主张上，而 measured 主张要求 `artifactPath` 落在 `.evimed-sources/` 且 `supportQuote` 在该文件里逐字命中（`:1627-1637`）。全仓只有两处写这种工件：`official_pages.py:193/213`（白名单 7 个 HTML 站点：cochrane、acc、professional.heart.org、cpr.heart.org、nhs.uk、ccfdie、mpa.hunan.gov.cn）和 `open_access_fulltext.py:325/345/383/407`（按 DOI/PMCID）。`api.fda.gov`、`gnomad.broadinstitute.org`、`clinicaltrials.gov`、`string-db.org` 一个都不在。**API 的返回体永远变不成可引用工件，链条永远够不到 measured evidence。** 不是硬拒（`qualityDegradable:true`，最后标 unverified 交付），但会先把两次修复机会（`agentRuns.mjs:1439`，`maxClinicalRepairAttempts = 2`）花在一个结构上不可能满足的要求上。
- **送进 adr-analysis / mendelian-randomization → 不被验。** 这两条线的 `citationsResolvable`（`agentRuns.mjs:925-949 / 1148-1159`）只检查 `.md` 里的 URL 能不能解析、有没有带凭据、是不是部署内网地址——一个 `api.fda.gov` 查询串轻松通过。**没有任何东西重算过 ROR、核对过四格表、确认过引用的查询串真能返回报告里那个数、校验过 PT 是不是真的 MedDRA 词。**

全平台唯一真核验计算结果的机制，是 `dataset-research-scoping/scripts/preflight.py:292` 的 `check_profile_recomputable`（重跑 `data-profile.py` 与 `data-profile.json` 逐项比对）——而那条线因为 `requiredInputs` 写死 `datasetPath`、`specialistClassifier.mjs:77` 又明确指示分类器拒绝「只描述了数据而非提供了数据」的请求，恰好是这 13 题全部进不去的。

**并且退路不存在。** `deploy/web/docker-compose.yml:866-869` 把 `runtime-internal` 声明为 `internal: true`，`config.mjs:601` 生产默认 `allowRuntimeNetworkEgress=false`，`runtimeManager.mjs:2764-2785` 还要求 `OPEN_SCIENCE_ALLOW_RUNTIME_NETWORK_EGRESS` + `..._POLICY_ACK` 两个显式开关。**在 skill 脚本里写 `requests.get('https://api.fda.gov/...')` 在生产跑不通**（本机能直连是开发机形态，不是生产形状）。分诊表没写这一层，但它决定了「不改平台、自己写脚本 curl」这条路根本不成立。

例外只有一条：MR 族不走网关。`docker-compose.yml` 的 `evimed-mr-agent` 挂在 `default` 网桥上，R 模板里的 `library(ieugwasr)` 直连 `api.opengwas.io`，token 以 `OPENGWAS_JWT` 环境变量注入（compose:480 → `specialist_jobs.py:35` 白名单 → `:380` 注入子进程）。两个后果都要记住：**给 MR 接 FinnGen 不需要动服务端白名单；但也没有任何东西沙箱化那个容器取什么。**

## 改动 1 · 配 OpenGWAS token（零代码解锁 8 道题，性价比第一）

**症状。** `api.opengwas.io/api/status` 活着（v4.0.0，build 20260721.1856，SERVICES__ASSOCIATIONS=Operational，50,164 个数据集 / 50,055 个公开），但每一个取数端点都回 401：「From 1st May 2024 you must provide a token (JWT)」。本机 `deploy/web/.env` 根本不存在，`.env.example` 里**连 OPENGWAS 这个词都没有**——运维照着示例文件配，永远不会知道要配它。`source_catalog.json` 把 `opengwas-ieu-gwas` 标为 `ready_credentials`（即未接通）；`PROGRESS.md` 记着上一个 token 已于 **2026-07-31 02:51:26 UTC** 过期，`audit:capabilities` 从那天起一直是红的。

**除了 token，这条线其余都是好的：** `deploy/specialist-adapter/Dockerfile:41` 装了 r-base 全家桶，`:81` 跑 agent 自己的 `install_r_packages.R`，构建期校验每个包能 load 且 TwoSampleMR 的 pin 没被冲掉；`PROGRESS.md` 2026-08-01 在已部署镜像里实测过十个包可用、七个 pin 完好、MVMR 把模拟的 0.4 / 0.2 还原成 0.390 / 0.217。

**怎么改。**

1. `deploy/web/.env.example` 加两个变量，并写清它们是**两个不同的消费者**（极易只配一半）：
   - `OPENGWAS_JWT=` —— 给 `evimed-mr-agent`（`docker-compose.yml:480`），最终到 R 模板里的 `ieugwasr`
