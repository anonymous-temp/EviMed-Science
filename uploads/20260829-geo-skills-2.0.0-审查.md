# geo-skills 2.0.0 接入审查

日期：2026-08-29。方法：解包、跑通、逐条对撞、变异测试。所有数字均为实测，不是读文档得来的。

## 一、先说结论

**探测链路是真的，规则设计比我预期扎实，但它的自证能力有一个具体的洞。**

三件事分开说：

1. **能跑起来** —— 五家厂商全部就绪，真问了一题拿到真答案，14.7 秒。
2. **规则不是空壳** —— 88 条规则宣称的 88 个 check 函数全部真实存在，309 个测试全绿。
3. **但 78 条 BLOCK 规则里有 23 条可以被完全关掉而测试不红** —— 包括整组患者旅程（PJ-G01 到 G06）。

第 3 条是这份审查唯一要你现在就知道的事。

`probe_client.py` 里有一处设计我要单独夸一句：

> 「只有进分母的结果才算测到了，才可以复用。会话失效与服务繁忙是测量失败，不是测量结果——把它们缓存下来，断点续跑就会把失败原样重放，永远不再重试，而人还以为续跑补齐了。」

这正是我这两天在自己代码里反复挖出来的同一族缺陷（空不是错、失败长得像没干活）。写这段的人踩过同样的坑。

## 三、变异测试：哪些规则是真的

规则声明与实现的对照，我没有靠读，而是逐个函数改坏了跑：

| 检查 | 结果 |
|---|---|
| 88 条规则声明的 check 函数是否存在 | **88/88 存在** |
| 自带测试 | **309 passed** |
| 78 条 BLOCK 规则逐条改成 `return []`（等于关掉），看测试红不红 | **55 条被抓住，23 条存活** |

> **测量方法的一处校正（2026-08-29 补）**：这套测试里有一条 `test_readme_test_count_is_current`，
> 它断言 README 写的测试数与实际相符。补了 9 条测试之后重跑变异，结果一度显示「78/78 全被抓住」——
> 那是假的：任何一次变异都会让测试数变化，于是这条计数钉住的测试必红，掩盖了真实覆盖。
> 把它从变异判据里排除后，诚实数字是 **59 抓住 / 19 存活**。
> 我补的 5 条（IRON-04、PJ-G02、PJ-G04、PJ-G05、PJ-G06）确实咬合了——单独关掉任一条，
> 对应的对抗测试当场红。剩余 **19 条仍无对照**。

「存活」的意思是：**把这条铁律彻底关掉，309 个测试仍然全绿。** 它可能是对的，但没有任何东西证明它是对的；下一次重构把它改坏，没人会知道。

### 无对照的 BLOCK 规则（补测试前 23 条，补后仍余 19 条）

按它们保护的东西分组：

**患者旅程整组失守（6 条）** —— PJ-G01 阶段骨架与 Rx/OTC 身份一致；PJ-G02 每格标证据等级、标注率 100%；PJ-G03 用户原话必须带 corpus_ref；PJ-G04 情绪曲线三要素；PJ-G05 机会点必须两线交叉；PJ-G06 内容窗口三个实测值缺一不成立。

PJ-G02 的规则原文写着「把推演写成实测是本技能唯一不可接受的错误」。**这条规则本身没有一个测试。**

**语料与需求（5 条）** —— DM-G02 SEO 农场命中必须为 0；DM-G03 每条问法唯一主组；DM-G04 语料覆盖率下限；DM-G06 互动量 0 处用于人群比例推断；CN-G06 未采集到就写「无信号」并停下。

**证据与实测边界（4 条）** —— EF-G04 同源折减（五家转载同一篇算一条）；EF-G08 无差异时必须显式写出；VF-G01 实测与预估永不同列；VF-G05 探测面披露三元组。

VF-G05 的原文：「甲方当场用手机开深度思考复现不一致，现场即塌。」这条也没有测试。

**对客语言与合规（5 条）** —— X-WRITE 写作三铁律；X-JARGON 内部编号不得进对客件；PB-G03 概念集上限；CP-G01 资产必须绑 claim_id 且 on_label；CP-G07 资质前置。

**其余 3 条** —— CN-G04 证型主治逐字出自说明书；HR-E3 证据分级不得混入 GRADE；HR-E4 真实问法不得进证据引用。

## 四、与我们平台对撞：谁补谁

### 4.1 它有而我们没有的（必须接）

| 能力 | 对应需求 | 我们的现状 |
|---|---|---|
| 大模型逐平台探测 | R-026~R-033 | **零** —— 26 个 MCP 工具全在文献/药学侧 |
| 社媒真实问法采集 | R-018 | **零** |
| KPI 口径与测算 | R-034~R-044 | **零** —— 无「监测次数作分母」概念 |
| 语义作战表与存量/增量闭合 | R-012~R-017 | **零** |
| 全案交付物编排 | R-052~R-060 | office 技能在，但无 GEO 交付合约 |
| 单一权威数据源 | R-065 | **零** |

### 4.2 我们有而它更弱的（不要退让）

| 能力 | 我们的实现 | 它的实现 |
|---|---|---|
| 引语逐字绑定原文 | `supportQuote` × `sourceArtifacts`，标点容差的 `passageSkeleton` 比对，取不到原文时明说「无法核对」而不是判错 | 有 `corpus_ref` 概念，但无逐字比对机制 |
| 「没查」与「查了没有」分开 | 撤稿检查、证据表、覆盖台账三处都强制区分 | `collection_status` 有此意图（CN-G06），但**该规则无测试** |
| 每处修复配变异对照 | 今天 16 个提交每个都配 | 55/78 有，23/78 没有 |
| 门禁预算纪律 | 全系统 6 个阻断点，新检查先 notice | 78 条 BLOCK，无预算概念 |

**这一条要特别注意**：这套包有 78 个 BLOCK。按我们的纪律（阻断点是预算，新检查先 notice 再阻断），直接照搬会让交付几乎必然被卡住——而卡住之后运行没有可修的路径，就会开始为通过而写，那正是我今天在 rq03f 里抓到的事（运行读了阅卷代码，按能过的方式组包）。

### 4.3 两边同构、可以直接对接的

- **实测/推算/历史复用必须分层**（R-001）↔ 我们的 `claimType: direct/synthesized/derived` + `provenance_layers L1/L2/L3`。语义几乎一致。
- **确定性计算与 LLM 分工**（R-072）↔ 我们的「LLM never does statistics」。同一条纪律。
- **对客件清洗内部语言**（IRON-05 / R-061 / R-062）↔ 我们今天刚做的 `revision-notes.md` 出口 + 14 个合约的正文扫描。**它有黑名单，我们有出口**——两者应该合并：黑名单负责判定，出口负责给去处。没有出口的黑名单，运行会把内部话术藏进正文。

## 五、我的建议

**接入方式：作为能力包接，不作为插件接。**

理由是我们已定的纪律（socket 是唯一插件面，新功能一律走能力包），而且这套包本来就是 skill 形态 + 独立 python 脚本，正好落在 `capabilities/geo-*/` 与 `capability-skills/` 里。三条通道（探测/社媒/联网）走 MCP 工具，由网关持有凭证——**运行时永远拿不到 key，这一条不能因为接入 GEO 而破例**。

**接入前必须补的三件事：**

1. **给那 23 条 BLOCK 补对照测试**，或把它们降级为 notice。二选一，不能维持现状——一条没有对照的 BLOCK，比没有这条规则更危险，因为它给人一种被保护了的感觉。
2. **78 个 BLOCK 要重新分档**。按我们的预算纪律，先跑一批真实项目、看实测分布，再决定哪些真的该阻断。其余先 notice。
3. **探测通道要进网关白名单**，`43.248.117.249:9999/9966` 目前不在 `publicSourceGateway.mjs` 的 80 个允许主机里。

**我判断能做到的**：R-020~R-025（证据链）我们本来就比要求做得严；R-026~R-033（实测）这套包已经实现且实测可用；R-034~R-044（KPI）它有 `compute_metrics.py`，需要与我们的合约校验器对接。

**我判断风险最大的**：R-039（内容准确性逐条医学审核）和 R-069（发布前医学终审）。这两条要的是逐条医学判断，量大且不可自动化——78 个 BLOCK 里没有一条能替代它，我们的 `clinical-safety-rules.json` 也只覆盖药物/场景规则。这是需要人的地方，方案里必须诚实标出来，不能承诺自动化。
