## 四、授权：按学术平台口径

**ToolUniverse 是 Apache-2.0，管的是客户端代码，不管它取回来的数据。** 每个上游库有自己的条款——但作为学术平台，绝大多数走免费学术通道。

### 学术免费，注册即可(接线我已做完)

| 数据库 | 条件 |
|---|---|
| **DisGeNET** | 学术免费。注意其条款按**机构属性**判定，不是按用途 |
| **AlphaGenome** | 其条款本身就是 free non-commercial，学术使用正好落在里面 |
| **COSMIC** | 学术免费，**必须用机构邮箱注册** |
| **DrugBank** | 有面向学生/教师/科研的免费学术库 |
| **BRENDA** | 学术免费(需账号 + 密码) |
| **OMIM / PharmVar / Addgene / BioGRID** | 学术免费，需注册 |

### 仍需你的法务确认一项

**UMLS**：NLM 本身不收费，但内含 SNOMED CT 归 IHTSDO 所有、**仅在成员国免费**；另有 Category 1–4 受限词表(如 AMA 的 CPT)。中国的部署是否在覆盖范围内需确认——这一条不因学术/商业而免除。

### 有一件事我必须说一次

**DisGeNET 的措辞是按组织属性判定的**，原文：*"A commercial license is required if you belong to a commercial company wishing to use DISGENET in any capacity"* —— 注意是 *belong to*，不是 *use it for*。如果 EviMed 的**运营主体是公司**(即便平台定位学术、用途学术)，它们的学术许可可能不适用。同类条款在 COSMIC("not-for-profit organisation only")也存在。

这一句说完就过——按你给的口径我已经把这些都配好了。如果运营主体是公司，请在注册时如实填写，让对方判定；不要用学术身份注册再用于公司运营的平台，那是这类许可最典型的踩线方式。

### 商用自由，无需担心

openFDA(美国公有领域)、NCBI / PubMed、Crossref、Semantic Scholar、OpenAlex、Unpaywall、ClinicalTrials.gov

### 授权控制点是一个开关

实测验证：**不给 key，对应工具根本不注册**。

```
无 DISGENET_API_KEY 调用 → ToolUnavailableError: Tool not found
无任何 key 调 openFDA    → 正常返回(华法林黑框警告)
```

compose 里凭证**全部写成可选**(没有一个是 `:?required`)，所以没拿到许可的库，不配 key 它的工具在系统里就不存在——无论原因是「还没申请」还是「不够资格」。

## 五、我已经接完的(不依赖你)

### ToolUniverse sidecar(Apache-2.0)

2741 个工具 / 618 类，其中 **439 个直接在循证路径上**：openFDA 药品标签(156)、OpenTarget(61)、ChEMBL(29)、临床试验(16)、GWAS Catalog(13)、PharmGKB(10)、CPIC(9)、DailyMed(9)、ClinVar / dbSNP(各 3)、DisGeNET(5)、UMLS(5)、PubTator、medRxiv、DOAJ、OpenAIRE、**Crossref 撤稿检查**。

**架构**：不装进运行时镜像。实测 `p0-internal` 是 `internal=true`，容器**完全没有外部连通性**(三个探测全 000，DNS 不解析) —— 装进去根本跑不通。做成 sidecar：它持有自己的 key 和出口，运行时经内网 MCP streamable-http 连它，容器仍然两样都不持有。默认关闭，不配 URL 就不发 MCP 行。

**为什么不能做成 DSH 插件**：DSH 插件是 Node/Cordis ESM 包，ToolUniverse 是 Python。而 `@deepseek-ai/dsh-mcp-client` 正是 DSH 官方的外部工具接入机制 —— 我用的就是它。

### 网关白名单 64 → 80

- **修掉四处自相矛盾**：`gwas.mrcieu.ac.uk`(MR)、`api.ror.org`(meta / 文献计量)、`pmc.ncbi.nlm.nih.gov`(药物安全)、`pubmed.ncbi.nlm.nih.gov`(文献计量)—— 被已交付 agent 实际调用却不在白名单
- **新增 12 个**：FinnGen、eQTLGen、Retraction Watch、Epistemonikos、CPIC、CELLxGENE、Single Cell Portal、DECIPHER、SEER、NHANES、ESC、EMA

### 凭证接线

NCBI / openFDA 走「可选限流键」通道(它们无 key 也能用，放进强制凭证表会让现有调用全部 403)；运行时自带 `api_key` 一律拒绝，不允许伪造别人的配额。

六个专科 agent 的凭证接线全部补齐：bibliometric 的 `NCBI_API_KEY`/`NCBI_EMAIL`、meta 的 `PUBMED_API_KEY`/`PUBMED_EMAIL`/`EVIMED_API_KEY`、MR 的 `UMLS_API_KEY`/`OPENGWAS_JWT`。

### 三条新守卫

| 检查 | 防什么 |
|---|---|
| `credential_host_variables_agree` | 同一凭证被两个不同宿主变量读(OpenGWAS 就是这么空了两天) |
| `specialist_agent_credentials_wired` | agent 代码在读、compose 从不传 |
| `every host a shipped specialist agent calls is on the gateway allowlist` | 已交付能力调用未放行的主机 |

三条都从源码推导要求，不是抄清单，变异对照全部咬合。

## 六、安全说明

所有凭证只存在**控制面和 sidecar**，运行时容器永远拿不到任何 key。
网关在转发时注入 header/query(`publicSourceGateway.mjs:689-692`)。
你给我的 key 我只写进 `/srv/evimed-science/shared/secrets/` 下的文件并用 `*_FILE` 变量引用，不会出现在日志、argv、提交或聊天记录里。

**ToolUniverse sidecar 不给 `OPENAI_API_KEY` / `AZURE_OPENAI_API_KEY` / `GEMINI_API_KEY`** —— 它的 agentic 工具会拿这些自己调模型。本部署所有模型调用必须走我们的网关、用认证过的模型、计入运行预算。
