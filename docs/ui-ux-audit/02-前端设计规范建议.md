# EviMed Science 前端设计规范建议

> 基于《01-调研报告.md》的发现撰写。目标：把现有"暖纸 + 赤陶"的视觉底子体系化，消灭三套分裂（语言、形态、品牌），让设计 token 从"完成一半"变成唯一事实源。
> 规范适用对象：`OpenScience/apps/desktop`（桌面 + hosted web）、`记忆模块/web`（Memos 嵌入侧）、meta HTML 报告模板（远期）。

## 1. 设计原则

1. **证据感（Evidence-first）**：界面服务于"可追溯"——引用、版本、来源永远比装饰重要；交互反馈必须区分"成功 / 失败 / 中断 / 无结果"四种结局，不允许"静默跳过"。
2. **平静的密度（Calm density）**：科研工具信息密度高，但默认界面保持安静——工具过程折叠、状态收敛为徽章、颜色只在有语义时出现。
3. **一套语言**：面向中文科研用户，UI 文案以简体中文为基准语言；英文仅用于专有名词与代码语境。
4. **Token 唯一事实源**：任何颜色、字号、圆角、阴影、z-index 不允许字面值进入组件代码；例外（如"文档纸张"预览）必须以命名 token + 注释声明。
5. **键盘与鼠标平等**：所有鼠标可达的操作必须有键盘路径；所有 hover 才出现的内容必须 focus 可见。
6. **双形态一致**：桌面与 hosted web 共享同一信息架构与视觉语言，差异只允许由"能力有无"（如本地 shell）产生，不允许产生两套页面实现。

## 2. 色彩系统

### 2.1 品牌与语义色（在现有 token 基础上修订，亮色需过 WCAG AA）

| Token | 亮色（建议值） | 暗色 | 用途 | 备注 |
|---|---|---|---|---|
| `--bg` | `#f7f5ef` | `#16151a` | 页面底 | 维持现状 |
| `--surface` | `#ffffff` | 现有暗色值 | 卡片 | 维持 |
| `--surface-2` | `#f2efe7` | 现有 | 次级面/用户气泡 | 维持 |
| `--text` | `#2a2723` | 现有 | 正文 | 维持 |
| `--muted` | **`#6f6a61`**（现 `#8c877d` 仅 3.1–3.6:1） | 现有（已达标） | 辅助文字 | **必改**，现不达 AA 4.5:1 |
| `--accent` | **`#b04e2a` 或加深至 ≥4.5:1**（现 `#c15f3c` 4.23:1） | `#d0764f`（达标） | 品牌主色/主按钮 | 若坚持现状，则限定 accent 只用于大字/图形，不用于小字 |
| `--accent-fg` | `#ffffff` | `#16151a` | accent 上的文字 | **禁止绕过**，现状有 4 处硬编码 `text-white`（`MemoryPage.tsx:196,294`、`ConfirmDialog.tsx:50`、`WebProjectsCard.tsx:248`） |
| `--link` | `#2a6fdb`（核对小字对比度） | 现有 | 链接 | — |
| `--warn` | **加深至 ≥4.5:1**（现 `#c98a2b` 2.94:1） | 现有 | 警告 | 必改 |
| `--ok` | 加深至 ≥4.5:1（现 4.08:1） | 现有 | 成功 | 必改 |
| `--error` | 微调至 ≥4.5:1（现 4.49:1） | 现有 | 错误 | 微调 |
| `--border` / `--border-faint` | 现有 | 现有 | 分隔 | 非文字，3:1 即可 |

规则：
- 颜色只允许经 `bg-accent / text-muted / border-border` 这类语义类名出现；**禁止 `text-white`、`bg-black/70`、`#hex` 字面值**进入组件（lint 强制，见 §11）。
- 状态不允许只用颜色圆点传达：必须"颜色 + 形状/文字/图标"冗余编码（CVD 友好）。典型反例：侧栏会话圆点恒绿 `bg-ok`（`Sidebar.tsx:155-159`）——应映射真实状态（运行中=脉冲蓝点、失败=红点、完成=无点或灰点）。
- 图表色 `--series-1..8` + `--chart-grid/axis` 维持与 `@ai4s/shared`、matplotlib 三方同源的现状，新增图表一律经 `chartPalette(theme)` 取色。
- `theme-color` meta 与 favicon 换成 EviMed 品牌资产（现残留上游蓝 `#2563eb`），并按亮暗主题用 media 属性分别声明。

### 2.2 "纸张"例外的正规化

`MarkdownViewer` document 变体、`FigureBlock` 图区、文档预览刻意在暗色下保持白纸底——保留这个设计决策，但把 20+ 个硬编码 hex（`MarkdownViewer.tsx:29-57`）收敛为一组命名 token（如 `--paper-bg/--paper-text/--paper-accent`），品牌色不再硬写。

## 3. 字体与字号

- 字体栈维持：Inter（UI）/ Source Serif 4（页面标题、报告感标题）/ JetBrains Mono（代码、命令、数据）。Memos 侧引入同款 Inter + 中文回退栈，替换系统栈。
- **字号刻度收敛**（当前 `text-[10.5/11/12/12.5/13/13.5/15/26px]` 等 251 处任意值 / 45 个文件）为 6 档语义刻度，写进 `tailwind.config.js` 的 `fontSize` 扩展：

| 刻度 | 大小/行高 | 用途 |
|---|---|---|
| `caption` | 11px / 1.4 | 徽章、元信息、时间戳（替代 10.5/11px） |
| `ui-sm` | 12.5px / 1.45 | 次级按钮、chip、辅助行（替代 12/12.5px） |
| `ui` | 13.5px / 1.5 | 默认 UI 文字、列表行（替代 13/13.5px） |
| `body` | 15px / 1.65 | 对话正文、markdown 正文 |
| `title` | 20px / 1.3 (serif) | 页面标题 |
| `display` | 26px / 1.25 (serif) | 品牌级标题/空态 |

- 规则：`text-xs/text-sm` 与任意值并存的局面二选一收敛；lint 禁止 `text-[*px]`。
- 中文排版：正文行高 ≥1.6；数字与西文用 tabular-nums 场景（运行记录、计时）加 `font-variant-numeric: tabular-nums`。

## 4. 间距、圆角、阴影、层级

- 间距沿用 Tailwind 4px 标尺；页面级容器宽度收敛为 4 档：`content-narrow: 672px`（设置/表单）、`content: 760px`（对话流）、`content-wide: 1024px`（笔记本/运行记录）、`content-full: 1080px`（记忆/目录），替代 `max-w-[760px]` 等散值。
- 圆角三档：`rounded-input: 10px`、`rounded-card: 14px`、`rounded-chip: 999px`；消灭 `rounded-[5/6/16/18/20px]` 散值（MemoryPage、NotebooksPage、AttachmentLibraryStates 等）。
- 阴影两档：`shadow-card`（静态卡片）、`shadow-pop`（浮层）；消灭 `shadow-sm/md/lg` 裸用。
- z-index 建立刻度（参考 Memos 已有做法）：`base 0 / sticky 10 / overlay 40 / drawer 40 / modal 50 / popover 60 / toast 70`；禁止 `z-[1]/[2]/[3]` 字面值。

## 5. 主题与暗色

1. 主题选项改为三档：**浅色 / 深色 / 跟随系统**（现状只读一次 `prefers-color-scheme`，`store.ts:18-24`）；跟随系统时监听 `change` 事件实时切换。
2. **hosted web 必须有主题入口**：在 AccountPage 加 Appearance 卡（现状托管端无任何切换入口）。
3. 暗色适配规则：所有颜色走 CSS 变量即自动适配（现有方案自洽，保持）；任何新组件禁止 `dark:` variant 与变量混用——统一走变量。
4. 切换入口收敛：设置页 + ⌘K 两处维持，外加 Memos 侧主题与平台联动（嵌入时跟随平台 data-theme）。

## 6. 布局与响应式规范

- 断点沿用 Tailwind 默认（sm 640 / md 768 / lg 1024 / xl 1280），并明确各断点行为：
  - **右栏检查器（RightPane）**：≥lg 为侧栏面板；**<lg 降级为全屏 overlay / 底部抽屉**（复用现有 `fixed inset-0` 最大化分支），禁止 `hidden lg:block` 一藏了之。
  - Sidebar：<md 时可整栏折叠为图标栏（Memos 的 64px icon 导航即现成范式）。
  - FilesPage 目录树改为可拖宽（与 Sidebar/RightPane 一致），<md 时目录树与预览改为单栏切换。
- hosted web 需要最小移动可用性：对话流 `max-w-[760px]` 在小屏应 `px-4` 全宽；ConfirmDialog `w-[360px]` 改 `w-[min(360px,92vw)]`。
- macOS overlay titlebar 的 78px 留白抽为共享常量/组件（现散在 4 个文件：`AppShell.tsx:93`、`LiveSessionPage.tsx:186`、`Sidebar.tsx:82`、`RightPane.tsx:108`）；平台判定抽 `lib/platform.ts`，消灭 `userAgent.includes("Mac")` 重复。

## 7. 组件规范（建设 `packages/ui` 的蓝图）

`packages/ui` 目前是空壳（只有 README）。建议分两期：

**一期（就地收敛）**：把散在各页的重复实现抽到 `apps/desktop/src/components/ui/`，共 8 个原语：

| 组件 | 现状来源 | 状态矩阵要求 |
|---|---|---|
| Button | Settings 的 `btnGhost/btnAccent`（`SettingsPage.tsx:1111-1130`） | default/hover/active/disabled/loading + focus-visible ring；variant：primary(accent)/ghost/danger |
| Input / Textarea | Settings 的 `inputCls` | default/focus（border-accent + ring）/error/disabled；配 label 与错误文案插槽 |
| Card | 各页 `rounded-card border bg-surface shadow-card` | 统一 padding 刻度与可选 header/footer |
| EmptyState | 复活 `components/cards/EmptyState.tsx`（现仅死代码引用） | 图标 + 标题 + 描述 + 主行动按钮（重试/引导）四要素；全站空态统一收口 |
| SegmentedControl | MemoryPage/SettingsPage 两处自绘 | radiogroup 语义 + roving tabindex |
| Dialog / ConfirmDialog | 重写 `ConfirmDialog.tsx` | 焦点陷阱 + 初始焦点落「取消」+ Enter=确认 + 关闭还焦 + aria-describedby |
| Toast | 重写 `lib/toast.ts` + `Toaster.tsx` | `role="status"` + `aria-live="polite"`（error 用 `assertive`）；hover 暂停；error 时长 ≥6s 且可展开长文；支持 action 按钮（撤销/重试） |
| Skeleton | 推广 `ThreadSkeleton` 范式 | 每个列表页提供与内容同构的骨架，替代 spinner |

**二期（沉淀为包）**：稳定后移入 `packages/ui` 供 desktop 与后续 web 复用；补 Storybook 或最小 demo 页。Memos 侧不强行换组件库，通过主题 token 对齐视觉（见 §10）。

组件通用规则：
- 所有交互元素加 `focus-visible:ring-2 ring-accent ring-offset-1`（或全局 `:focus-visible` 样式）。
- hover 显现的操作按钮统一 `opacity-0 group-hover:opacity-100 group-focus-within:opacity-100` 模式（消灭 `hidden group-hover:block`，现 `Sidebar.tsx:166` 键盘不可达）。
- 禁止 `div onClick`：交互元素必须是 `button/a` 语义或带齐 role/tabIndex/onKeyDown（Memos 的 TagTree、Shortcuts 示例卡同样适用）。
- 图标按钮必须有 `aria-label`（中文）。

## 8. 状态设计规范（loading / 空态 / 错误 / 成功）

统一"四态 + 两辅助"：

1. **加载**：首屏加载一律骨架屏（与内容同构）；局部刷新用按钮级 spinner；>300ms 才显示（防闪烁，借鉴 Memos `useDelayedFlag`）；禁止白屏（Memos 的 MemoDetail/UserProfile `return null` 必须修）。
2. **空态**：EmptyState 四要素（图标/标题/引导文案/主行动），区分"还没有数据"与"服务不可用"两种文案（FilesPage 已有好范式，推广）。
3. **错误**：三级——字段级（input 下红字）、区块级（内联 banner + 重试按钮）、全局级（toast）。**任何失败必须给出下一步动作**（重试/重连/查看日志），禁止只读错误。
4. **成功**：轻量操作用 toast；破坏性操作成功给「撤销」action（5–8s 窗口），替代部分 ConfirmDialog。
5. **中断（辅助态）**：用户主动中断用**中性色**（muted/warn）区别于失败的 error 红（现 `runtime.ts:1374` 误用 error）。
6. **无结果（辅助态）**：与"失败"显式区分——这条同时约束后端：科研选题式"静默跳过"（`app/main.py:615-618`）必须向前端发降级提示。

## 9. 交互模式规范

### 9.1 快捷键（建立全局表并文档化）

| 场景 | 键位 | 说明 |
|---|---|---|
| 全局 | ⌘/Ctrl+K | 命令面板（**hosted web 也要挂载**，并扩充为导航中枢：6 个主页面直达 + 会话搜索） |
| 全局 | ⌘/Ctrl+B | 侧栏 |
| 全局 | ? | 快捷键帮助面板（新增） |
| 会话 | Esc | 中断运行——**分层优先级：模态 > 菜单/popover > 面板 > 中断 turn**（修 `LiveSessionPage.tsx:141` 守卫，纳入 `[role="menu"]`） |
| 会话 | ⌘/Ctrl+Enter | 发送（可选设置项） |
| Composer | Enter / Shift+Enter / ↑↓ / Tab / Backspace | 维持现状 |
| 列表页 | j/k、/ | 导航与搜索聚焦（新增，Runs/Files/Memory） |

### 9.2 会话与流式

- 流式期间**自动跟随滚底**（用户上翻则暂停跟随并显示「回到底部」浮动钮，有新消息计数）。
- 文本 token 渲染做 100–250ms 缓冲/节流（对齐工具输出的 250ms 折叠），避免逐 delta 整树重渲染。
- 失败消息尾部常驻「重发」按钮（重放最后一条 user 文本）。
- 用户消息保留原始换行（`whitespace-pre-wrap`）。
- 聊天代码块接入语法高亮（highlight.js 已在依赖，复用 `CodeViewer` 方案）。
- 会话列表补齐：重命名（inline 编辑）、运行中状态点（接 `runningSessions`）、搜索过滤、时间分组；删除支持撤销。
- 附件支持**拖拽上传**（Composer 与知识库，全库当前无 `onDrop`）。
- 修复 `pickBrowserFiles` 取消卡死（监听 `cancel` 事件）。

### 9.3 确认与撤销

- 高危批量操作（清空、批量删除）→ ConfirmDialog；单条删除 → toast + 撤销。ConfirmDialog 文案必须说明后果（"删除后不可恢复"）。
- 菜单/popover/panel 全部支持 Esc 关闭并正确还焦。

### 9.4 表单

- 所有输入控件有可见 label 或 `aria-label`（反例：`InteractionPrompt.tsx:150-155` 仅 placeholder）。
- 校验错误内联、提交错误区块级；提交中禁用并 spinner；成功 toast。
- 时间格式化统一 `toLocaleString("zh-CN", …)` 或共享 `formatDateTime` 工具（修 `NotebooksPage.tsx:182`）。

## 10. 文案与 i18n 规范

1. **基准语言简体中文**。一期先消灭英文残留（优先级从高到低）：SettingsPage 整页 → Composer 审批菜单/aria-label → WorkspaceChip → 子 agent 活动文案 → 下载 toast → StepSummaryRow。
2. 二期引入轻量 i18n（react-i18next）建立文案层；`RunsPage.tsx:31-85` 的手搓 `ZH` 字典作为迁移起点而非范式。
3. `approvalLocked` 与"语言"解耦——它是 hostedWeb 标志，不应决定文案语言。
4. 术语表（首批建议）：session=会话、run=运行、artifact=产物、workspace=工作区、approval=审批、prompt=指令/提示词（全站统一，不混用）、agent=智能体、workflow=工作流。
5. 语气：状态用进行时短句（"正在执行…"）；错误说人话 + 给动作（不说 "error 500"）；按钮用动词（"保存记忆"非"提交"）。
6. 文案与模型/供应商解耦：消灭 `userFacingRuntimeError` 里硬编码的 "DeepSeek V4 Pro"（`runtime.ts:64`），改从配置读取。
7. `researchAgentUi.ts` 的 agent 中文文案应随服务端 `listWebResearchAgents` 下发（或按 id+version 显式兜底 + 告警），避免新增 agent 静默退化英文。

## 11. 可访问性规范（基线 WCAG 2.1 AA）

1. 对比度：正文 ≥4.5:1、大字 ≥3:1；亮色修订见 §2.1（muted/warn/accent/ok/error）。
2. 焦点：全局 `:focus-visible` ring 样式；引入 `eslint-plugin-jsx-a11y` 进 CI。
3. 键盘：所有操作键盘可达；对话框焦点陷阱；拖拽调宽提供键盘替代（`role="separator"` + `aria-valuenow` + 方向键，步进 16px）。
4. 动态区域：toast/流式状态用 `aria-live`；工作指示器 `role="status"`。
5. 动效：尊重 `prefers-reduced-motion`（全局媒体查询关掉 `animate-pulse/spin` 非必要动效）。
6. 表单：label 关联、错误 `role="alert"`、必填标识不只靠颜色。
7. 触控： hover-only 交互必须有替代；点击目标 ≥32px。

## 12. 品牌规范

1. 品牌资产：logo `evimed-mark.svg` + serif "EviMed" 字标维持；favicon、PWA icon、`theme-color`（亮暗双值）全部替换上游残留蓝。
2. **Memos 品牌对齐**：新增 `evimed.css` 主题（利用其 OKLCH 主题文件机制，`--primary` 映射为平台赤陶、字体映射 Inter、radius 映射 14/10px），替换 logo/标题/usememos 外链；嵌入平台壳时跟随平台 `data-theme`。
3. **meta HTML 报告**：远期抽共享模板 + CSS，token 与主站对齐（或直接由主站渲染 JSON payload），消除 25 份复制样式。
4. 登录页/空态/关于页保留"循证医学"免责语（LoginPage 已有好范式）。

## 13. 工程落地机制

| 机制 | 内容 |
|---|---|
| Lint 防线 | `eslint-plugin-jsx-a11y`；自定义规则禁止 `text-[*px]`/`rounded-[*px]`/`shadow-(sm|md|lg)`/`text-white`/`#hex` 进入组件目录；stylelint 禁裸 hex |
| Token 单一源 | `index.css`（CSS 变量）+ `tailwind.config.js`（映射）双文件为唯一入口；`@ai4s/shared` 图表色维持三方同步 |
| 组件基线 | `components/ui/` 一期 8 原语（§7）；新页面禁止自建 Button/Input/空态 |
| 视觉回归 | 关键页（Live/Settings/Runs/Memory/Login）截图基线测试（现有 Vitest 体系上加 Playwright component 或截图比对） |
| 双形态守护 | 新增页面必须同时声明桌面/托管行为；CI 加一个"hostedWeb 渲染冒烟"测试（现有 `AppShell.web.test.tsx` 扩展） |
| 死代码红线 | 未接线路由/空目录不允许合入；`*` 路由渲染 NotFound（带回首页链接）而非静默重定向 |
| 协议协同 | 与 `lx-manus` 前端的契约（静默失败提示、图表协议、凭证不入聊天）记入 `接口文档/`，跨仓库评审 |

## 14. 规范落地的优先级

1. 先做 §2.1 对比度修订 + §11 焦点/对比度基线（低成本高影响）。
