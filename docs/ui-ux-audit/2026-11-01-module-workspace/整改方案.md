# 模块工作台整改方案

2026-11-01。代码基线：GitHub main `38b5af2a8`。

**执行情况：** 已按本方案实施，分支 `codex/module-workspace-20261101`（基于 `int-1101`），未合入 `main`，未部署。规范见 `OpenScience/docs/FRONTEND_DESIGN_SYSTEM.md` DS23 和 `OpenScience/DESIGN.md`“模块工作台”。与方案不同的三处：工作台投影放在各模块的前端适配器里，只有词表和类型放在 domain；窄屏展开对话时覆盖整个结果区，不做右侧浮层；输入框上不做“正在看”标记，也不记住展开状态（理由见 `DESIGN.md`）。

以下是实施前写的方案和盘点。

**依据和局限：** 用户截图一张，加上对全部模块前端和后台任务的源码盘点。没有在浏览器里逐页走查，内核里的渲染只读了注入代码（`runtimeUiCommands.mjs`）。数字来自源码统计，缺陷共 50 条，由只读代理记录，其中约 45 条读代码确认，我亲自复核了最关键的 8 条。“混乱程度”的分级是我的判断。

布局示意图：`mock.png`（源文件 `mock.html`，数据是虚构的）。逐条证据：`evidence/`。

## 1. 结论

**根因不是某一页没排好，而是平台没有“模块工作”这个统一对象。** 每个板块都在自己回答同一组问题：现在到哪了、下一步做什么、缺什么、AI 在干什么、哪些会自动跑、结果在哪、怎么跟 AI 说。答案散在几十个组件里，互相不一致。

具体是五件事：

1. **没有统一的状态来源。** GEO 有 9 种进度显示、8 处“下一步”；服务端的 `needsYou` 和客户端的 `geoJourney` 各算各的。虚拟临床研究没有“下一步”：`vcrNext.mjs` 已不在代码里。
2. **对话和结果互斥。** 对话是另一个路由，打开后结果区整个消失。规范写的是“对话是同一页的一个视图”，实现是换页。
3. **按钮外观一样，后果不一样。** 同样的按钮，有的只填草稿，有的立刻花钱开跑，有的授权自动投放。
4. **首屏信息塞进了内核的空白对话页。** 模块卡片用内联样式注入输入框插槽，不受设计规范约束，又和外壳上的进度重复。
5. **自动检查只量外观，不量逻辑。** 走查数控件种类、顶带高度、字号组合，不检查“按钮按下去发生的事和文字一致吗”。所以页面能全绿，任务流依然混乱。另外，九月到十月的多轮裁决叠加，`DESIGN.md` 已有互相矛盾的条文（见第 7 节）。

**整改方向：** 建一个统一的“模块工作台”：一个投影函数、一套状态词、四类按钮、一种布局。现有路由、结果页、项目和权限都不动，不新增审批环节，不新增第二个发送入口。

**对话框放底部：可以，而且应该。** 但只放在底部还不够，光放底部解决不了“看不到结果”。方案是两种形态，用的是同一个输入框：

- **对话展开时：** 右栏，输入框在右栏底部，左边结果不消失。
- **对话收起时：** 主区底部的常驻条。

理由和取舍见 4.2。

### 3.3 缺陷

共 50 条（GEO 20、虚拟临床研究与工具 15、其余 15），全文在 `evidence/`。影响最大的 10 条：

1. **“生成虚拟患者”不生成。** 它只跳到对话并填草稿，隔壁的“开始评估”却立刻排队运行。外观一样。
2. **“查看诊断与开始测量”落到一个没有开始按钮的页面。** 真正的入口在另一个标签页。
3. **改引擎或覆盖周期会静默停掉自动监测。** 提示只说“下一轮按新的引擎问”。
4. **“发布后第 1、2、4、8、12 周会自动复测”是无条件提示。** 实际要有自动监测授权才会发生。
5. **定时任务运行时项目对话被锁。** 用户要点开新对话才知道。
6. **`awaiting_budget` 被显示成“未完成”。** 用户点重试会再排一个任务。
7. **“停止”“取消”写在单个步骤上，实际停的是整个研究。**
8. **GEO 运行中的工作没有停止按钮。** 页面框架有活动条的位置，GEO 没用。
9. **没有权限的成员也看到“需要你”。** 点“去处理”后落到一个什么都做不了的页面。
10. **对话结束一轮后没有事件通知外壳。** GEO 靠 10 秒或 30 秒轮询刷新，对话里的 GEO 卡片只在特定事件时更新，可能和进度条不一致。

## 4. 目标设计

### 4.1 一个对象：模块工作台

每个模块只提供一个适配器，输出同一个结构。纯函数放在 `@evimed/domain`，列表、预览、工作台、对话四处读同一个结果。

```
workspace = {
  identity,    // 项目是谁、谁能做什么（权限统一在这里判断）
  stages[],    // 步骤或结果去向：名字、状态、是否在本次范围、依赖谁
  now,         // 一句话 + 一个主操作。全页只有这一处
  needs[],     // 等人的事，类型见 4.4
  activity[],  // AI 正在做和排队的事，可停，有进度
  automation,  // 接下来什么会自动跑、何时、怎么停
  results      // 当前步骤的结果（现有标签页内容不变）
}
```

GEO 的 `geoJourney`、`bandSteps`、`bandNow`、`progressLine`、`stepMark` 和服务端 `needsYou` 合并进适配器。虚拟临床研究补上它现在没有的 `now`。

### 4.2 一种布局

```
≥1280 宽屏（对话展开）
┌────┬───────────────────────────────────────────────┐
│    │ 顶带：返回 · 项目名 · [下一步：xxx] · 更多操作   │
│侧  │       证据 · 旅程 · 问题 · 诊断 · ……（进度轨）  │
│    ├───────────────────────────────────────────────┤
│栏  │ 活动条：AI 正在做 xxx 12/42        [停止这一项] │ ← 有活动才出现
│    ├─────────────────────────────┬─────────────────┤
│    │ 「等你」条（有才出现）        │ 对话            │
│    │ 结果区：当前步骤的表格、图、  │                 │
│    │ 稿件；工具栏只有一行          │ [正在看：问题]  │
│    │                             │ [ 输入框     ↑] │
└────┴─────────────────────────────┴─────────────────┘

收起对话：结果区占满，底部一条  [问这张表，或让 AI 接着做…  正在看：xxx] 展开
768–1279：默认底部条；展开时从右侧盖在结果上
<768 手机：一次一屏；底部条，点开是全屏弹层；进度轨收成“第 7/8 步”
```

**默认形态：** 没有结果或对话正在进行时展开，数据宽表和图表页默认收起。用户手动切换后，按模块记住。

**为什么右栏加底部条，而不是只放底部：**

- 笔记本屏幕高度不够：上下分屏后对话和表格各只剩约 375 px，都看不全。
- 调研的结论：对话为主的产品把输入框放在对话底部（Cowork、Lovable），页面为主的产品用侧栏（Notion、Microsoft Copilot）。模块页两种时刻都有，所以两种形态都要。未找到比较这两种布局的实证研究，这一点是推断。

**技术上可行，但有三个约束：**

1. **不用移动 iframe。** 现在的常驻 iframe 本来就是按矩形盖在窗格上（`SessionFrameHost`、`registerTaskPane`），换位置不会重载。
2. **底部条不启动容器。** 如果每进一个模块页都启动内核，就会碰到每人两个容器的上限和 63 秒的打开时间。所以收起时显示的是外壳画的封面，也就是上一轮做的可输入封面：点击才启动，打的字作为草稿交给原生输入框，封面本身不发送。发送入口仍然只有一个。这依赖分支 `codex/open-speed-20261031` 先合入 main，它现在还没合。
3. **窄宽度要先验证。** 内核的原生右栏不能禁用（`ui-chat` 依赖它），432 px 下要让它收起，要打开文件时切到对话全宽。这一步写在 P2 的开头。

### 4.3 联动规则

| 发生了什么 | 页面怎么反应 | 现状 |
|---|---|---|
| 切换步骤 | 结果区切换，对话不动，输入框上的“正在看”随之变化 | 退出对话 |
| 点“让 AI 改这个” | 就地填入输入框并带上对象引用，不跳页 | 跳到对话路由 |
| 对话一轮结束 | 内核通知外壳（新增事件），立即刷新状态和当前结果 | 轮询，没有事件 |
| AI 写入了结果 | 高亮新版本，对话里出现“在左边查看”；不替换用户正在看的版本 | 无提示 |
| 待办被解决 | 从“等你”消失，进度轨同步 | 依赖轮询 |
| 后台任务完成 | 活动条结束，结果刷新；用户不在页面时才进收件箱 | 只有虚拟临床研究有完成提示 |
| 程序运行占用对话 | 在对话区提前写明“运行中，结束后可继续”并给停止按钮；任务开始前也提示 | 打开时才报错 |
| 权限不足 | 所有入口统一隐藏，改为只读说明 | 部分泄漏 |
| 改设置会影响自动化 | 保存前写明后果，例如“这会停止自动监测” | 静默 |

### 4.4 交互逻辑

**四类按钮。** 文字和图标必须说清后果，每个按钮声明 `data-action-kind`：

| 类型 | 按下去发生什么 | 文案和外观 | 例子 |
|---|---|---|---|
| 起草 | 填入输入框，用户发送才开始 | “✎ 让 AI …” | 让 AI 补充问题 |
| 开始 | 服务器立刻运行 | “开始 …”，写明预估费用；活动条出现，可停 | 开始诊断 |
| 设置 | 改项目状态，就地生效 | 动词 + 对象 | 选这一档、暂停项目 |
| 对外 | 花钱或对外发布 | 确认框写明后果（沿用现有确认，不新增） | 放行稿件、设投放预算 |

一条规则直接消除大部分混乱：**写着“生成”“开始”的按钮必须真的开始；只填草稿的必须写“让 AI”。**

**一套状态词：**

| 状态词 | 含义 | 替换掉的说法 |
|---|---|---|
| （只显示步骤名） | 不在本次工作范围 | 未请求、未开始、还没开始、尚未提交工作 |
| 待开始 | 在范围内，包括依赖步骤 | 待继续、待执行 |
| 排队中 | 已受理，还没轮到 | 已排队、即将执行 |
| 进行中 | 正在跑 | 研究进行中、执行中、运行中、工作中、计算中 |
| 等你（后接具体事项） | 等人，例如“等你设预算” | 需要你、待确认、待回答、需要你补充 |
| 简版已完成 | 作为依赖以较低精度跑过 | 部分完成 |
| 已完成 | 跑完了 | — |
| 未完成 | 失败，已算出的部分保留 | 失败、未成功、没有做完、需要留意 |
| 已过期 | 输入变了，结果可能不再准确 | 5 种写法 |
| 已停止 | 用户停的 | 已取消 |
| 已暂停 | 项目级，优先于以上 | — |

“未完成”沿用现有不说“失败”的做法。词表放在 domain，模块代码里写死这些词的测试不通过（闭合词表检查，符合原则 5）。

**“等你”只分四种，不新增任何审批：**

- **待提供：** 产品信息、数据文件。
- **待确认：** 预算、放行。
- **需处理：** 失败、余额、连接。
- **平台外：** 需要用户在平台外完成的事。

只把现在已经要人做的事集中显示。调研也支持把“回答问题”和“批准动作”分开（Devin、Manus）。

**待输入的做法：** 不做大表单，也不做第二个输入框。页面列出缺哪几项，用户在对话里说或发文件，AI 通过现有写入工具写进项目，读到后自动打勾（截图一的做法）。

**GEO 的导航从 5 个维度减到 2 个：** 进度轨是唯一的主导航（前面加“总览”），步骤内只保留一行视图切换。27 个分析视图的下拉改成一个入口“深入分析”；分析范围并入筛选；方案归到信源步骤下。全部现有结果页和链接保留。

### 4.5 自动化

对用户统一说三档，每个模块的 `automation` 字段讲清楚：

| 档位 | 含义 | GEO | 虚拟临床研究 | 定时 / 主动科研 | 知识库 | 记忆 |
|---|---|---|---|---|---|---|
| **自动** | 不问就跑 | 依赖步骤、排队接续、额度到账恢复 | 输入变更后重算、引擎恢复后继续 | 按计划运行、长任务续跑 | 解析、整理知识页 | 提取记忆、学习做法、整理 |
| **授权后自动** | 用户开启一次，之后自动 | 每周复测、发布后复测、预算内投放 | 全流程（明确要求时） | 启用任务 | — | — |
| **每次要人** | 必须有人 | 预算、放行、目标档、平台外动作 | 预算、选定方案、复核 | 补充材料 | 选择项目、删除 | 确认外部写入、重置 |

**全平台盘点：** 22 个后台 worker 和 9 个定时器。其中用户能停的约 7 个，无控制的约 11 个，用户完全看不到的约 9 个。纯内务不用露出；影响用户结果或花费的必须露出。

规则：

1. 会花用户额度的自动工作，页面上必须看得到“接下来什么时候跑”，并能停。**知识页自动整理是目前最明显的缺口。**
2. 改设置会让自动化停下时，保存前要说。
3. 一个项目只有一个暂停，停的范围写清楚。
4. 通知只在两种情况发：卡在人身上，或长任务结束且用户不在页面。这和 Cursor、Claude 的做法一致。
5. 文案不说实现。“周一自动复测”可以，队列和 worker 不出现。

## 6. 分期和验收

工期是粗估，按一条执行线串行计算，未经实测。合入和发布仍按你的指令进行。

### P0：止血，不动布局（2–3 天）

- **截图这一页：** 进度轨去掉“未请求”；“项目第 N 周”等有第一轮结果再显示；模块对话不再显示通用问候；重复的要求只留一处；三个选项改成小按钮；输入框小标签不再跳走。
- **GEO：** 依赖步骤显示“待开始”；修“查看诊断与开始测量”的落点；等待状态的文字和图标一致；打开信号详情时步骤切换失效的问题；改设置前说明会停自动监测；复测提示按实际授权显示。
- **虚拟临床研究：** 起草类按钮改名为“让 AI …”；“需要你”按权限过滤；“停止”写明范围；等预算不再显示成失败；显示已暂停。
- **其余：** 添加材料时说明会继续任务；解除绑定加确认；收件箱和专区、复核提示自动刷新；记忆写入轮询不再过早放弃。

**验收：** 对应缺陷各有单元测试；截图这一页重拍对比。

### P1：统一的底层（5–7 天）

- domain 增加工作台投影和状态词表；GEO、虚拟临床研究改用适配器。
- 共用组件 `WorkspaceBand`（顶带 + 进度轨）、`NeedsBar`、`ActivityStrip`（GEO 接入并支持停止）。
- 四类按钮：`data-action-kind` 落到所有模块页。
- 新增“对话一轮结束”事件（经 `runtimeUiBridge`），替代靠轮询发现变化。
- GEO 导航减到 2 个维度。

**验收：** 列表、预览、工作台、对话读同一个投影，测试断言一致；模块代码里写死状态词的数量只减不增。

### P2：布局（5–8 天，先做 1–2 天验证）

- **先验证：** 432 px 下原生输入框和右栏的行为；窗格换位不重载、不丢焦点；收起和展开时的草稿交接。**不通过就退到：** 对话展开时盖在结果上，结果仍可切回，不做并排。
- 右栏 + 底部条 + 窄屏弹层 + 手机单屏；形态按模块记忆。
- 就地起草取代跳到对话路由，旧 `/chat` 地址继续可用，打开时默认展开对话。
- 模块空白页不再由内核绘制卡片，删除 `Starters` 里的模块分支和输入框里的 journey 小标签。

**验收：** 按项目规定，改对话行为必须在真实 DSH + DeepSeek 会话上验证（多轮、补资料、换话题、工具失败），保留实际输出。

### P3：铺开（5–7 天）

定时任务、主动科研、知识库、记忆；自动化说明和停止入口；通知规则。

### P4：把规范和检查补上（贯穿，P1 开始）

- 改 `DESIGN.md`（第 7 节）。
- 走查增加**语义检查**，这是防止复发的关键：
  - 点起草按钮：地址不变，输入框有内容。
  - 点开始按钮：2 秒内出现活动条。
  - 点对外按钮：出现确认框。
  - 首屏有且只有一个“现在”和一个主操作。
  - 对话一轮写入后，进度轨 2 秒内变化。
  - 同一个状态词在进度轨上不重复超过 3 次。
- 现有走查的预算不放宽。

## 9. 风险和未验证

- **打开速度是前提。** 对话若还要等 63 秒，并排也救不了体验。`codex/open-speed-20261031` 没合入 main，实际提速也还没量。
- **窄宽度内核表现未测。** 这是 P2 最大的技术风险，已安排先验证并给了退路。
- **Kernel 升级可能影响。** 布局依赖内核的插槽和样式。按现有做法，每次升级要重查。
- **“AI 写入后自动打勾”依赖 AI 真的写入。** 10-31 的实测已跑通过一例“写入产品字段并回读”，其他字段要在 P2 验证。
- **本次没有浏览器走查。** 分级来自代码和这张截图，P0 开工前建议用夹具数据把四个重度模块的主要状态各拍一遍作为对照基线。
