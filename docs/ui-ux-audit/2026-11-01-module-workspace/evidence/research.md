## A. Guidance: Shape of AI (shapeof.ai)
- Taxonomy [FACT] https://www.shapeof.ai : pattern types = Wayfinders (gallery, follow up, initial CTA, nudges, prompt details, randomize, suggestions, templates), Inputs, Tuners (attachments, connectors, filters, modes, parameters ...), Governors (action plan, branches, citations, controls, cost estimates, draft mode, memory, references, sample response, shared vision, stream of thought, variations, verification), Trust builders (caveat, consent, data ownership, disclosure, footprints, incognito, watermark), Identifiers.
- Action plan [FACT] https://www.shapeof.ai/patterns/action-plan : two modes - "Advisory" (plan shown as reasoning, user not asked to review) and "Contractual" (user must verify before execution). Quote: "The right time to stop an erroneous run is before it begins." Use for compute-heavy tasks; confirmations add friction so designers must set the threshold for blocking vs showing a stream of thought. Guidance: show plan before resources are committed; skimmable; editable (no full regeneration to fix one issue); let experienced users collapse/bypass but keep review available; "Silent deviation quickly erodes trust" (execution must match plan or plan must be updated). Variations: step lists, execution previews with approval gates, content outlines, adaptive plans (change mid-process, Perplexity Labs cited). Examples named: Replit and Devin = execution preview that pauses until confirmed; Cursor = plan of action optional in settings; Zapier = outline editable before steps are created.
- Stream of thought [FACT] https://www.shapeof.ai/patterns/stream-of-thought : "Separate plan, execution, and evidence" (what will happen / what happened / what supports the result); "Treat every step as a clear state," such as queued, running, waiting for approval, error, retried, or completed. v0 shows logic inline before building, then moves remaining steps to a LEFT DRAWER while the codebase builds in the main canvas. Perplexity puts steps in a tab above the results pane (also Comet). Defaults vary by mode, with progressive disclosure.
- Controls [FACT] https://www.shapeof.ai/patterns/controls : stop (keep it in same place, clickable until done), pause (keeps progress), fast-forward, queue ("Replit supports the notion of a queue, similar to how a developer would have multiple tasks in their backlog"; Cursor too); queued tasks should be editable/removable; prefer variations over overwrites.
- Footprints [FACT] https://www.shapeof.ai/patterns/footprints : interface footprints (badges, inline markers) + system footprints (logs, metadata for admins/auditors); "Treat footprints as first-class data". ChatGPT agent mode cited as "browser view showing each step and screenshot, with scrubbable playback".
- Consent [FACT] https://www.shapeof.ai/patterns/consent : about data consent (recording, training), NOT agent-action approval; page has no section on approving agent actions. "Silence is not consent." "Consent must be reversible." Do not cite it for action approval.

### Linear agents
- [FACT] https://linear.app/developers/aig (Agent Interaction Guidelines): six principles: disclose it is an agent; inhabit the platform natively ("existing UI patterns and standard actions"); instant feedback; transparency about internal state (inspect "reasoning, tool calls, prompts, and decision logic"); respect requests to disengage; accountability ("The final responsibility should always remain with a human"; delegated issues keep a human assignee shown). - [INFER] Closest published state vocabulary to what EviMed needs: 6 states derived from last activity, not set manually; `awaitingInput` and `stale` are the two that matter for background work.

## D. Guidance (continued)
### OpenAI Apps SDK UI guidelines (display modes)
- [FACT] https://developers.openai.com/apps-sdk/concepts/ui-guidelines : inline card = "A single action or decision", "Support up to two actions maximum, with one primary CTA and one optional secondary CTA", avoid tabs/deeper navigation, no nested scrolling, "No duplicate inputs"; carousel 3-8 items; fullscreen for "interactive maps or rich editing canvases" and "The ChatGPT composer remains overlaid ... Design your UX to work with the system composer"; PiP for "ongoing or live sessions" pinned until dismissed, "Do not overload PiP with controls". "Every app initially appears inline."
- [FACT] https://developers.openai.com/apps-sdk/build/chatgpt-ui : fullscreen "composer remains available"; "Start with inline UI, and request more space only when the workflow needs it"; follow-up via `ui/message` / `window.openai.sendFollowUpMessage`; selection/staged edits the model should see go via `ui/update-model-context`.
- [INFER] This is the most explicit published rule that a rich surface embedded in a conversation keeps ONE composer that talks to the whole thing (the composer is the host's, the surface must "work with" it). Directly relevant to "one composer".

### MCP Apps
- [FACT] https://modelcontextprotocol.io/extensions/apps/overview : UI from MCP servers renders in a sandboxed iframe in the chat; stated fit: exploring data, "Configuring with many options" (form instead of back-and-forth: "Which region?" "What instance size?"), rich media, "Real-time monitoring", "Multi-step workflows" (approving, triaging, navigation controls + "state that persists"). "Context preservation. The app lives inside the conversation." Supported by Claude, Claude Desktop, VS Code Copilot, M365 Copilot, Goose, Postman (as listed 2026-11-01).
- [INFER] MCP Apps and OpenAI apps both put structured UI INSIDE the chat; EviMed's case is the inverse (a module page that contains a conversation). They agree on the principle that parameters-with-many-options should be a form, not a Q&A.

### AG-UI / CopilotKit / A2UI
- [FACT] https://docs.ag-ui.com/introduction : building blocks "Interrupts (human in the loop): Pause, approve, edit, retry, or escalate mid flow without losing state"; "Typed store shared between agent and app, with streamed event-sourced diffs"; generative UI static ("stable, typed components under app control") vs declarative ("agents propose trees and constraints, the app validates and mounts").
- [FACT] https://docs.copilotkit.ai/human-in-the-loop : two HITL patterns - `useHumanInTheLoop` (the model chose to ask) and `useInterrupt` (graph-paused: "the code path deterministically requires a human answer"; "the pause is enforced by the graph itself"). Decision table: LLM decides to ask vs code path requires a human.
- [FACT] https://a2ui.org/ : agents "send declarative component descriptions that clients render using their own native widgets", only "pre-approved components from your catalog"; user actions go back to the agent; data not code (avoids "UI injection attacks").
- [INFER] The CopilotKit split (model-chosen ask vs code-enforced stop) maps cleanly onto "inline ask" vs "queue item": deterministic requirements (missing parameter, confirmation of external side effect) should be code-enforced and appear in a queue, whereas model-chosen clarifications can stay inline.

### Smashing Magazine, Victor Yocco, 2026-02-11 (reputable practitioner analysis, not a standard)
- [FACT] https://www.smashingmagazine.com/2026/02/designing-agentic-ai-practical-ux-patterns/ : six patterns. Intent Preview ("speed bump"; required for irreversible actions, financial transactions, actions that share information with other people/systems; choices Proceed / Edit Plan / Handle it Myself; card in the conversation). Autonomy Dial: 4 levels - Observe & Suggest; Plan & Propose; Act with Confirmation; Act Autonomously (pre-approved tasks, notify afterwards); set PER TASK TYPE, not globally; "Trust is not a binary switch; it's a spectrum." Explainable Rationale ("Because you said X, I did Y", as an entry in the notification feed with View/Undo). Confidence Signal. Action Audit & Undo (chronological timeline with status successful / in progress / undone; state honestly when an action becomes permanent; "if reversion rate above 5% for a task, disable automation for that task"). Escalation Pathway ("A well-designed agent doesn't guess; it escalates"). Metric targets (85% acceptance, 5-15% escalation) are the author's suggestions, not standards.

### Microsoft HAX
- [FACT] https://www.microsoft.com/en-us/haxtoolkit/library/ (the library page lists all 18, no phase grouping on that page; phases initially / during / when wrong / over time are stated in the Microsoft Research blog above). Verbatim titles: G1 Make clear what the system can do; G2 Make clear how well the system can do what it can do; G3 Time services based on context; G4 Show contextually relevant information; G5 Match relevant social norms; G6 Mitigate social biases; G7 Support efficient invocation; G8 Support efficient dismissal; G9 Support efficient correction; G10 Scope services when in doubt ("Engage in disambiguation or gracefully degrade ... when uncertain about a user's goals"); G11 Make clear why the system did what it did; G12 Remember recent interactions; G13 Learn from user behavior; G14 Update and adapt cautiously; G15 Encourage granular feedback; G16 Convey the consequences of user actions; G17 Provide global controls ("Allow the user to globally customize what the AI system monitors and how it behaves"); G18 Notify users about changes.

### Shape of AI - empty-state and mode patterns
- [FACT] https://www.shapeof.ai/patterns/suggestions : starters = "three to five", "Display three to six relevant options, ordered by context or performance"; make them actionable (click runs or pre-fills); draw on context (attached file); "Preview risky actions" (data access, publish, heavy compute: "Users should understand implications before committing"); anti-patterns: showing everywhere, too many options ("scanning fatigue"), "Irrelevant suggestions before any context exists" (Typeform named), static lists. Not suited to "focus-heavy tasks, where a blank input may work better".
- [FACT] https://www.shapeof.ai/patterns/cta : "The direct input has become the default starting point"; scaffold it: suggestions, galleries, templates, attachments, modes; variants "Initial CTA (AI-first)", "Action-first" (AI alongside wizards/templates/workflows "in products where AI is a feature"), "Contextual" (AI offered "once there is data to act on"). Zapier = strong example: previews the workflow generated from the prompt so the user can refine it.
- [FACT] https://www.shapeof.ai/patterns/modes : "Treat a mode as a contract, not a theme"; "Reconfigure the surface when the mode changes"; explicit entry/exit and visible active state; "Set inheritance rules and stick to them"; guard costly modes (preview latency/token tradeoffs). Perplexity: web search, deep research, labs as tabs in the initial prompt area.

## F. Other primary sources on workflows vs agents
- [FACT] https://www.anthropic.com/engineering/building-effective-agents : "Workflows are systems where LLMs and tools are orchestrated through predefined code paths"; agents "dynamically direct their own processes"; workflows "offer predictability and consistency for well-defined tasks"; agents for "open-ended problems where it's difficult or impossible to predict the required number of steps"; agents may "pause for human feedback at checkpoints or when encountering blockers"; recommends "explicitly showing the agent's planning steps"; include stopping conditions.
- [INFER] An 8-step GEO programme is a predefined workflow (fixed steps, code-owned) with agent runs INSIDE steps; the stepper should be fixed and code-owned, while the per-step plan (what the agent will do in this step) can be dynamic and shown as an action plan. This is how Replit (fixed columns, dynamic per-task plan) and Elicit (fixed stages) are built.

## K. ANSWERS TO THE SPECIFIC QUESTIONS (sourced facts, then [INFER] marked)

### (a) Bottom-docked composer vs side panel when a structured page exists
- Sourced: Every surveyed product that puts structured content next to a conversation keeps exactly ONE composer, and it belongs to the conversation, not the content: Microsoft ("Don't duplicate ... prompt input ... inside the widget"; chat stays usable while the side panel is open), OpenAI Apps SDK (fullscreen: "ChatGPT composer remains overlaid ... Design your UX to work with the system composer"), Lovable (chat panel left, Details view opens in the preview area, composer stays), Claude artifacts ("opens beside your conversation"), Notion Agent (right "Sidebar" or "Floating"), GitHub Copilot (prompt box below the session log), Claude Code desktop (chat is one of arrangeable panes).
- Sourced counter-pole: Elicit's Systematic Review has no chat at all - a fixed stepper with Run buttons; Elicit's home separately offers the Research Agent. Peec/Otterly/Profound AEI are dashboards with no conversation in the monitoring views.
- [INFER] Docked bottom composer works when the conversation is the primary thread and content is a result (Cowork, Lovable). A side panel works when the page is primary and the conversation is a helper (Notion). It fails (a) when a second input appears inside the content area, (b) when the composer's scope is ambiguous (Claude Projects: a message in the coordinator does not reach a thread; the docs have to warn about it), (c) on phones where only one pane fits (Material compact: only main pane). For a module page: one composer whose visible scope label names what it talks to (module / current step / selected run).

### (b) One inbox vs inline asks
- Sourced: both exist and are used together. Inline: Lovable question cards (up to 4 questions, options or free text, Skip/Skip all, drafts kept), Claude permission cards, Smashing "Escalation Pathway", Microsoft inline "Confirmations". Cross-item queues: Devin notification inbox (2026-10-07) + sidebar "Blocked"; Claude Projects Overview "Waiting on you" + dot; Claude agent view "Needs input"; Codex "The Scheduled view acts as your inbox"; Agent Inbox (Accept/Edit/Respond/Ignore); Manus Automations "Updates".
- Sourced rule: where the ask is answered stays with the work item (Claude Projects: approval prompt is inside the thread; "go ahead" in the coordinator does not reach it; agent view: permission prompts cannot be answered from the peek panel, you must attach).
- Sourced notification policy: Cursor removed turn-finished pushes but kept question/approval pushes; Claude loops notify only when they need input; Claude Projects notifies on post/error/needs-input and shows a dot in browsers. 
- Sourced limit: asks expire - Claude cloud environment expires; "A session counts as inactive while it waits for you to approve"; Devin suspended reasons include inactivity.
- [INFER] CopilotKit's split suggests the rule: asks the MODEL chose (clarifications) can be inline cards in the conversation; asks CODE requires (missing mandatory parameter, external-effect confirmation, sign-off) should ALSO appear in a queue/badge visible from the step and module list, because the user may not be in the conversation when they arise.

### (c) Stepper vs task list vs agent plan; dynamic vs fixed
- Sourced: Elicit = fixed stepper ("visual timeline"), stage toggles, user-triggered transitions ("Define screening", "Run screening", "Run extraction"), all settings visible before anything runs. Replit = fixed board columns (Drafts/Active/Ready/Done) with a dynamic step-by-step plan per task; plan editable; auto-approve switch. Lovable = plan as a document (Approve/Skip), Plan mode never modifies code. Manus/Cowork = agent-generated progress ("Progress indicators", sub-agents). Shape of AI: separate "what will happen, what happened, and what supports the result"; "Treat every step as a clear state"; advisory vs contractual plans; adaptive plans exist (Perplexity Labs) but "Silent deviation quickly erodes trust". Anthropic: predefined-code-path workflows for well-defined tasks, dynamic agents for open-ended ones; show planning steps.
- [INFER] EviMed's eight/seven steps are a predefined workflow, so the stepper should be fixed and code-owned; the agent's per-step plan/to-do is the dynamic layer inside the step and should be shown as an editable action plan before heavy runs; a flat task list is for the agent's inner to-do only.

### (d) States vocabulary (observed, verbatim)
- Linear: pending, active, error, awaitingInput, complete, stale (derived automatically from last activity). 
- Devin: status new/claimed/running/exit/error/suspended/resuming; detail working / waiting_for_user / waiting_for_approval / finished; sidebar groups Working / Ready / Blocked / Inactive.
- Manus API: running, stopped (not always final), waiting (question | action confirmation | browser), error.
- Claude agent view: Working, Needs input, Idle, Completed, Failed, Stopped; groups add Ready for review. Claude Projects groups: Ready for review, Waiting on you (reply, approval, or failed), Working, Landing, Idle, Resolved.
- Replit: Drafts, Active (incl. Queued), Ready, Done. Cursor: In Progress, For Review, Queued; parent takes the most active child's status. Shape of AI step states: queued, running, waiting for approval, error, retried, completed. Vercel AI Elements tool states: pending, running, completed, error; approval-requested / approval-responded / output-denied / output-available.
- [INFER] Common core across 5+ systems: queued / running / needs input (answer) / needs approval or review / failed / done, plus stopped, stale-expired. "Ready for review" is separated from "done" in Claude, Devin, Replit, Cursor.

### (e) Empty state: suggested tasks vs a single next action
- Sourced: Shape of AI suggestions: 3-6, ranked, contextual, actionable, preview risky actions; anti-pattern "Irrelevant suggestions before any context exists" and "Not in focus-heavy tasks"; Shape of AI CTA: "Action-first" for products where AI is a feature, "Contextual" once there is data; Zapier previews the generated workflow. Elicit: three starting points with a one-line selection rule. Replit: Drafts as proposed tasks with plans. Claude Code desktop: suggested tasks with Start / Start all.
- [INFER] A module with a known programme should open on the next incomplete step with one primary action, with 3 contextual starters only for the free conversation; generic starters before the project has data is the named anti-pattern.

### (f) Autonomy levels and expressing what runs without asking
- Sourced: Smashing four levels (Observe & Suggest; Plan & Propose; Act with Confirmation; Act Autonomously) set per task type; Claude Cowork modes Manual / Auto / Skip chosen in the composer and connector permissions Always allow / Needs approval / Blocked; Claude Code Manual / Accept edits / Plan / Auto / Bypass; Replit Auto-approve plan and Auto-apply switches; Manus "Skip confirmations" for trusted scheduled workflows; Codex unattended runs: sandbox + `approval_policy = "never"`, out-of-envelope calls fail; Profound: every run has an approval step before publish (no skip documented); Claude Projects: autonomy is stated in natural language to the coordinator and saved to memory, docs say "instructions Claude keeps to, not enforced settings".
- Sourced guidance: PAIR (health/finance/safety = people want to stay accountable); HAX G17 global controls, G16 convey consequences; Smashing: "if reversion rate above 5% ... disable automation for that task" (author's suggestion); Intent Preview required for irreversible, financial, shared-with-others actions.
- [INFER] Enforced-in-code envelopes (Codex, Manus skip-confirmations) are more defensible than prompt-stated autonomy (Claude Projects admits it is not enforced). For EviMed: show per step "runs without asking / asks before external effect / always needs a person's confirmation", change it in one place, and enforce it in code.

### (g) Mobile
- Sourced: Claude mobile is "a client for Claude Code sessions rather than a place where code runs": check progress, answer questions, steer; push for finish/decision; no Bypass permission mode on phone. Cursor iOS shows the MCP sign-in card; pushes only for question/approval. GitHub Mobile lists agent sessions under the Copilot menu. Material: at compact width list-detail and supporting pane show ONE pane; "Bottom sheets can act as supporting content to the primary view"; OpenAI/Microsoft: inline first, bigger surface only when needed. NotebookLM mobile: Chat and Studio panels with a source selector in the prompt box.
- [INFER] Phone = queue + answer + glance at status + read results; authoring parameters and 8-step navigation collapse to "current step + next action"; the composer is a sheet, not a permanent column.
