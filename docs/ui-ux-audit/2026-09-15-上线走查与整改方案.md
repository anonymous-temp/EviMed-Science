## 0. 一句话结论

外壳是按规格 §18.1 的「自研会话页」方案切的，会话面后来换成了规格当时否掉的「嵌入 DSH 网页」方案，两件事各自都做完了，没人把外壳按新会话面重切。于是同一个东西出现三次（外壳左栏、内核左栏、外壳右栏），同一个概念有三个名字（任务 / 会话 / 运行），记忆有三个入口，能力叫「模板」。整改的核心不是修 UI，而是先定「DSH 网页就是主面」这一条，再把外壳压成一根导航条并把导航塞进内核的 slot 里。

## 6. 整改方案

### 6.0 先拍板（需要操作者决定，半天）

### 6.2 P1 · 外壳重切（1–2 周，`apps/web` + `packages/harness-port`）

### 9.1 镜像怎么重建的

`open-science-web` 走完整 Dockerfile 在主机上重建（阿里云 apk / npmmirror 镜像，约 6 分钟）。**运行时镜像走了一次依赖不变的增量**：新建 `deploy/runtime-dsh/Dockerfile.delta`，`FROM` 已验证的基线镜像，只重放 socket 插座之后的那一段——socket / domain / harness-port 三个包、客户端 bundle、preset 的两份副本、profile seed 里真正被 import 的那一份、重新封印、再跑一遍 `build-smoke`。理由写在文件头：完整构建里 apt、R、Chromium、uv、DSH CLI 才是构建本身，而这次没有动任何依赖；`docs/WEB_DEPLOYMENT.md` 本来就把这种情况列为「dependency-preserving delta」。一次增量约 2 分钟，完整重建要小时级。

**`build-smoke` 当场抓到两个我自己引入的缺陷**，这是它存在的全部理由：

1. `evimed-guidance` 用 `ctx.provide('evimedInjectedSkills', …)` 发布服务，内核拒绝挂载整个 preset：「row(s) published process-global service(s)」。agent preset 的行不能发布进程级服务，但可以**调用**宿主侧提供的服务——改成由 `evimed-store` 的诊断服务提供 `injectedSkill(name)`，guidance 调它。事实的流向本来就是这个方向：run-state 投影是宿主侧写的。
2. 列表型 slot 要 `options.id`，不是 `key`（`key` 是右栏 tab 用的）。写错时注册静默失败、能力条不出现。两条都写进了 harness-port 的测试夹具。

### 9.2 内核左栏：占 slot 不等于收回宽度

占 `sidebar` 只换掉列的**内容**；列宽仍由内核自己的 layout store 决定，所以第一次上线后页面上多了一条 280 px 的空白沟——真机量到的。`ctx.layout.toggleSidebar()` 从占位组件里调不动。最后用三条 CSS 收口：列 `display:none`，会话列显式占第 1–2 轨，右栏占第 3 轨（不这么钉，会话列会掉进 280 px 那一轨，右栏去抢 1fr——也是量到的）。右栏开（680+528）与关（1208+0）两种状态都在真机验过才写进代码。代价写在注释里：两个拖拽手柄共用一个类名，一起隐掉了，所以右栏不能再拖宽——它的开 / 关 / 全屏仍在会话头部，按它自己的契约那里才是它的控件位置。

### 9.3 能力卡最后落在哪

不是空会话起始面。那个位置的 slot 是 `conversation.hero.agentPreset`，由 `ui-agent-preset` 声明，而这个部署把它列进了 14 个禁用面板——**被禁用的行不声明 slot**，所以占它等于什么都没注册，静默无效（真机量到的）。改落在 `conversation.input.dock`（输入框上方，`ui-conversation` 声明，必然加载），一行可折叠的「科研能力 · 15 项」。顺带也更符合 §9.8：能力是建议不是绑定，而想起要做 Meta 分析的那一回合通常不是第一回合。E5 的「预填多五个空行」同时修掉——Lexical 把每个 `\n` 渲染成一个段落，`capabilityBrief` 改成单换行。

| 就绪报 `deepseek_release_receipt_mismatch` | 回执绑 `sourceRevision`，它是一次真实探针的凭据，不能改签只能重挣 | 在 `open-science-release-receipt` 容器里跑 `release-receipt-scheduler once`；这个容器才有控制器套接字、数据卷和运行时网络腿 |
| 回执一直失败 | `.env` 的 `OPEN_SCIENCE_RELEASE_MANIFEST_HOST_FILE` 仍指向旧 release 目录，容器挂进来的是旧清单 | 改指新目录；`.env` 里所有指向 release 路径的值都要跟着搬 |
| `release-retention` 报 `0 releases` | 见 §8.2 | 已修，本次用它把 10 个 release 目录清到只剩当前一个 |
