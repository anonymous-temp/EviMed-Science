## 0. 一页结论

**你看到的「乱」只有一个来源：我们在 DSH 自己的应用外面又套了一个自己的应用，然后每遇到一个问题就再加一个面，从来不删。** 于是同一件事在产品里存在两到四份，名字还不一样；页面是照着我们的数据表画的，不是照着用户要做的事画的；系统能自己做的事被做成了表单和按钮推给用户。你 9-15 说「能力卡进新任务起始面」、9-17 问「dsh 每一步的执行进度那个咋删啦」，今天说的是同两件事——说明前两次我都是在补丁上打补丁，没有回到你的原话。

今天在线上量到的五个硬事实：

## 2. 五个总根因

**R1 两个应用叠在一起。** 9-09 决定「会话面用 DSH 自己的应用」，但外面的壳没有跟着重切：壳有自己的导航、自己的页面、自己的词；内核应用的左栏被我们用空组件占掉，右栏被我们的四个标签占掉，顶上再压一条我们的横栏。结果是同一件事存在多份：任务 / 会话 / 运行；进展在右侧标签里一份、在运行记录页一份；能力有四个入口；停止和取消是两个按钮一个接口。`SessionRoute.tsx:14-23` 的注释自己就写着这件事，但只处理了其中一处。

**R2 页面照着数据表画，不照着用户要做的事画。** 记忆六个 tab = 六份存储；右侧四个标签 = 四路数据；运行记录页 = 账本；知识库的「整理进度」tab = 解析作业表。用户要做的事只有四件：问一个问题、用一个工具、放资料进来、看看它记住了我什么。

**R3 把系统能自己做的事做成了表单和按钮。** 写方法 ×2、写笔记、逐份「放进胶囊」、逐个管理胶囊、每个产物文件上的「采纳 / 我改过」（一次 GEO 运行 11 个文件 = 22 个按钮）、总览的「还缺」待办、新建议程要填三档预算、「待你复核」。这和你 9-19 说的设计初衷正相反。

**R4 只加不删，而且加的是我自己的主意。** 无痕、本次用到的背景、时间轴、六分区、右侧四标签、首页角色卡，都是我在某次方案里提的，每一个单看都讲得通，合起来就是现在这样。DSH 原生已经有的（过程行、子任务入口、文件预览、分支、重试、排队/插话），我们要么关了，要么在旁边又做了一份。

**R5 执行链路是为「过门禁」设计的，不是为读者设计的。** 总是委派 → 过程离开主对话；先验收冻结、后审查 → 审出问题改不了；编号靠模型手工维护 → 会漂移；结束运行是模型要调的一个工具，它能被拒 → 模型去读门禁源码、最后一条消息变成内部旁白；质控发现写成英文、散在三个面、没有一处汇总给读者。

## 3. 捋清楚之后的整体

### 3.1 四个名词

| 名词 | 定义（会印在对应页面标题下） | 谁写 | 范围 |
|---|---|---|---|
| **对话** | 你和 EviMed 的一次研究。过程、计划、报告入口都在这一条对话里。（不再出现「任务」「会话」「运行」） | 你和 AI | 属于一个项目 |
| **科研工具** | 一个专门做某类研究的智能体（15 个）。进它的页面 = 同一个输入框，带着它的说明和示例 | 平台 | 全局 |
| **知识库** | 你放进来的资料：文献、方案、数据。AI 回答和做研究时会去读 | 你 | 项目内；可标为「所有项目可用」 |
| **记忆胶囊** | AI 自己记下的：关于你、你的项目、你的做法。自动生效，每条看得到来处，随时能改能忘 | AI | 关于你 = 跟着账号；关于项目 = 只在该项目 |

**项目** = 一组对话共用的文件夹、知识库和项目记忆。默认项目「我的研究」是个杂物间，所以：默认项目不写「项目主题」类记忆；一次运行的审查、自检只读**本次计划里的交付物**，不读整个工作区（修掉今天那次串台）。

### 3.3 首页（新对话）

从上到下：一句标题 → **输入框** → **科研工具网格**（临床证据 / 药学评价 / 研究设计与数据 / 写作与传播，先露 8 个 +「全部工具」）→ 有晨间简报时一条简报（你 9-15 要的）。没有角色卡，没有顶栏。

### 3.4 工具页（= 同一个输入框）

点任意工具（首页网格、「科研工具」目录页、输入框里的 `/`）→ **还在同一个输入页**，变化只有两处：

- 输入框上方出现这张工具的页头：名称、一句话承诺、你会拿到什么、通常用时、需要你提供什么（需要资料时给上传入口）、三条示例问题；
- 输入框里出现一枚可移除的工具标签。

示例问题点一下是填进输入框、可改、回车即发；输入框的占位文字也换成这张工具的（如「描述你的临床问题…」）。按 × 或在空输入框里退格，标签消失，回到首页原样。

这不是发明：Manus、Kimi、ChatGPT（GPTs 与 @ 提及）、豆包、Genspark 现在都是同一个模式——输入框下面选工具 → 输入框里一枚可移除的标签 + 占位文字改写 + 下方示例换成该工具的；没有一家用侧边抽屉加第二个输入框（调研 E §1）。

选中即把这条对话硬绑定到这个工具（现成机制：`PUT /api/research-sessions/:id {mode:"specialist"}`），不再往你的话前面塞「请以「…」能力完成以下任务：」，也不再经过 LLM 路由去猜——你选了什么就是什么。对话标题因此也不再是「请以「临床证据深度分析」能…」。地址 `/app/tools/:id` 可直接分享。「科研工具」目录页保留为一张干净的网格，卡片直达工具页；抽屉、第二输入框、回执横幅删除。

### 3.5 对话面：DSH 原生 + 一个「运行」页签

内核的对话区顶上本来就有一排**视图页签**（`conversation.view`：一个列表槽位，每个条目带 id、order、label，内核按 label 画成页签）。原生装了两个：「对话」和「轨迹」。轨迹会把系统提示词原样显示，所以 9-16 起只对运营开放——**这就是你说的「dsh 每一步的执行进度」被我关掉的地方**。

我们不再自己造面，而是在这个槽位里挂一个自己的视图：

| 页签 | 来源 | 内容 |
|---|---|---|
| **对话** | 内核原生 | 一步一步的过程：思考、工具调用、计划卡、子任务卡、结论。委派改按需之后（§3.7），大部分任务的过程就在这里 |
| **运行** | 我们注册（`id: evimed-run`，order 5） | 这次研究的结构：状态、用时、花费、走到哪一步、每件要交付的东西和它的子任务（可点进去）、每条结论的 ✓/⚠、引用的来源、产出的文件。不显示系统提示词，所以对所有用户开放 |
| 轨迹 | 内核原生 | 仍只对运营开放——它是内核的调试面，会露出提示词 |

两个页签常驻。没有研究任务时「运行」写一句「这次对话还没有研究任务」。阶段只显示走到过的，不再出现「核验 0 · 撰写 0 · 交付 0」；「当前」是走到的最远一步，不是最后一次带标签的调用。

我们在对话面里的定制只剩五处：

1. 品牌位与中文语言包（已有）；隐藏「系统提示词 / 上下文注入」两种行（已有）；
2. 对话内的卡片：研究计划、子任务（有子任务时）、自检 / 提交结果；
3. **本轮交付卡**（新，用 DSH 的 `conversation.chat.turnTail` 空位）：报告标题、打开报告、核对 29/31、审查发现几条已改几条未改、用时与花费——由平台渲染，不依赖模型写得好不好；
4. 首页的工具网格、工具页，和输入框上方的工具标签；
5. 右侧的文件列表（§3.6）。

删除：顶部记忆横栏；`evimed_complete_run · {}` 这种裸工具行；三处「同一件事藏两遍」的重复手段（分项核查 A 的 E 节）。

### 3.6 右侧栏：回到 DSH 的用途——文件

DSH 的右侧栏原生是**文件树 + 文件预览**。右侧栏这个包不能关（`ui-chat` 把它写进了硬依赖，关掉整个对话就没了），所以我们照它的用途来，并且**只注册一个入口「文件」**：

- 一个入口 → 右侧直接打开文件列表，不再有导览页（「开始」就是导览页的标题），「+ 新标签页」也没有意义了；
- 列表 = 这次对话产出的文件（报告、证据表、附件），按写它的那件交付分组，未通过核对的标出来；
- 点一个文件 → 在壳的阅读器里打开（整宽阅读，带目录、每条结论的 ✓/⚠ 和参考文献）。WP1 之后对话面常驻，去阅读器再回来是瞬时的，不再是「跳出去又冷启动一遍」；
- 只在这次运行第一次产出文件、而且你正看着的时候自动打开一次；打开一个已完成的旧对话不会弹。

关于你说的「预览」：内核原生的预览标签读的是 `workspaceFiles`，那个接口按上游自己的文档是**不限目录**的，我们不能打开它。所以预览就是壳里的阅读器——同一件事只有一个地方看，不做两份。

### 3.7 执行流程

```
你的话（可带工具标签）
 └─ 普通问题：直接回答，零工具（现状已是，保持）
 └─ 要产出报告：
     计划（1 张计划卡）
      ├─ 默认：就在主对话里做 —— 检索 → 读全文 → 记结论 → 写报告 → 提交（过程行全在你眼前，「运行」页签同时给结构视图）
      └─ 值得并行/隔离时才委派；每张子任务卡内联该子任务最近几步 + 「查看过程」
     提交 = 渲染编号 → 门禁 → 独立审查，一次返回；文件此时仍可改；按意见就地修，再提交
     最后一条消息 = 给你的结论（中文）+ 报告入口 + 质控小结
     对话这一轮结束 = 运行结束，此时才冻结文件、出回执
```

与现状的差别和理由：

- **委派改按需，由模型判断。** 今天两次运行都是「1 件交付物」，却都多了一层：计划、委派、等待，过程全在别处。查了一轮（附录 B）：**DSH 自己的指令是反过来的**——「默认放后台跑，只有当你下一步就依赖它的结果时才设 `run_in_background: false`」，而且它的工作流工具明说「一两个委派就用普通子代理」；「子代理的中间步骤不进父对话」是它写在文档里的**设计代价**，不是缺陷。所以「每件交付物都委派」是我加的，内核从没这么说。委派真正买到的是并行和上下文隔离，一件交付物两样都用不上：没有并行（父只能干等），隔离换来的是你 20 分钟只看见一句「正在等待」。指令改成一句判断标准，其余交给模型——这也是原则 12 和 16。

  新的那句（写进所有智能体共用的那段指令）：**「默认就在这次对话里把活干完。只有两种情况才委派：同时有多件互相独立的活可以并行；或者一段附带工作会带回大量你不会再用的内容（一次大范围检索、一堆日志、一次全库扫描）。一件交付物就是一次对话，在这里交付。」**
- **不再强制先查记忆。** 现在的指令是「检索顺序 1. 先查记忆与胶囊」（`guidanceText.mjs:98`），于是每次开场固定两次 `evimed_capsule_recall`，账户里 0 条也查。相关记忆本来就会作为上下文注入；改成「需要用户既往资料或偏好时再查」。这也是原则 12（不强制每轮检索）。
- **「结束运行」不再是模型要调的工具。** 今天 GEO 那次：最终回答之后，`evimed_complete_run` 被一条规则拒了 → 模型用 bash 去读门禁实现 → 改用 `{"partial": true}`；这些行都排在最终回答后面。一轮对话结束就是运行结束；安全扫描在结束时由平台跑，结果作为提示附上（与 9-17「门禁裁定不扣交付」的裁定一致）。
- **阶段提示改成只进不退。** 现在「当前阶段」= 最近一次带标签的工具调用属于哪一类（`packages/domain/src/runPhases.mjs:107-119`），所以已交付的运行会停在「核验」（交付之后又跑了一次核对类调用）、「筛选」几乎永远是 0（只有两个工具算筛选，而模型很少用）。改成到达过的最远阶段；没用到的阶段不显示。你截图里运行才 14 秒就写「当前：核验」，这一条单靠上面的机制解释不了——那时还没有任何核对类调用；我怀疑是同一项目共用的运行侧状态文件把上一次运行的痕迹带了进来（和 §3.1 的串台同源），整改时先复现再定论，不在这里假装已经查清。
- **对用户说的话用用户的语言，内部名词不出现。** 今天主对话每一句旁白都是英文，还带 control plane / frozen bytes / gated artifacts / sub-agent。全平台只有开放问答那一个技能写了「Chinese in, Chinese out」（`runtime/skills/evimed/open-domain-answer/SKILL.md:69`），所以普通问题答得是中文；编排指令和 18 个能力的技能正文里一句都没有，而临床证据那份技能正文是 1,839 行英文，模型就被带成了英文。在所有智能体共用的那段指令里加一句稳定的话（对用户说的话用用户的语言，内部名词不对用户说），不是逐条禁令；再进离线评测（原则 16、6）。

### 3.8 结果质控

今天那份阿司匹林报告暴露的链条：**编号靠手改 → 门禁查不到「号对不对得上文献」→ 验收即冻结 → 审查排在冻结之后 → 修订授权只有服务端修复轮才签发，而修复轮自 9-17 起默认为 0 → 永远签不出来 → 带着已知缺陷交付 → 对话里不说。** 每一环单看都有当时的理由，连起来就是质控失效。

改法（每条都是数据依赖或确定性检查，不是新闸门）：

1. **编号在提交那一刻由程序渲染。** 现成的 `evimed_render_report`（按首次出现重排 [n]、重建参考文献表、同步矩阵；已有序时原样返回）今天子任务没调，自己用 bash 改的。把它并进提交：提交 = 先渲染，再检查。原则 10c「数字是渲染产物，不是手打的」。
2. **审查并进提交，一次返回。** 「先审查再提交」现在只是一段写在 1,839 行技能正文里的话，模型跳过了。改成提交工具自己调独立审查者，门禁结果与审查意见同一个返回值；`contradicted` 级意见以「必须改」返回，此时文件还能改。
3. **冻结挪到运行结束。** 运行内随便改、随便再提交；结束时出回执并冻结。之后在同一对话里要求修改 = 自动签发一次修订授权（用户开口要改就是授权）。
4. **新增一条提示级检查**（先作提示 + 指标，不阻断，原则 4）：账本里每条结论的 `referenceNumber` ↔ 参考文献表对应条目的 DOI / PMID / 题名 ↔ 正文引用号，三者一致。今天这个缺陷是审查模型加 5 次 bash 才查出来的，它本来是个确定性检查。
5. **一个结论词表，三个面一致。** 已交付 / 已交付 · N 条未能逐字核对 / 未完成。去掉「待你复核」「待人工复核」「自证未通过」。
6. **质控发现用中文、汇总到一处。** 本轮交付卡（§3.5）+ 报告预览里的 ✓ / ⚠。现在的「literature_search searched and returned no source」「review weakened: …」改成中文句子。
7. **花费按对话归属，不靠猜。** 交互式运行环境的模型令牌是按项目发的，网关只能问「这个项目里现在是不是恰好只有一个运行」，是才记到它头上，两个同时跑就都不记（`server.mjs:1243-1254`、`modelGateway.mjs:588-599`）。你今天正好在同一个项目里同时跑了两条：GEO 那次全程与阿司匹林重叠，所以显示「约 ¥0.00」（账本只归到 1 次请求）；阿司匹林那次的 ¥0.76 也只是没重叠那几分钟的，实际更高。默认项目是个杂物间，并发是常态。改成每次模型请求带上所属对话的根会话 id，网关按对话找运行。

### 3.9 记忆胶囊：一页

标题下一句定义（§3.1）。从上到下：

1. **总开关**（一个）+「本项目不使用记忆」（一个）。原来三个开关合并。
2. **EviMed 眼中的你**：四到六句生成的概述（你和你的方向 / 你的做法 / 这个项目）。每句都点得开、对应到下面的具体条目；没有条目支撑的话不出现。
3. **最近变化**：最近五条记下 / 改动 / 撤销，每条可撤销。（替代时间轴 tab；你要的「看到变化和成长」保留在这里和每条记忆的历史里。）
4. **清单 + 一个搜索框**：筛选 全部 / 关于我 / 我的做法 / 当前项目 / 已忘记（30 天可恢复）。搜索 = 关键词 + 语义（复用现有召回接口），搜的是句子、来源对话标题、项目名。
5. **每一行**：一句中文；来处标签（你说的 / AI 推断 / 来自研究）；「来自 9月12日《…》」可点回那条对话；「用过 7 次，上次 9月18日」；改、忘记；推断类多一个「不对」。强度用次数，不用百分比。
6. **页尾一行**：分享我的做法 / 导入别人的胶囊（你说「最最重要」的那件事，收成一个动作；收到的胶囊作为清单里的一组，整包启用 / 停用）。

**「我的做法」就是你说的「方法」**：由系统从你采纳的报告、你在对话里的纠正、同类任务的重复中学到，写成观察到的行为——例如「Meta 分析先报 GRADE 再报效应量（从你改过的 3 份报告学到）」。先生效、带「新」标、可撤销；后台配对评测只用来自动降级表现变差的做法。用户想固定一个要求，就在对话里说一句，它会被记下——不需要任何表单。

写入侧同时要改（否则页面再好看，里面还是今天这些东西）：报告里的数字和结论是**报告的内容**，不是记忆，不再存成「分析口径」；运行内部记账永不入库；每次研究只留一条「做过的研究」摘要（问了什么、结论一句、报告入口），显示在「当前项目」下；默认项目不写「项目主题」。

### 3.10 知识库

定义印在标题下。两个 tab（文件 / 整理进度）合成一页：文件列表，每行自带解析状态；「整理进度」只在有需要处理的条目时作为一条提示出现。「加入资料库」「放进胶囊」两个动作删除：资料读完后，其中带出处的事实自动进入记忆（标「来自资料」，可撤销）。

### 3.11 连接与启动

- 会话界面常驻：挂在壳上而不是路由里；去别的页面只是隐藏；每个项目一个，最多留 2 个（与每人 2 个运行环境的上限一致），超出按最久未用回收；
- 四步开场白只在真的启动运行环境时出现；界面已在就直接切，界面需重载就放一个普通骨架；
- 展开某个项目分组即预热它的运行环境（现成的 `warmWebRuntime`）；
- 租约 30 分钟，到 50% 续；失败静默重试；真过期才提示并自动恢复。

**什么时候该委派（补查，2026-09-20）。** 结论是业主的判断对的，而且有量化依据：

- **DSH**：`ctx.subagents` 是可选的能力接缝；`one-shot` 模式默认等待子代理，`run_in_background: true` 立刻返回作业号；`continuable` 模式直接返回子会话 id。它自带的唯一一段「何时委派」提示是「默认放后台，一次消息里把互相独立的委派一起发出去，自己继续干有用的活；只有下一步依赖某个子代理的结果时才设 `run_in_background: false`」。工作流工具的说明是「只有用户明确要求工作流或大规模多智能体编排时才用；一两个委派就用普通子代理」。两份文档都写明代价：「子代理的中间步骤不进父对话」「模型只看到一个最终结果，看不到任何中间消息」。**全部文档里没有一句建议「一件交付物也委派」。** 另外内核的工作流运行**是**作为一个节点画在对话里的（阶段 + 成员状态），也就是说「长时间的委派工作显示在主对话里」这个形状内核自己就有，只是给了工作流而不是子代理。
- **Claude Code**：该委派的情形是「这段附带工作会用你不会再看第二眼的检索结果、日志、文件内容淹没主对话」；不该委派的是「前后依赖的串行工作」和「小任务——委派的开销超过收益」。社区实测两条：重复性编辑直接改比委派「省 5–10 倍 token」；一次 4 小时、27 个子代理的会话里，仅保活用的状态摘要就占了 22.7% 的请求、18% 的加权 token，**成本随挂钟时间和扇出增长，不随有用的工作增长**——一个跑 30 分钟的独生子代理全程在付这笔钱。
- **Codex**：长任务是单智能体加结构化循环，用落盘的 markdown 做可见性；它的子代理功能正在被用户提同一个 bug——「主界面几乎看不出委派的活还在不在跑」。
- **同行**：Cursor（「长研究任务的上下文隔离」/并行才用，且劝「先从 2–3 个开始」）、Devin（子代理「通常只负责回答一个问题，不写代码」）、Manus（「子代理有用是因为它拿到干净的上下文窗口，不是因为它扮演了不同角色」，n 项才 n 个）、Aider / OpenHands（单智能体）。**没有一家默认委派。** 显示上做得最好的是 GitHub Copilot：子代理活动在对话里折叠成一张卡，卡上有一行「它现在在干什么」，可随时展开。
- **单体 vs 多体**：Anthropic 自己的数据是智能体约 4× 对话 token、多智能体约 15×，且「所有智能体需要共享同一上下文」和「智能体之间依赖很多」的任务上多智能体更差；它们的取胜场景是广度优先的扇出，不是一个孩子。LangChain、OpenAI 的建议都是先单体、只有分支真的需要不同工具或隔离时才拆。MAST（1600+ 条轨迹、14 类失败模式）：「多智能体系统在常见基准上的收益往往很小」。
- **只有一个好处成立**：上下文窗口隔离，而且这是真的——18 个前沿模型都随输入变长而退化。代价是编排 token、保活开销、冷上下文的延迟、以及**你没法纠正你看不见的 39 步思考**。我们的缓存命中 95%+，主对话变长的钱远小于这些。

**工具入口、长任务界面、设计语言、导航（E）。** 工具入口见 §3.4。长任务：Manus 的「电脑」面板、OpenAI 深度研究的活动与来源侧栏、Gemini 的计划 → 报告进 Canvas、Claude 的分屏产物、Devin 的进度页——右侧都是「先看它在干什么，再看结果」，结果以文档形式在右侧打开；我们取与 DSH 一致的那一半（右侧 = 文件与报告预览），过程留在对话里。设计语言见 §3.12（DeepSeek 自家界面：白底、单一强调色、平面加发丝线、只有浮层有阴影；Ant Design 与 W3C 中文排版要求给出 14/22 与行距 1.5–2.0；Anthropic 对宿主界面的建议是三种字号两种字重、0.5 px 描边、骨架屏而非转圈）。导航：Manus 四项、ChatGPT 因入口越堆越多被用户抱怨；调研建议把记忆和主动科研都收进设置，**这一条我没采纳**——记忆胶囊（尤其是胶囊分享）是你定的核心产品，留在一级导航。
