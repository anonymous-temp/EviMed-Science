## 2. 截图 1：循证 GEO · 信尔美 · 信源（Operate）

**它实际是什么。**[码] 每行是 `ListRow`，整行是一个被拉伸的“标题按钮”，点击只在行内展开一个 `SourceDetail`：备案 / 新闻源 / 医疗三项是否满足，加“单篇价格”；三项未核实时只显示一句“三项都未核实”。没有 drawer，没有跳转。所有者说“点了没反应”，源码和他看到的一致：展开了，但只多出一行不相干的字。

**问题（按严重度）**
1. **P1 · 点开的不是这一行承诺的东西**（启发式 6、4；认知负荷：渐进披露）。行里红字“有 14 处讲错”是整页最有分量的信息，却是死胡同——14 处在哪、哪句话、哪个引擎、哪个问题，点开都看不到。展开给出的“三条件 + 价格”是投放决策的信息，不是这行所说的事。
2. **P1 · 没有“可点”的表示**（启发式 1、4）。[图] 无箭头；[码] 悬停底色是 `surface-1`，对页面底色 `bg` 的对比约 1.04:1，肉眼等于没有；展开态也只多一行小字，没有选中色。读者既不知道能点，点了也不知道点中了。
3. **P2 · 数字嵌在句子里，不能比较**（启发式 6、7、8）。“被引用 69 次 · 有 14 处讲错 · 提到你 35 次”是一句话，三个数各行错位，没法纵向扫读；排序只有“被引用”，而可操作的维度是“讲错”（“只看 → 讲错过我方”是过滤，不是排序）。一行三行高，一屏 8–9 条，1,440 条要翻很久。
4. **P2 · 孤儿词“自有 / 覆盖 / 锚点”**（启发式 2、10）。[码] 表格时代它有列头“布局”；改成列表后列头没了，右端只剩一个灰色单词，既不是状态也不是动作。
5. **P2 · 筛选行 8 个元素**：五个引擎芯片、搜索、“只看”、计数；计数里还带“已排除 1 个冒名站”（统计怎么数，违反页面结构第 4 条；冒名站在页底已有折叠区）。
6. **P3**：无名称的行少一行，行高不齐；“可见度”页签的字也是深色，若不是悬停，会读成两个页签同时被选中。

**截图 5 对应的做法。**它的列表行只有“名称 + 下次时间”，点行就得到那件事本身（对话），行级操作在 ⋯ 里。映射到信源：行里只放读者据以决定“点不点”的数，点开就是**这些数背后的条目**。

**目标结构（shape）**
- 筛选行：保持一行；右侧只写“1,440 个信源”，冒名站只留页底折叠区。
- 列表：两行以内。第一行：名称 · 类型标签 · 灰色域名（同一行，截断）。右侧三列右对齐、表头吸顶、等宽数字：**被引用 / 讲错 / 提到你**，“讲错”大于 0 时才用红色；行尾一个“›”，悬停与选中用 `surface-2` / `accent-soft`。“自有 / 覆盖 / 锚点”移进详情，只在“自有”时留一个 Tag。排序：表头可点，默认被引用，可切到讲错。
- 点一行 → **右侧抽屉**（保留列表位置，一个有 1,440 行的榜单要自上而下浏览，这里抽屉是对的）：页头域名（可外开）+ 类型；正文顺序：① **讲错 N 处**：前 5 条，每条“引擎 · 讲错的那句话（波浪线，与回答页同一渲染）”，点一条去该条回答页；末尾“全部 N 处”；② 提到你 M 次（折叠，前 3 条）；③ 一行：备案 ✓ 新闻源 ✓ 医疗 ✗ · 单篇 ¥X（原来的详情降到这里）；底部唯一主按钮 **在对话中处理**（草稿含域名与讲错的句子，不自动发送，与 §6.4「循证 GEO 的问 AI」同一交接）。
- 数据：[码] `GeoErrorRow` 已有 `statement`、`engine`、`citedSource.domain/url`、`snapshotId`，抽屉的“讲错”可以是这批行按域名过滤，不需要新模型；唯一待验证的是错误读取有没有分页（“讲错的计数取全部记录”）——分页的话要加 `?domain=` 过滤。
- 去掉：行内展开、孤儿布局词、筛选行里的“已排除…”、三行高的行。

**与设计参考的冲突**
- §4.1 页面结构第 6 条允许“就地展开”，并把它算作合格的“给出结果”。截图 1 说明条款太松：结果必须回答这一行自己的主张。**建议**：第 6 条加一句“打开的内容必须能回答这一行写出的数字或状态（红字的计数打开后列出被计数的条目）”，并让走查的 `ROW_CLICK_PAGES` 断言“有讲错的行，打开后含指向回答页的链接”，而不是只检查“折叠线以下有变化”（参见记忆里“走查断言必须证明走到了”）。
- §15.3 与 B-7 把预期匹配 / 主战场 / 预期达标挪去方案页是对的；这里只补一条：信源行的详情要的是“讲错与来源的证据”，不是策略。

## 3. 截图 2：虚拟临床研究对话底部（Operate，内核页）

**它实际是什么。**[图] 输入卡片下方一行：会话统计（“1 轮 86 步 · 251 tok/s”）、用量（“6.1M tok · 缓存命中 95%”）、蓝色“虚拟临床研究 ×”芯片、两个原生下拉“起点：队列”“预期用途：探索”、一个 20% 的环。[码] 统计两项是内核的 `data-composer-stats`，只对运维显示（`runtimeUiShell.mjs`）；芯片与两个下拉是 EviMed 放进 `conversation.composer.dock` 的 `DockedChip`。所有者是运维账号，所以他看到 7 个元素；研究者看到的是芯片 + 两个下拉（+ 环，它是否属于被隐藏的统计没有核实），仍是 3–4 个，仍然贴底。

**问题（按严重度）**
1. **P1 · 贴底，没有底部留白**（启发式 8；layout：节奏）。[图] 按 2× 屏估：芯片底边距视口底约 4–5 CSS px，输入卡片与这一行只隔约 12 px。整组东西被压在窗口最下沿，像页脚而不是输入的一部分。[码] `apps/web/src` 里没有任何 `safe-area-inset-bottom`，手机底部手势条上同样会贴边。
2. **P1 · 一行 7 个元素**（认知负荷：选项 ≤4）。两类东西（运维统计、产品控件）一个节奏挤在一行。
3. **P2 · 原生 `<select>` 宽度被最长选项撑开**（启发式 4）。[图] “预期用途：探索”的箭头离文字约 130 px，几乎碰到右边的环；“起点：队列”的箭头紧贴文字，同一行两个控件的形态不一致，且 `appearance: auto` 的外观随系统变。
4. **P2 · 蓝色芯片是这一区最饱和的元素**，比（空输入时淡蓝的）发送键还显眼；它的 × 与下拉同排，误触会退出工具（启发式 5）。
5. **P3**：运维统计与产品控件不该共用一行（启发式 4）。

**目标结构（shape）**
- 主方案 A：芯片与选项移到卡片**上方**的 `conversation.input.dock` 席位，外包一层宽度等于输入卡片的容器（`max-width: var(--dsh-composer-card-max-width)`，居中，`HeroTools` 已经用这个做法；§4.6 之所以退到卡片下方，是因为这个席位铺满整个框架、芯片会跑到左边缘——外包容器正是它的解法）。一行最多两个东西：芯片“虚拟临床研究 ×”，和一个合并控件“队列 · 探索 ▾”（点开是两个字段，各自带“AI 设定”标注，与 §15.2 一致）。卡片下方不再有 EviMed 的东西，运维统计留在内核自己的行里。

## 4. 截图 3：定时任务详情抽屉（Operate）

**它实际是什么。**[码] `AutopilotPage.tsx` 里右侧 `Drawer`（约 672 px）：页头配置摘要、三个按钮（编辑任务 / 立即运行 / 更多）、**蓝色气泡 = 任务指令**、“研究进展”卡（补充材料）、`TaskTimeline`（每次执行一段）、底部**自绘的追问输入框**。也就是说，外壳在抽屉里画了一个迷你对话：气泡、时间线、输入框，全部不是内核的。执行条目底部只有一个小字链接“打开运行对话”（`TaskTimeline.tsx`，`chatPath(sessionId)`），没有运行时它不存在。

**问题（按严重度）**
1. **P1 · 对话被画成了抽屉**（启发式 4、3；违反 §2.1 总则 2、§4.2「对话工作区：外壳不重画输入框、消息流和过程视图」、§6.2 唯一输入框）。内核已经有流式输出、排队与插话、停止、运行视图；抽屉里的副本一个都没有。
2. **P1 · 任务与对话断开，不能实时驱动**（启发式 6、7）。[码] 追问不是对进行中的会话说话，而是新建一次 `follow-up` 执行；进行中的执行靠轮询刷新（抽屉里还会出现“自动刷新已暂停”）。任务级没有“打开对话”，对话里也没有任务的痕迹（没有任何由对话创建任务的路径，MCP 与工具名里没有）。
3. **P2 · 空态占满抽屉**（启发式 8；clarify：每个意思只说一次）。[图] 内容区约 47% 空白；“还没有运行”写了两遍（卡片上方一遍、下方“还没有运行结果。”一遍）；“研究进展”卡片里只有“补充材料 / 添加材料 / 从知识库选择”，标题与内容不符；输入框占位写“更正上面的结论”，而上面没有结论。
4. **P2 · 页头写预算，立即运行还要确认**（启发式 2、5；违反 2026-09-20“预算平时不写”、§6.5 花钱确认只有两种、E-7 统一灵豆）。“单次上限 ¥100”在页头；[码] 立即运行弹 `ConfirmDialog`“本次最多花费 ¥…”。
5. **P2 · 三个按钮读成页签条**（启发式 4）。[图] “立即运行”灰底像被选中的页签，“编辑任务”“更多”是纯文字；主操作与次操作同权重，页面上最响的是用户自己写的那句话（蓝气泡）。
6. **P2 · 列表行没有 ⋯**（启发式 7）。暂停、立即运行要先开一个模态抽屉。ListRow 本来支持常显的 ⋯（2026-09-24 裁定），这里没用。

**截图 5 做对了什么（对本屏，也对知识库）**
1. 一种对象一个表面：任务 = 列表里一行；任务的执行 = 主区里的对话；没有第二个对话。
2. 任务从对话里诞生：用户说一句话，助手回三句短话，下面一张**任务卡**（图标、名称、周期、“打开”）。对话 → 任务有链接，任务 → 对话就是点那一行。
3. 列表是**常驻的次级面板**，不盖遮罩：点另一个任务，主区直接换。
4. 行级操作在行的 ⋯ 里：暂停、立即运行、编辑、分享、删除，删除分隔并标红。
5. 行上只有两样：名称、下次时间。没有预算、没有状态词表。
6. 输入框永远是同一个；过程是一行折叠的“用时 30 秒 ›”（对应内核的“N 次工具调用”）。
- 不要照搬：分享、朗读、点赞（那是内核消息操作的事）；“ChatGPT 可能会出错”一行（违反“不解释系统如何运作”）；它是图标栏加次级面板两层侧栏，EviMed 只有一条全局侧栏，对应物是**页内的列表栏**。

**目标结构（shape）**
- ≥ 1024：三栏。全局侧栏 | **任务列表栏**（约 320 px，页内，不是抽屉：页头“定时任务”+ 搜索 + 一个主按钮“新建任务”；分组“即将执行 / 已暂停”，每行 = 名称 + “下次 明天 07:00 · 每天”，行尾常显 ⋯：立即运行 · 暂停或启用 · 编辑 · 删除（删除分隔，红色）；执行中的任务行用 `RunStatusDot`）| **主区 = 所选任务的对话**。
- 主区顶部一条外壳自绘的任务条（在 iframe 之外，外壳随便画）：任务名；“每天 07:00 · 中国标准时间 · 下次 10 月 9 日 07:00”；一个主按钮“立即运行”（执行中变“停止”）；⋯。预算不写。条下面是**内核对话本身**：最近一次执行的会话（实时流、排队与插话、运行视图、文件卡与来源卡都沿用内核与 `conversation.chat.node` 里已有的 EviMed 卡）。任务指令是这次对话的第一条用户消息，不再另画蓝气泡。
- 执行切换：任务条里一个安静的“第 N 次 ▾”，列出每次执行的日期与结果（有结果 / 失败；“无新证据”要等 N-8）；换一次 = 换 iframe 的会话。“补充材料”进入内核输入框的 `+` 和 ⋯，不再是一张卡。
- 还没有运行：主区只有任务指令、“还没有运行，下次 10 月 9 日 07:00”、主按钮“立即运行”。不画空卡，不画输入框（没有会话就没有输入框）。
- < 1024：列表就是页面，点一行进 `/app/autopilot/:id`（全屏，页头有返回）。
- 实时驱动 = 进行中的执行就是一个普通会话：输入框里的排队 / 插话（Ctrl/⌘+Enter）与停止都是内核原生；已结束的执行里追问就是在同一会话里继续。
- 立即运行：不再弹确认，改成一条带“打开”的提示（§6.5）。
- **分期**：P1（不需要新契约）= 点任务行进入“任务条 + 最近一次执行的对话页”（用现成的 `chatPath(sessionId)`），去掉抽屉、蓝气泡、自绘输入框、页头预算、确认框，行上加 ⋯。P2 = 页内列表栏的三栏布局（要让 `SessionFrameHost` 能把框架摆在页内窗格里，每个项目至多 2 个框架，要核对）。P3 = 从对话创建任务并留下任务卡：需要一个 `schedule_task` 工具（evimed-research MCP）、`conversation.chat.node` 里的任务卡渲染、≥3 个 `evals/` 用例（原则 9），表单保留为次路径。
- **已知代价**：打开一次已结束的执行 = 冷启动运行环境（约 5 秒，且受“后台工作至多占上限减一个运行位”约束），没有运行环境时对话读不出来（N-1）。所以任务条里“成果文件”必须不依赖运行环境就能读（现有的阅读器路径保留），按 §7.2 把等待原因说具体。
- 去掉：右侧抽屉、蓝色气泡、迷你时间线、自绘追问框、研究进展卡、页头预算、立即运行确认框、重复的“还没有运行”。

**与设计参考的冲突**

## 5. 截图 4：知识库 · 资料抽屉（Operate）

**它实际是什么。**[图] 抽屉 ≈ 555 CSS px：类型 · 大小，文件名，页签“内容 / 原文”，“讲了什么”五段（每段 7–11 行），底部固定“在对话中使用”（主）+“下载”。后面的列表页只有一行资料，其余近 90% 是空白。

**问题（按严重度）**
1. **P1 · 对象是文档，详情面却是抽屉**（启发式 4；operate.md：“Modal as first thought. Modals are usually laziness”）。摘要 + 原文都挤在 576 px 侧栏里，原文要靠“抽屉加宽”才勉强可读（§13.1）。§5.3 自己写着“长文和可以单独引用的文件用页面”，一份 PDF 恰好既是长文又要被引用。
2. **P2 · 摘要是五段整块文字，约 190 字一段，没有结构**（启发式 8；认知负荷：分块、渐进披露）。第一段已经是行上的一句话要点，第二到五段是逐条罗列（“1.1 判辨证推理内容错误，1.2…”），末段在评价这份资料而不是概括它。
3. **P2 · 缺少主流知识库的三个基本面**（启发式 6、7，对照见下）：① 范围选择：哪些资料进这次对话，现在只能在输入框里 `@`；② 结构视图：页、表格、图的覆盖（`coverage.materials` 数据已有、界面不用，E-9）；③ 引用回跳：对话里的引文点回资料的位置。
4. **P2 · 一条资料的页面几乎空白**，抽屉盖住的列表也没有下一步（启发式 8；onboard：空态给下一个有用的动作）。
5. **P3**：“…”里藏着重新读取、删除；读取失败的原文下载要在抽屉里才看得到。

## 7. 跨页面发现

1. **抽屉被用来装“对话”和“文档”。**[码] 全应用 28 个非测试文件用 `Drawer`。记录类（记忆条目、收件箱、矩阵行）合适；定时任务把一个对话塞进去并重画了它的输入框，知识库把一份 PDF 的阅读塞进去。这是本轮最大的一类问题，也是“又是抽屉”的原因。
2. **看起来能点却交不出东西。**[码] `ListRow` 的行内展开（`expanded=`）在 7 个文件里用：收件箱、插件、技能、虚拟临床研究数据页、科研额度、GEO 的 `EvidenceTab` 与 `SourcesTab`（GEO 的 `QuestionsTab` 也有展开）；只有“展开后确实回答了这一行”的才合格，截图 1 是反例，应按这个标准把这几处过一遍。红色计数（“讲错 14”）也属于“能点的东西”，必须是链接。
3. **贴底控件没有呼吸空间。**[图] 截图 2；[码] `apps/web/src` 里没有 `safe-area-inset-bottom`，输入区、抽屉底部操作条在有底部手势条的手机上都会贴边。应作为统一规则而不是单点修补。
4. **从表格改成列表时丢了列头。**“自有 / 覆盖 / 锚点”是例子；改成行内句子的数字（“被引用 69 次 · …”）同样失去了可比较性。列表行里同类的数应该对齐成列并有表头。
5. **后台账词汇与预算漏到用户页。**“单次上限 ¥100”（页头）、“已排除 1 个冒名站”（筛选行）、运维账号下与产品控件混排的 tok/s 与缓存命中。
6. **空态带着全套外壳。**截图 3 的半个抽屉、截图 4 的一行资料页：没有内容时应该只留一个下一步，不画空卡、不画输入框。
7. **说两遍。**“还没有运行”×2，列表要点与摘要第一段重复。clarify 的原则：每个意思只说一次。
8. **控件形态不统一。**原生 `<select>` 与自绘胶囊、按钮条像页签、主操作灰底。
