# EviMed AI 原生研究平台设计参考规范

版本 1.0 · 2026年10月8日 · 适用对象：产品、交互、视觉、前端、研究能力与质量团队

EviMed 的设计目标，是让研究者从问题和材料出发，持续获得可以阅读、核查、修改和复用的研究成果。对话承担表达意图，工作界面承接材料、分析与结果；用户离开对话后，仍然能够找到自己的研究，理解依据，并继续工作。

本规范覆盖平台的产品理念、入口层级、布局、交互、视觉、内容、AI 状态、主要页面、响应式、无障碍、性能和验收。它延续现有循证蓝与组件体系，将 AIHOT 的内容组织经验和人机交互研究转化为 EviMed 的具体设计要求。

## 2. 产品理念与核心工作对象

### 2.1 四项产品原则

| 原则 | 在界面上的含义 | 不符合的表现 |
|---|---|---|
| 简单 | 用户在当前位置能识别下一步；必要信息就地提供 | 为一个操作新增入口、页面和解释文案 |
| 明确 | 名称、范围、状态和动作后果一致 | “完成”却找不到结果；“重试”实际开启另一项工作 |
| 清楚 | 信息层级对应研究者的阅读顺序 | 统计卡、流程图和标签先占满首屏 |
| 完整 | 成功、部分结果、未知、失败与恢复都有可用路径 | 只设计有数据时的漂亮画面 |

四项原则是现行约束。后续规范将它们落实到具体对象、页面和行为。

### 2.2 AI 原生的六项设计要求

1. **围绕成果组织工作。** 一份报告、一组证据、一张分析表可以独立打开和继续使用。用户不必翻阅长对话才能找到结果。
2. **自然语言与直接操作配合。** 用语言描述问题，用选择、表格、筛选和局部编辑处理明确参数；不要要求用户为每次排序或换单位重新写提示词。
3. **让依据靠近判断。** 需要核查的结论可直接打开相应来源、原文或计算输入；不要只在页面底部堆参考文献。
4. **让委托可以持续。** 用户离开、刷新、切换页面后，任务、草稿与成果仍有归处。后台工作应有可找回的入口。
5. **让修改具有范围。** 修改一句话、一个分析假设或一列变量时，说明影响范围，保留原版本，避免无意重做全部成果。
6. **让不确定性可以理解。** 分开表达“没有读到”“没有发现”“存在冲突”“尚未核实”，而不是用一个 AI 分数概括。

混合界面有助于减少用户将意图完整表达成提示词的负担；这为第 6 节的输入设计提供依据，并不意味着所有任务都需要表单。[NN/g，Hybrid Interfaces](https://www.nngroup.com/articles/ai-articulation-barrier/)

### 2.3 稳定的工作对象

| 对象 | 用户理解 | 应具备的可见信息 | 典型操作 |
|---|---|---|---|
| 项目 | 一项持续研究的范围 | 名称、相关对话与资料、当前所处项目 | 切换、重命名、整理 |
| 对话 | 围绕问题的讨论与委托 | 问题、回复、相关任务和成果 | 继续讨论、发起研究 |
| 任务 | 一次有明确目标的工作 | 做什么、真实状态、可用结果、可执行的恢复动作 | 查看、取消、按支持范围继续 |
| 资料 | 原始文献、数据或文件 | 来源、版本、可读范围、解析结果 | 打开、引用、用于研究 |
| 成果 | 报告、证据矩阵、图表等 | 内容、依据、适用范围、版本 | 阅读、核查、导出、局部修改 |
| 事件 | 同一件事的多个报道与进展 | 发生了什么、最新变化、来源和关联 | 跟踪、阅读原文、深入研究 |
| 记忆 | 可复用的研究背景或做法 | 内容、适用范围、来源、有效时间 | 编辑、停用、恢复、用于后续工作 |
| 专业研究对象 | 一项临研或 GEO 项目 | 所属项目、当前阶段、材料与结果 | 在模块内推进和查看成果 |

这些是产品认知对象，不要求为每个对象增加一级菜单或新建数据库。任务继续归于它发生的对话，专业研究对象继续归于其模块。

### 2.4 平台应形成的工作闭环

发现值得研究的问题 → 带着来源发起委托 → 获得可阅读成果 → 核查关键依据 → 修改或比较 → 留存资料与记忆 → 在有新证据时继续。

闭环的每次交接都应保留用户选择的对象、研究范围和来源。跨页后把上下文清空、只留一个空输入框，视为流程缺陷。

### 2.5 四种使用情境

| 使用情境 | 用户当下需要 | 设计侧重 |
|---|---|---|
| 短时间了解变化 | 判断有哪些新进展、是否与当前工作有关 | 有终点的简报、明确变化、来源与收藏 |
| 深入核查问题 | 理解结论、证据和适用边界 | 舒适阅读、逐条依据、相反证据与来源定位 |
| 带数据开展研究 | 确认变量与方法，取得可复核结果 | 资料与分析并排、可编辑参数、版本和计算产物 |
| 持续推进项目 | 接续工作、管理委托、跟踪结果 | 项目范围、恢复位置、历史成果与有节制的通知 |

同一用户可能在一天内切换这些情境，界面密度和辅助信息应随任务变化。这里的情境不新增账户角色，也不改变后端权限模型。

## 3. 信息架构与入口层级

### 3.1 四层入口

| 层级 | 解决的问题 | 应放内容 | 不应放内容 |
|---|---|---|---|
| 全局目的地 | 我到哪里做这类工作 | 新对话、前沿动态、科研工具、知识库等 | 单个工具调用、每一个技能、每一份报告 |
| 模块视图 | 在这里看哪一类内容 | 动态与简报、资料与文件、插件与技能 | 重复的全局导航 |
| 工作对象 | 我正在处理什么 | 一个事件、一项研究、一份报告 | 与当前对象无关的推荐墙 |
| 就地操作 | 现在对这个对象做什么 | 查看依据、收藏、筛选、导出、修改 | 为轻量动作单独开一套页面 |

从全局入口到已有结果，目标是经过清晰的“列表 → 对象”路径；复杂任务允许更多步骤，但每步都必须带来真实决策或信息，不用强制“三次点击”替代任务分析。

### 3.2 保留的全局导航与当前地址

**现行约束：**主入口、顺序和模块可见性以 [Sidebar.tsx](../../OpenScience/apps/web/src/components/sidebar/Sidebar.tsx) 为准；路由以 [router.tsx](../../OpenScience/apps/web/src/app/router.tsx) 为准。首页目前进入对话，不额外增设营销式工作台首页。

| 当前入口 | 当前地址 | 主要任务 | 层级要求 |
|---|---|---|---|
| 新对话 | `/app/chat` | 提问或发起研究 | 首要发起入口；历史对话在项目分组中继续 |
| 前沿动态 | `/app/frontier` | 发现事件、阅读简报、跟踪进展 | 开通时紧接新对话；内部容纳证据专区 |
| 科研工具 | `/app/capabilities` | 找到适合目标的研究能力 | 不把每项能力铺进全局导航 |
| 虚拟临研 | `/app/virtual-research` | 推进具体研究 | 开通时位于科研工具之后 |
| 循证 GEO | `/app/geo` | 分析与改善 AI 答案中的品牌表现 | 开通时位于虚拟临研之后 |
| 知识库 | `/app/files` | 管理和使用研究材料 | 承接资料、预览与相关文件 |
| 记忆胶囊 | `/app/memory` | 管理可复用背景和做法 | 不与原始资料混为同一列表 |
| 定时任务 | `/app/autopilot` | 管理持续委托 | 每次执行都能找到对应结果 |
| 插件与技能 | `/app/extensions/plugins` | 管理扩展 | 保持普通用户可达；模块故障不拖住无关研究 |
| 收件箱 | `/app/inbox` | 查看需要注意的变化和结果 | 作为通知入口，避免再复制一份任务列表 |
| 设置 | `/app/account` | 账户、外观、额度、数据源、项目等 | 留在账户区；运维按真实权限提供 |

插件与技能的两个视图分别位于 `/app/extensions/plugins` 和 `/app/extensions/skills`。专业模块未向当前账户提供时，不显示可以点击但只能得到“尚未开放”的导航项；旧深链仍应给出具体说明和有效返回入口。

### 3.3 项目范围与导航行为

**现行约束：**项目是账户级选择，普通路由不携带项目 ID。不要为了面包屑方便，擅自改成另一套 URL 体系。

目标行为：

- 项目切换处始终能辨认当前项目；同名项目增加有意义的区分信息，例如研究主题或创建日期，不以原始 ID 替代名称。
- 切换项目时，旧请求的迟到响应不得覆盖新项目。正在编辑的内容保留在原项目，不能被静默移动。
- 跨项目成果链接先解析所属范围；仅在有访问权时进入正确对象。无权限、对象已删除、连接失败分别处理。
- 浏览器前进、后退恢复筛选、滚动位置、当前对象和阅读位置。恢复动作不得再次提交任务或扣费。
- 一个模块只有一套内部导航。嵌入宿主平台时由宿主承担全局导航，不能叠加第二个侧栏。

### 3.4 何时新增入口

只有同时满足以下条件，才考虑新增全局入口：有独立且高频的用户任务；有持续管理的对象；现有目的地不能自然承接；在移动端和权限差异下仍有清晰归属。

若只是新增一种研究能力、一个结果视图或一种筛选，应进入现有能力目录、对象页面或就地操作。能力数量增长，不应导致导航数量同步增长。

### 3.5 搜索与快捷方式

搜索框应注明范围，例如“搜索本项目资料”“搜索动态”。跨范围搜索结果必须按项目和对象类型区分；资料、对话、事件和工具不能以同一种无标识的卡片混排。

全局命令面板属于探索项。它应调用已有导航和动作，保留普通可见入口；不能成为访问功能的唯一方式。`/` 等单字符快捷键在输入框和中文输入法组合期间不触发，并允许关闭或改为组合键。

## 4. 页面布局与信息顺序

### 4.1 全局框架

**现行约束：**使用 PageShell；标题、操作区与主体共享左边界。页头为单行标题，可附灰色数量或更新时间，最多一个主要按钮与两个图标操作，或一个搜索框。不得添加解释系统机制的副标题。

主体的阅读顺序为：当前对象或问题 → 有价值的内容或可用结果 → 与当前内容有关的操作 → 依据及补充信息。布局可以变化，但不能颠倒这一优先级。

| 区域 | 作用 | 布局要求 |
|---|---|---|
| 全局侧栏 | 目的地和项目切换 | 稳定位置，允许收起；长项目列表不挤走核心入口 |
| 页头 | 当前页面、对象与主动作 | 与正文对齐；不重复全局入口 |
| 内容工具栏 | 搜索、筛选、排序 | 控制当前内容；低频条件放入展开面板 |
| 主体 | 阅读、比较或操作 | 获得最大可用空间；先出现实际工作内容 |
| 上下文面板 | 来源、目录、属性或局部编辑 | 只服务当前对象，可关闭；窄屏转为抽屉或就地展开 |

### 4.2 五种页面模板

| 模板 | 适用页面 | 容器与结构 | 关键要求 |
|---|---|---|---|
| 阅读型 | 回答、报告、证据解读、文章 | `read`，正文内使用阅读行宽；按需打开来源面板 | 先给内容；目录和依据方便到达 |
| 列表型 | 前沿精选、工具、收件箱、扩展、记忆 | `page`，标题和工具栏后直接出现列表 | 同类信息对齐；批量内容用行，不堆重复大卡片 |
| 数据型 | GEO 指标、研究结果总览 | `wide`，结论与关键指标在前，解释性图表在后 | 数字带口径；图表支持比较与追溯 |
| 材料工作区 | 知识库、证据矩阵 | `wide`；集合、对象、预览分区 | 三栏仅在可读时并列；只保留一个主对象 |
| 对话工作区 | 提问、委托、继续研究 | 现有对话壳；正文和成果按内容类型呈现 | 输入区稳定；历史消息与实时任务可分别恢复 |

`read`、`page`、`wide` 的当前数值见第 10 节。表格或大图需要更宽空间时，在其自身容器内展开，不让整页所有文字变成超长行。

### 4.3 首屏预算

在 1440 × 900 桌面和 390 × 844 手机视口中，普通列表页应在无需滚动时看到至少一条可理解的内容及其主操作；阅读页应能看到标题与正文开始；专业研究页应能看到当前对象和可用成果入口。

以上是拟定的产品验收条件，不是行业通用定律。安全相关提示、必要身份验证和真实空状态按内容需要处理，不能为了满足首屏指标隐藏它们。

为达到这一目标：减少重复页头；把低频筛选收进同一入口；摘要榜单不要再展示完整榜单；移动端不同时展开全局菜单、归档、目录与详情；将长流程折叠为当前阶段和可展开的历史。

### 4.4 边框、留白与密度

通过间距表达分组，再使用背景差异，最后使用边线。现行规则限制至多一层带边框的容器嵌套，避免“卡片中套卡片再套标签框”。

密度按任务决定：浏览用紧凑行，判断用对比表，阅读用舒适行距。不要把数据表的一行强制扩成高卡片，也不要将正文挤成仪表盘的密度。列表可以铺满其容器，单条长摘要仍遵守阅读行宽。

### 4.5 典型页面排布

| 页面 | 首区 | 主内容 | 辅助区 |
|---|---|---|---|
| 前沿精选 | 标题、模块导航、当前视图与必要筛选 | 事件与新进展；紧凑热点摘要不得挤走首条内容 | 其他筛选、关注管理 |
| 研究报告 | 标题、关键范围、主要结论与真实限制 | 按问题组织正文、表格、图 | 目录与所选结论的依据 |
| 知识库 | 标题、上传、搜索 | 集合与资料列表、所选资料预览 | 元数据、解析范围、用于研究 |
| 虚拟临研 | 研究名称、当前阶段、可读结果 | 当前阶段材料与操作 | 历史、依据、其他阶段 |
| GEO 概览 | 项目、测量范围、时间与关键结果 | 趋势、差异和对应答案样本 | 口径、筛选、后续工作 |

## 5. 响应式、滚动与焦点

### 5.1 结构变化

**现行约束：**断点为 640、768、1024、1280、1536 CSS px；小于 1024 时全局侧栏使用覆盖式抽屉；小于 768 时正文侧边距 16 px。响应式优先调整结构，不缩小字体来塞进桌面布局。

| 场景 | 桌面 | 手机 |
|---|---|---|
| 全局导航 | 展开或收起的侧栏 | 顶部入口打开抽屉；关闭后移出焦点序列 |
| 报告依据 | 与正文并排，或非遮挡面板 | 打开单层阅读抽屉，关闭回到原结论 |
| 归档与目录 | 可固定在正文旁 | 单一目录/日期入口，不常驻占据首屏 |
| 复杂筛选 | 常用条件可见，其余展开 | 保留当前条件摘要与筛选按钮 |
| 宽表 | 表头固定，必要时冻结标识列 | 表内横向滚动并有提示；重要字段提供行详情 |
| 对比结果 | 并排或差异表 | 按同一比较维度纵向成对展示 |

### 5.2 滚动约定

- 阅读页以页面纵向滚动为主；不要给每个正文块再套独立滚动区。
- 多栏工作区可以独立滚动，但每栏必须有明确边界；触控板、键盘和触摸均能到达完整内容。
- 流式回答只在用户仍处于底部时自动跟随；用户向上阅读后停止跟随，提供“查看新内容”。
- 新动态进入时显示可点击的更新提示，不插入到用户正在阅读的行上方造成跳动。
- 固定页头、底部输入区、软键盘不得遮住焦点、错误提示和最后一行内容。

### 5.3 层级与返回

菜单用于短动作，浮层用于短解释，抽屉用于保持背景的对象阅读，对话框用于需要集中处理的短决策；长文和可独立引用的成果使用页面。

关闭最上层后恢复到触发控件；若控件已被删除，恢复到合理的相邻对象。Escape 关闭当前可关闭层，不连续退出整个工作流。路由变化与同页筛选使用不同的焦点策略，避免每次筛选都把用户送到页面顶部。

不得仅将隐藏侧栏宽度设为零却保留内部可聚焦元素。2026年10月7日审查 B02 发现过此类问题；验收应直接测试关闭状态下的完整 Tab 路径，而不仅检查截图。[审查 B02](2026-10-07-impeccable/report.md#b02--全局侧栏与项目选择--p1)

## 6. 输入、澄清与跨页面交接

### 6.1 从用户已有内容开始

| 用户输入 | 优先承接方式 | 不应强制发生 |
|---|---|---|
| 简单问题 | 直接回答，必要时引用依据 | 为每个问题创建计划、表单或文件包 |
| 明确报告请求 | 识别交付目标，带入必要参数与材料 | 让用户先认识内部智能体名称 |
| 已有数据 | 进入数据理解与研究范围确认 | 默认当作仅需检索文献的任务 |
| 一篇文献或一个事件 | 带入原文、标识和研究问题 | 让用户重新粘贴已经打开的内容 |
| 一份现有报告的修改要求 | 锁定段落、表格或版本 | 静默重写整份报告 |

**现行约束：**普通问答与文件交付型研究是两条产品路径；研究能力按真实意图选择。简单问题不强制使用工具、记忆或规划流程。

### 6.2 输入区

输入区应明确当前项目、已选材料与提交动作。材料显示为可移除的对象条目，长文件名可完整查看；上传中、上传失败、已上传但尚未读完分别呈现。

常用参数通过小范围控件提供，例如人群、时间范围、结果形式；复杂参数按需要展开。已从材料获得的信息先展示为可修正值，不要求用户重复填写。空白页可以给少量具体示例，开始工作后让位于内容。

“开始研究”表示将启动工作；“生成草稿”表示可编辑预览；“保存”表示保存当前对象。相同按钮名称在不同页面不得触发不同等级的副作用。

### 6.3 澄清与默认值

只有缺失信息会显著改变对象、方法、范围、费用或结果解释时才追问。一次询问优先聚合相关问题，提供可选答案与自由输入；非关键项给出明确默认值并允许后改。

例如，只要求整理一篇论文时，不先要求完整研究方案；明确要求两组数据比较但缺少分组字段时，应先确认字段。默认假设写在受其影响的结果附近，不用全局横幅重复提醒。

### 6.4 交接协议

从前沿动态、知识库、证据专区或专业模块进入对话时，至少携带：原对象、来源链接或材料引用、当前项目、选定范围和用户要做的动作。输入草稿可编辑，用户明确提交后才开始新研究。

“深入研究”沿用当前前沿动态的草稿交接行为，不把一次点击改成自动运行并消耗额度。点击一次、返回再进入、刷新深链均不得造成重复提交。

### 6.5 权限与确认

已有委托范围内的阅读、分析和可恢复编辑，不增加逐步确认。授权范围、预算与停止条件在持续任务设置处集中管理。

删除不可恢复资料、变更共享范围、对外发布或产生新支出等操作，按真实业务契约提供后果明确的确认；不能把这些权限从记忆或材料内容中推导出来。托管环境不允许的动作应清楚说明并提供可行替代，不能生成一个实际上无法批准的弹窗。

## 7. AI 长任务与状态规范

### 7.1 三种状态分别表达

| 维度 | 回答的问题 | 示例 | 不可替代的概念 |
|---|---|---|---|
| 执行状态 | 工作进行到哪里 | 进行中、已结束、未完成、已取消 | 不是结论正确程度 |
| 内容完整性 | 有哪些结果可以用 | 报告可读、图表暂缺、部分资料未读到 | 不是“整个任务失败” |
| 依据与不确定性 | 结论有何支持或限制 | 引文待核对、来源冲突、适用范围有限 | 不是完成进度或热度 |

现有运行标识沿用统一 runState 与 RunStatusDot 的状态映射；各模块不得自行把同一状态翻译成互相矛盾的结论。已完成的绿色圆点表示执行结束，品牌色的核对标记表示对应检查结果，两者不能混用。

### 7.2 状态与可执行动作

下表为目标行为；只有服务端已支持的动作才能出现在界面中。

| 场景 | 必须显示 | 可提供动作 | 禁止表现 |
|---|---|---|---|
| 提交尚未确认 | 输入仍保留、提交正在确认 | 避免重复点击；确认失败后重试 | 先清空输入再无法找回 |
| 已接收或等待运行 | 真实等待状态、任务归属 | 查看、取消（若支持） | 假装已开始检索 |
| 正在工作 | 最近可观察的有效变化、已有结果 | 查看部分结果、取消、离开页面 | 随时间自动增长的百分比 |
| 需要关键输入 | 缺什么、影响什么、输入位置 | 补充后继续（若支持） | 模糊的“请确认” |
| 当前连接断开 | 连接状态与最后确认的任务状态 | 重连、查看已有内容 | 将前端断网直接判为任务失败 |
| 部分结果可用 | 可读结果与具体缺项 | 打开、导出、补做缺项（若支持） | 隐藏全部成果或写成全部完成 |
| 工作结束 | 结果入口、适用范围、真实发现的问题 | 阅读、核查、修改、导出 | 只有庆祝图标没有内容 |
| 工作未完成 | 已保留内容、具体原因、正确恢复入口 | 重试相应步骤或重新发起 | 所有错误都引向“查看额度” |
| 已取消 | 停止状态及仍然保存的内容 | 阅读已有结果、另起工作 | 把“取消”解释为删除成果 |

### 7.3 进度呈现

AI 研究不使用伪百分比、虚构倒计时或循环播放的固定阶段。可以显示已实际发生的动作摘要，例如正在比较哪些材料，以及已有何种结果；只有总量已知的上传、下载和确定性批处理才使用相应进度条，并明确它的范围。

长任务的状态应分层：主界面显示当前工作与可用结果；展开后显示简洁的行动历史、来源与时间；工程日志留在诊断入口。不得把模型的内部推理或生成的工作日记冒充可验证执行记录。

Microsoft 的人机交互指南强调能力、状态、纠错和长期使用的可理解性；Microsoft 的 Agent UX 将任务跨时间和前后台运行纳入界面设计。这里据此采用持续可找回的状态，而不要求用户逐步批准每个动作。[Human–AI Interaction Guidelines](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) · [UX design for agents](https://microsoft.design/articles/ux-design-for-agents/)

### 7.4 失败与恢复

会话运行环境不可用时，应尽可能继续显示已经保存的历史消息和成果。没有服务端断点恢复能力时，按钮必须叫“重新发起”，不能叫“继续”；预计会重新计算或再次计费时，在动作处说明。

恢复优先级是：恢复读取 → 恢复连接 → 继续可续接步骤 → 对缺失部分重试 → 最后才是重新发起全部任务。取消、重试和刷新均应防止重复副作用。

### 7.5 部分交付

**现行约束：**可读成果与质量发现一起呈现，不能因格式、模板或非阻断性检查而整体扣留。临床安全发现醒目显示，待核对项就近呈现；来源完整性破坏、运行中断或没有结果等情况按真实契约处理。

界面应提供“已有什么”和“还缺什么”，避免用单一红色失败页覆盖已有研究。不得额外加入所有结果必须由人工裁决后才能查看的步骤。

## 8. 成果、依据与版本

### 8.1 阅读层级

成果首先回答研究问题，再交代适用范围、关键结果和会改变解释的限制。正文按内容组织；依据与方法可逐层展开。不得将每份短回答强制塞入同一个长报告模板。

报告与引用分为三层：

1. 正文中的结论与清晰的引用标记。
2. 当前结论的依据浮层或面板，说明支持内容、原文与来源。
3. 来源文档或原文位置，保留页码、段落或表格坐标等实际可得定位。

### 8.2 结论与来源关系

| 结论类型 | 读者需要看到 | 展示限制 |
|---|---|---|
| 直接陈述 | 对应来源与准确引文 | 不改写原文后仍称为直接引文 |
| 跨来源综合 | 多个相关来源、综合结论与不确定性 | 不把来源数量直接当成确定性 |
| 推导或估计 | 输入、方法、假设与适用范围 | 明确是推导；遵守现有领域安全约束 |
| 暂缺依据 | 哪一部分没有可核查支持 | 不用生成的引用补齐外观 |

核对标记要解释它检查了什么。例如“引文与保存原文一致”不能写成“结论已证实”。来源存在、引文匹配、研究质量和临床适用性是不同问题。

AI 生成与人工修改的区别应在内容发生混合或需要追踪版本时可识别；整个对话已明确由 AI 回答时，不给每个段落重复贴 AI 标签。IBM Carbon 的可解释性入口值得借鉴，具体标识沿用 EviMed 的组件与颜色。[Carbon for AI](https://www.carbondesignsystem.com/building-blocks/foundations/carbon-for-ai)

### 8.3 医学证据呈现

研究类型、证据确定性、推荐价值、讨论热度、与我的相关性必须分别命名。RCT 标签不自动等于高确定性，多篇报道不自动等于多项独立研究。

如展示 GRADE 等级，应说明对应的人群、干预、比较和结局，以及评价依据；缺少评价时显示“未评估”，不由文章类型或 AI 推荐分推算。GRADE 关注特定结局的整体证据及其局限，不是给单篇资讯贴一个通用质量分。[Cochrane Handbook，第 14 章](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-14)

预印本、撤稿、更正、适应证或人群限制放在会影响判断的位置。实际临床安全发现不能默认折叠；一般解释不扩展成每页重复的泛化警告。

### 8.4 局部修改与版本

目标交互是选中对象 → 描述改动 → 查看影响范围 → 生成候选修改 → 比较并保留所需版本。简单可撤销改动可直接完成；大范围替换、改变数值或方法的修改需有差异可查。

人工修改过的内容不得被无声覆盖。来源版本变化时，保留原成果采用的依据，并提示新版本的具体影响。语句改写不得悄悄改变数字、单位、比较对象或不确定性。

局部重算、分支对比和差异合并属于需要能力支持的目标交互；未支持时保留旧结果并明确创建新版本，不出现虚假的“仅重算这一段”。AI Chains 的小规模用户研究支持探索可编辑中间结果，但不证明这会提高所有医学任务的正确性。[AI Chains，CHI 2022](https://arxiv.org/abs/2110.01691)

### 8.5 导出与传播

复制、下载、打印和分享应保留内容意义：标题、来源、图注、必要限制、版本与时间。复制表格保留单位与列名；单独导出图表保留图例和来源；导出失败不把空文件当作成功。

分享链接与下载权限分别判断。对象链接不得让无权限的人看到隐藏内容；手机也能阅读分享对象。报告打印沿用现有浅色打印副本，隐藏侧栏与工具栏，科学图像保留适合阅读的背景。

## 9. 组件与通用交互

### 9.1 组件契约

**现行约束：**复用现有 `components/ui`、布局组件和状态组件。交互控件具备默认、悬停、按下、键盘焦点、禁用和加载状态；存在校验的控件另有错误状态。列表页面具备加载、空、错误和内容四种状态。

| 组件或场景 | 目标行为 | 验收重点 |
|---|---|---|
| Button | 动词和对象明确；主要动作最突出 | 提交过程防重复；成功与失败都给出可见反馈 |
| IconButton | 图形、可访问名称和说明一致 | 键盘、触摸均可发现用途；不只依赖浏览器 title |
| Tabs | 切换同一对象的视图，保留父级范围 | 当前项明确，键盘操作符合组件模式；可分享视图进入 URL |
| FilterChips | 表示可叠加的条件或明确的单选集合 | 显示当前条件，支持清除；与普通标签在行为上区分 |
| SearchInput | 指明搜索范围，保留关键词 | 清除可用；过期请求不得覆盖最新结果 |
| Menu | 容纳次要动作，危险动作分组 | 键盘移动、Escape、关闭后焦点恢复完整 |
| Tooltip | 提供短说明或图标名称 | 不承载唯一的关键依据或长表单；触摸可获得等价信息 |
| Disclosure | 展开当前内容的补充信息 | 按钮和区域关系明确，展开状态可被辅助技术识别 |
| Drawer | 阅读相关对象或完成短编辑 | 适应窄屏；有标题、关闭入口和可预测的返回 |
| ConfirmDialog | 处理有后果的短决策 | 说明对象与后果；危险操作初始焦点在取消 |
| Toast | 确认短动作或提供撤销 | 重要错误同时留在上下文中，不依赖短暂提示 |
| DataTable | 比较同类记录与数值 | 单位、排序方向、选中范围、横向滚动和行详情清楚 |
| EmptyState | 说明当前为何没有内容并给下一步 | 与加载失败、未开放和筛选无结果分别设计 |

真正改变位置的导航使用链接；改变当前状态的动作使用按钮。卡片内有多个动作时，避免整张卡片的点击区域与内部按钮互相抢夺。键盘、复制链接和在新标签页打开应符合用户预期。

### 9.2 表单与校验

标签始终可见，placeholder 只提供格式或例子。必填项、单位、范围和默认值在操作前可知；错误贴近字段，并在提交失败时把焦点引向错误摘要或首个错误。

用户输入过的内容在校验失败、网络失败和意外关闭后应尽可能保留。自动保存必须区分正在保存、已保存与保存失败；没有持久化成功时不能提前显示“已保存”。同名、重复上传和版本覆盖应有明确处理。

专业数值字段不能把未知值自动转成零。涉及剂量、时间、金额和比例时，单位与数值绑定；更换单位按真实换算执行，不能只替换标签。

### 9.3 表格与批量操作

表头给出比较维度；数字右对齐并采用等宽数字；文本左对齐。排序标记不依靠颜色；缺失、零、不适用使用不同显示。

批量选择必须说明是“本页”还是“全部符合条件的记录”。筛选变化后，不能保留不可见选择却执行危险操作。行内操作按对象出现，批量工具栏只在已选择时显示。

超长字段提供可展开值，关键结论不依赖截断后的 tooltip。证据矩阵在手机上优先保留结论、来源入口和核查状态，其余字段可进入行详情。

### 9.4 空、慢、错与旧数据

| 真实情况 | 建议文案形式 | 下一步 |
|---|---|---|
| 首次使用，没有对象 | “还没有研究资料” | 上传资料 |
| 条件筛掉全部结果 | “没有符合这些条件的结果” | 清除筛选、修改条件 |
| 检索正常完成但未发现 | 说明检索范围内未发现 | 调整范围、保留该结论 |
| 暂时无法读取 | “暂时无法读取这份资料” | 重试、打开原文件 |
| 当前只有旧版本 | 显示内容与实际更新时间 | 重试更新；不冒充最新 |
| 只有部分来源可读 | 可读内容与缺失范围并存 | 查看已有结果、补充来源 |
| 对象已删除或链接失效 | 说明对象不可用 | 返回所属列表 |
| 没有访问权 | 说明无法访问 | 切换有权访问的范围或返回 |

加载布局应接近最终结构；已经显示的有效内容不因后台刷新变回整页骨架。错误提示中不出现原始堆栈、接口名、项目 ID 或未经翻译的服务端异常。

## 10. 视觉与排版

本节为现行设计系统的引用快照，基于 design-tokens 2.1.2。实施时直接使用语义令牌；源文件更新后以源文件为准，不从本表反向创建新的常量。

### 10.1 颜色与主题

品牌延续循证蓝，浅色 accent 为 `#0a5dc1`，深色使用其已定义角色值。提供浅色、深色与跟随系统；首次绘制前应用主题，避免闪白。AIHOT 的青色不进入 EviMed 品牌体系。

| 语义 | 应用 | 限制 |
|---|---|---|
| accent | 主要动作、链接、当前选择、对应核对标记 | 避免每个图标和卡片都染色 |
| accent-soft / strong | 当前选择背景与其上的文字 | 不用颜色透明度临时拼出新浅色 |
| text / text-2 / text-3 | 正文、次级说明、元信息 | 不以过淡灰色承载必要文字 |
| surface / surface-1 / surface-2 | 内容、分区、悬停与结构层次 | 不靠重阴影区分所有面板 |
| warn | 待核对、需要注意的限制 | 一般不确定性不升级为红色警报 |
| error / danger | 错误、破坏性操作、真实安全发现等 | 不用来表达低热度、低排名或低确定性 |
| ok | 操作成功、已结束等对应状态 | 不替代“证据已核实” |

每个状态同时通过形状、文字和颜色识别。深色主题重新使用语义角色，不对图片与整页应用反相滤镜；品牌按钮文字使用 accent-fg，不能硬编码白字。

### 10.2 字体与字号

界面使用现有无衬线字体栈；衬线仅由 wordmark、hero、doc-title 三个语义档位承担。每页最多四组字号与字重组合，中文层级优先使用 400 与 600。

| 用途 | 语义档位 | 当前尺寸 |
|---|---|---|
| 元信息与图注 | meta / caption | 12 px |
| 紧凑控件与表格 | compact | 13 px |
| 默认界面、列表、对话 | ui | 14 px / 22 px |
| 报告正文 | body | 16 px / 1.75 |
| 正文章节 | section | 18 px / 26 px |
| 数据页分区或预览标题 | heading | 20 px / 28 px |
| 页面标题 | title | 24 px / 32 px |
| 文档标题 | doc-title | 24 px / 34 px，衬线 |
| 数据页指标 | metric / metric-lg | 32 / 40 px |
| 首页唯一主标题 | hero | 40 px，现有品牌表达例外 |

尺寸在浏览器中使用 rem；不能通过禁用缩放来维持布局。32/40 的指标档位只用于数据页，不把列表计数放大成 KPI。中文不使用全大写转换或额外字距。

多行中文在 ui/body 下分别使用 measure 560 / measure-body 640 的行宽限制，目标不超过约 40 个汉字。标题可以换行，不能把药名、研究名称和关键比较截成无法辨认的半句。

### 10.3 空间与几何

| 项目 | 当前规则 |
|---|---|
| 基础间距 | 4、8、12、16、20、24、32、40、48、64 |
| 分组 | 组内通常 8；组间 16—24；章节间 32—48 |
| 页面与卡片 | 页面侧边距 24；卡片内边距 16；网格间距 12 |
| 阅读容器 | read 720，正文再遵守阅读行宽 |
| 列表容器 | page 1040 |
| 数据容器 | wide 1200；宽视口按现有规则可至 1280 |
| 侧栏 | 默认 280，收起 56；可调整行为沿用现有实现 |
| 圆角 | 标签 6；控件和行 8；卡片 12；面板/抽屉/对话框 16；输入组合区 24 |
| 控件高度 | 小型 28；默认 36；主要表单动作 44；标签 22 |
| 图标 | Lucide，16 / 20，统一 1.5 描边 |

同一工具栏的控件高度一致，标签不会伪装成按钮。静态卡片不投影；确实浮起的容器使用 e1，输入组合区、菜单、浮层和提示使用 e2，抽屉与对话框使用 e3。

### 10.4 动效与层级

沿用 fast 120 ms、base 200 ms、slow 320 ms 及统一进入/退出曲线。动效只解释状态变化、位置关系或操作反馈；不使用页面入场编舞、循环闪光、装饰性粒子或持续呼吸的品牌光晕。

减少动态效果模式取消移动距离，淡入淡出不超过 120 ms；图表库另行关闭动画。持续任务的状态仍然可见，不能因停动画而消失。

浮层使用现有层级令牌：页面、固定区、抽屉、对话框、浮层、提示、tooltip、跳转链接。遮挡问题通过正确的层级与 portal 解决，不不断增大 z-index。

### 10.5 品牌表达预算

每页最多一个品牌表达重点。阅读和操作页面依靠清楚的排版、准确的状态与细致的对齐体现品质；不为“AI 感”增加彩色卡片墙。

已有特殊表达沿用其明确场景，例如首页主标题、文档标题、会员卡，以及记忆胶囊符合历史长度条件时的单条增长线。不要把现有例外推广成每个列表都需要图表和大数字。

## 11. 数据与科学图表

### 11.1 每个数值的解释条件

关键数值应能确定指标含义、单位、分母或样本范围、时间窗口和更新时间。一个指标在概览、详情、导出与通知中的口径必须相同；若不同，应在名称或相邻说明中明确区别。

零、未知、不适用和计算失败分开表示。没有历史值时不显示 0% 变化；覆盖范围改变时不直接比较涨跌；历史缺口不连接成看似连续的趋势。

### 11.2 图表选择

| 用户问题 | 首选呈现 | 必须保留 |
|---|---|---|
| 两组差多少 | 对齐条形或差异表 | 单位、基准、样本范围 |
| 随时间如何变化 | 折线或时间序列 | 时间轴、采样间隔、缺失段 |
| 效果大小与不确定性 | 点估计与区间图 | 效应量类型、区间含义、参考线 |
| 各来源支持什么 | 证据表或按维度排列的矩阵 | 来源入口、冲突与空白 |
| 分布是否异常 | 分布图或分位摘要 | 样本量、缺失情况、处理方法 |
| 一段关系怎样发展 | 时间线 | 事件时间、来源、关系类型 |

图表标题描述它展示的内容或可由数据支持的结论，不将相关性写成因果。正文中的统计结果来自实际计算产物，不由前端或模型临时编造。

### 11.3 颜色与可访问性

品牌比较图沿用 EviMed 为品牌色、竞争对象为灰阶的规则，用户主动选定的对象可获得强调。科学分组使用已定义分类色板；不能将品牌竞争图的灰阶规则误用于需要区分治疗组的科研图。

证据确定性沿用单色阶，不使用红黄绿等级暗示安全。颜色不能独立承担组别识别；增加直接标签、线型、符号或数据表。图表提供键盘可达的等价数据，关键数值不只存在于 hover tooltip。

上传或引用的原始图片保持原比例、图例与坐标完整，支持放大和打开原图。不得为填满卡片而裁掉科学图表坐标、单位或重要注释。

## 12. 前沿动态、事件与简报

### 12.1 AIHOT 的借鉴边界

AIHOT 的公开产品说明和代码展示了事件聚合、后续进展、时间线与有限篇幅简报的组织方式。EviMed 采用其中减少重复阅读、保留来源和提供明确阅读终点的思路；医学任务的来源独立性、研究类型和证据确定性仍采用自身口径。[AIHOT 更新日志](https://aihot.news/changelog) · [AIHOT 源码快照](https://github.com/KKKKhazix/AIHOT/tree/07d4c775e71a2f1ec3205a0082a21b423cb09b6e)

| AIHOT 设计细节 | 对 EviMed 的价值 | EviMed 的具体要求 |
|---|---|---|
| 一个事件聚合多篇报道 | 减少重复阅读 | 区分报道数、独立来源数和独立研究数 |
| 最新进展独立于背景摘要 | 让读者识别新增内容 | 已读事件优先指出新增事实，不能只换一条标题 |
| 热榜分配不同视觉权重 | 加快扫读 | 完整榜单才展开重点，精选页使用紧凑摘要 |
| 简报有日期、版面与终点 | 支持有限时间阅读 | 归档、目录、阅读位置与真实空刊状态清楚 |
| 来源可继续追踪 | 支持核查 | 原文、摘要、保存来源的可用范围明确 |
| 理由帮助判断是否值得读 | 降低选择成本 | 按现行规则写入内容摘要，不新增“为什么入选”栏 |
| 推荐分与趋势 | 辅助排序 | 不映射为医学可信度或使用建议 |

### 12.2 模块层级

**现行结构：**动态、证据专区、简报、关注；动态内部有精选、热榜、全部、与你相关等视图。保留现有 URL、深链和视图恢复，不把所有层级同时渲染成多排同等显眼的大标签。

主导航说明所在功能，视图切换说明当前内容，筛选说明条件。移动端保留主导航与当前视图，把低频筛选收进同一面板；简报页不再显示与阅读无关的动态筛选。

### 12.3 动态列表

每条内容按标题或核心事实、必要摘要、来源与时间、主操作排列。标题应包含真正的变化和对象；摘要补充结果、范围或限制，不换句话重复标题。

**现行约束：**资讯标题打开原文；站内解读、事件详情和深入研究使用各自明确入口。不得把审查中“提高站内阅读便利”的建议实施为静默改变标题点击行为。

收藏、深入研究和更多操作在键盘与触摸下可达，不能只在 hover 时出现。热榜已有紧凑形态，改进重点是首屏占比和信息排序，不重新发明一块更大的热点墙。

一手来源使用可见文字或清晰标签，不能只靠小圆点和辅助技术文字。大量来源可以汇总为数量，再展开来源列表；机构头像不等于经过独立验证。

### 12.4 热榜与变化

热榜明确计算窗口、更新时间与排序含义。图线只能呈现真实保存的历史；不知道、采集不全或比较基准变化时显示对应状态，不能绘制补齐的平滑曲线。

“新上榜”只表示榜单状态变化，“热度上升”只表示在可比口径下的讨论变化。没有依据时，不使用“重大突破”“颠覆”“爆”等词替代事实判断。重要安全事件可以被优先提示，但理由应来自实际事件性质。

### 12.5 事件详情

建议顺序为：事件是什么 → 最新进展 → 关键来源 → 报道时间线 → 明确类型的关联事件。背景综述可以折叠，不应挤走最新变化。

同一药物、同一机构、同一 NCT 仅表示可能有关，不能单凭这一条件合并事件。试验初次结果、后续随访、指南更新和监管变更可能需要不同事件，通过关系连接。关系未知时写“相关”，不能强行写成“同事件”。

时间线标明采用发生时间还是发布时间；新旧排序可切换并保留选择。提供一手来源筛选作为目标迭代；支持打开原文、收藏事件和带上下文进入研究。

### 12.6 日报与周报

简报是有边界的阅读内容。默认呈现日期、当期要点与章节；归档用于找往期，目录用于跳转本期。桌面目录可在旁边，手机通过单一入口展开。

文章较长时，目录锚点、阅读位置恢复和“返回本期目录”优先于装饰性日历。阅读时长只能作为估计，不作硬承诺。日期控件明确哪些日期有刊物、哪些尚未出版；不可点击的日期不能伪装成链接。

**现行约束：**日报默认按北京时间 07:30 出刊，截取时点及内容窗口由现有服务规则决定；实际配置的时区与出刊时间应一致呈现。当天无满足条件内容时不制造刊物。界面必须区分“本期没有新内容”和“本期暂时无法生成或读取”，保留上一期时显示其真实日期。已刊内容后续发生撤稿或更正，按现有规则更新相关标识。

### 12.7 与你相关、关注与证据专区

与你相关以可理解的兴趣或研究主题分组，不在每张卡片重复推荐说明。推荐范围应可调整，支持减少此类内容；反馈到底改变当前筛选、长期偏好还是提交意见，要按真实能力说明。

关注对象分清主题、事件和来源。关注成功后可找到管理入口；取消关注不删除用户已收藏或已用于研究的内容。空状态提供可用的主题或检索入口，不把用户送回没有指导的空白页。

证据专区承担持续整理后的主题阅读。专区目录强调主题与内容范围；专区内区分原始研究、综述、指南和证据解读，不把所有材料统一称为“高质量证据”。解读页沿用第 8 节的来源与不确定性规范。

### 12.8 阅读详情与失效链接

站内摘要、可读取的文献摘要与原文必须清楚区分；没有全文时提供原文入口，不以重复元数据填满“详情”。翻译内容保留查看原文的路径；版权允许的展示范围按来源处理。

失效对象深链给出对象级错误与返回位置，不在整页列表上叠一条无法处理的报错。关闭详情后恢复原列表条件和阅读位置。

## 13. 知识库与数据理解

### 13.1 资料列表和预览

知识库首要任务是找到并使用材料。列表优先显示名称、类型、来源、更新时间和实际可用状态；不以解析工具名称、索引阶段或内部路径作为主信息。

点击资料进入预览，常用操作为打开原文件、用于研究与管理。选择一个资料时，列表与预览的选中状态一致；预览加载失败不让资料列表消失。

大批量资料可以按类型、来源和时间筛选；上传是主动作，删除和重新处理置于对象操作中。可用的原文件不因解析失败而无法下载。

### 13.2 摄入与覆盖范围

应区分上传完成、文字可读、表格可用、图像或页面尚未解析。系统没有读取到的部分必须说明，不把“文件存在”呈现为“已理解全文”。

资料发生更新时，保留原版本及引用关系；重新解析与重新上传不是同一个动作。引用已经生成的成果时，不无声替换其来源。

### 13.3 数据集语义

数据表旁提供变量名、含义、单位、分组、缺失值约定和来源。每项解释区分研究者确认、字典说明与模型推断；更弱的依据不能覆盖更强的依据，这是现有数据语义契约。

需要研究者确认的内容就地可改；已确认字段不在每次分析前重复询问。发现重复观测、连接关系变化、分母不一致或时间泄漏等问题时，定位到相关对象和影响，不只显示一个“数据质量分”。

为分析传入资料时显示具体版本和用途；不因选中了整个文件夹就默认为所有资料都与任务有关。

## 14. 记忆与持续委托

### 14.1 记忆胶囊

记忆页面首先展示用户可以理解的内容：研究背景、偏好、已采用做法和项目事实。原始资料进入知识库，可复用的理解进入记忆；同一来源可以支持记忆，但两者的删除与更新语义应清楚。

每项记忆能查到来源、适用范围、有效时间及修订情况。冲突、过期、已被替代和来源撤回分别呈现；不将所有历史记忆都表现为当前事实。

编辑、停用和恢复应可找回。用户应能知道后续任务会使用哪些范围的记忆；不在每条消息旁堆记忆命中数。导入胶囊前说明内容与目标范围，胶囊本身不授予任何执行权限。

### 14.2 定时任务

创建持续委托时，用户应能确定研究目标、资料或主题范围、触发时间与时区、预算、停止条件和通知方式。表单首先让用户写要持续完成的工作，再配置必要约束。

任务列表显示下一次执行、最近一次真实结果与是否启用；详情优先展示结果历史，再展示配置和执行记录。暂停日程只影响未来触发，是否同时取消当前运行必须按实际功能明确区分。

一次执行没有新证据、一次执行失败、一次执行产生了结果，是三个不同状态。旧结果继续可读；失败提供具体恢复入口。通知直接到达本次结果，不能只返回任务首页。

### 14.3 主动性与打扰

默认由用户配置持续工作的范围。新增发现优先汇总，只有实际需要及时处理的变化才单独提醒；普通刷新不产生新通知。

取消订阅、减少此类内容、暂停委托和关闭渠道互不混淆。设置页修改通知方式后保留研究任务本身，不误删任务。平台应解释用户能控制的范围，不展示后台轮询频率等无关细节。

## 15. 科研工具与专业模块

### 15.1 科研工具目录

每项工具说明它能交付什么、需要什么输入，以及已知的时间或额度信息。名称使用研究者熟悉的任务，例如证据综合、统计分析，而不是内部路由或技能包名。

工具目录提供按研究任务查找的方式，能力地图作为辅助探索，不取代可直接使用的列表。点击工具应带入相应任务起点；已上传材料和已选项目不能丢失。

**现行约束：**内部能力不进入公开目录；仅从专业模块使用的能力不额外铺入通用工具页。NCBI GEO 的基因表达分析与“循证 GEO”分开命名与解释，避免缩写造成误入。

### 15.2 虚拟临研

首页围绕研究对象：研究名称、当前阶段、可用成果、最近变化和继续操作。研究详情保留既有阶段结构，但默认显示当前阶段的实际内容，不让七阶段流程占据整页第一屏。

完成状态必须对应可打开的材料或结果；尚无结果时不能显示“研究完成”。分析失败但已有方案与证据时，仍能查看这些内容。概览、分阶段页面和通知中的状态来自同一口径。

分析计划的冻结、数据封存、数据访问及小样本抑制遵守既有业务规则。前端在操作发生处说明影响；不新增与真实契约无关的审批链。隐藏受限数据时，解释当前可看到的范围，不显示误导性的零值。

模拟值与观察数据、模型推断与计算引擎输出、匹配未知与不匹配必须区分。任何统计图表均能回到对应分析结果及其参数；患者级资料不进入普通对话附件或任意生成式视图。

### 15.3 循证 GEO

概览围绕测量对象、时间窗口、引擎与问题样本显示关键结果。指标卡必须能够进入相同口径的明细，保留样本数、覆盖情况、失败请求和未知值的区分。

AI 答案详情保留回答时点与保存快照；后续重新测量产生新快照，不覆盖历史。曝光、提及、引用与其他域内指标按已有定义命名，不能在不同页面借用同一个“得分”显示不同量。

策略、内容、投放或订单等操作放在相应项目内。涉及预算的操作显示当前金额、已占用部分与执行后果；研究建议不自动等于发布指令。支付、退款和失败记录分别呈现，不以乐观动画提前宣布成功。

### 15.4 插件与技能

目录区分发现、已安装和当前项目配置；状态使用“可用”“安装中”“需要处理”等用户语言。说明扩展提供的能力及真实权限范围，避免让用户阅读依赖树才能决定是否安装。

更新、停用、回退和安装失败应可理解。当前运行采用的版本不因用户浏览目录而变化；扩展不可用时只说明受影响能力。现行资格或兼容标识不是隐藏所有已安装扩展的理由。

## 16. 通知、设置与边界页面

### 16.1 收件箱

一条通知必须回答发生了什么、涉及哪个对象、何时发生、打开后能做什么。优先显示结果、重要变化和需要处理的事项；不把每个内部步骤都推入收件箱。

同一对象的重复通知应合理归并，但不能吞掉后续安全变化。已读与已处理分开：打开通知不代表已完成建议动作。按钮指向具体成果、事件或任务，而不是不相关的首页。

### 16.2 设置

沿用账户、外观、通知、用量/科研额度、数据源、项目及有权限时的运维分区。个人偏好、项目设置和管理员配置明确范围；不得把项目级操作放在看似全局的开关后。

额度展示说明可用、占用和已消耗的真实含义；普通任务区不显示 token 或 tok/s。涉及费用的可理解信息放在额度和交易页面，技术诊断信息留在受控诊断入口。

保存即时生效还是需要应用，应由控件行为清楚表达。主题切换即时预览且可恢复；通知测试与真实研究通知区分；数据源未连接时只影响相关能力，不制造全平台不可用的印象。

### 16.3 登录、首次使用与回访

登录页聚焦账户操作，提供可理解的失败原因和恢复方式，允许密码管理器与粘贴。登录后返回先前请求的有效对象，不能总是丢到空白首页。

首次使用优先让用户提问、上传材料或打开一个实际可用的任务入口；专业背景、兴趣和持续委托配置可在有需要时补充。演示内容必须标识为示例，不混入用户的研究结果或用量。

回访优先恢复上次工作和未读成果。不要每次进入都重新展示引导遮罩。用户能跳过引导，也能从稳定位置再次查看帮助。

### 16.4 404、无权限、服务错误与模拟页面

不存在页面提供返回工作区；不存在对象提供返回所属列表；无权限页面说明无法访问并保留可用导航；服务错误保留已加载内容及合适的重试动作。模块关闭与网络故障不能使用相同文案。

现有模拟充值、模拟会员、模拟订单和模拟退款页面始终清楚标识模拟性质。订单状态只能来自真实交易契约，模拟结果不得呈现为实际付款或退款。

## 17. 前沿交互与生成式界面

### 17.1 稳定框架中的适应性

生成式界面属于探索项。建议先让 AI 根据任务选择已有的呈现组件，例如比较表、证据矩阵、变量编辑器或时间线；导航、项目范围、来源入口、错误处理和权限保持稳定。

生成式界面研究显示，特定任务中的用户会偏好更可交互的呈现；这些结果不等于医学正确性、可访问性或性能已经得到保证。因此 EviMed 先在边界清楚的结果视图中验证，再决定是否扩大。[Generative Interfaces for Language Models，Findings ACL 2026](https://aclanthology.org/2026.findings-acl.74/)

### 17.2 建议探索的六个方向

| 方向 | 用户价值 | 最小形态 | 必要依赖 | 验证重点 |
|---|---|---|---|---|
| 新证据变化摘要 | 快速知道已读主题发生了什么 | “新增、改变、仍未知”三类变化及来源 | 对象版本、事实差异与事件关系 | 是否减少重复阅读，是否误报变化 |
| 结论旁的上下文操作 | 在阅读时继续核查和研究 | 选中结论后查看依据、找反证、比较 | 结论锚点、来源范围、明确任务草稿 | 是否提高核查成功率和减少上下文重填 |
| 可编辑中间结果 | 修正局部理解后继续 | 修改问题范围、变量映射或筛选条件 | 版本化中间产物、影响范围与重算支持 | 是否减少无效重做，同时保持结果一致 |
| 基于保存版本的分支比较 | 比较不同研究假设 | 从同一材料版本生成两个可对照结果 | 分支来源、相同基线、计算产物 | 是否能解释差异来自哪些假设 |
| 可恢复的研究工作区 | 回访后立即继续 | 固定当前报告、材料和阅读位置 | 持久化对象与项目隔离 | 跨会话找回时间、恢复成功率 |
| 有边界的个性化简报 | 只关注与工作有关的变化 | 主题订阅、有限篇幅、明确结束 | 兴趣控制、来源覆盖、去重与时间规则 | 有用内容比例和打扰率 |

这些方向可以分批试验，不要求一次上线。“找反证”等动作仍应先形成可见研究草稿或沿用已有委托范围，不因选中文字就自动开启高成本任务。

### 17.3 生成式组件的契约

生成内容选择组件类型、数据绑定和必要说明；应用负责组件渲染、权限、状态及动作执行。字段至少覆盖对象类型、数据来源及版本、单位、缺失状态、允许操作和静态回退。

生成结果不携带任意执行代码，不自行拼接敏感数据请求，不通过一个看似无害的控件扩大权限。数值来自保存数据或确定性计算结果；未知值保持未知，不为了补全图表生成数据。

界面生成失败时回退为可读表格或正文，仍可查看来源与导出。保存成果时应能恢复其数据和呈现版本，避免同一份已分享报告每次打开都随机换布局。

### 17.4 人机协作的验证边界

需要纠错时提供低成本介入点，例如改材料、改假设、停任务、比较结果，而不是为每个动作增加确认。Magentic-UI 将共同规划和可介入操作作为研究方向，但它是研究系统，不能证明 EviMed 已有相同恢复能力。[Magentic-UI，2025](https://arxiv.org/abs/2507.22358)

认知干预研究提示，某些强制思考机制能减少过度依赖，但可能增加负担、降低偏好。人机协作的元分析也表明，组合不必然超过较强的一方。EviMed 应同时测量错误识别、任务结果和操作成本，不能以“用户点击了确认”代替质量评估。[To Trust or to Think，2021](https://arxiv.org/abs/2102.09692) · [When combinations of humans and AI are useful，2024](https://www.nature.com/articles/s41562-024-02024-1)

## 18. 前端实现与内容规则

### 18.1 工程边界

**现行约束：**浏览器通过应用服务端访问研究能力；领域对象、状态与错误口径来自现有共享契约；设计值来自令牌包。界面不能直接连接研究内核或复制一套领域判定。

| 层次 | 承担内容 | 不承担内容 |
|---|---|---|
| 设计令牌 | 颜色、排版、空间、动效、层级与主题 | 页面专用的临时样式集合 |
| UI 原语 | 控件语义、焦点、基本状态与交互 | 医学结论和权限判断 |
| 页面模板 | 对齐、容器、导航与响应式结构 | 每个模块再造一套按钮 |
| 业务组件 | 事件、证据、研究结果等对象呈现 | 靠解析文案反推业务状态 |
| 数据契约 | 对象范围、版本、状态、来源与可用操作 | 由前端臆测的完成状态 |

### 18.2 状态数据要求

设计稿涉及的每个状态都应对应实际数据。需要的新字段先扩展现有领域契约，避免只在一个页面维护状态推断。

| 设计需要 | 契约需要表达 | 前端禁止补猜 |
|---|---|---|
| 可读成果入口 | 已存在的成果及其可访问地址 | 根据任务结束就猜测文件名 |
| 更新时间 | 数据实际更新或测量时间 | 用页面加载时间替代 |
| 完整与部分 | 已取得范围、缺项和原因 | 把接口成功视为内容完整 |
| 可继续或可重试 | 实际支持的操作与作用范围 | 同一个按钮处理全部失败 |
| 来源核查 | 检查对象、检查结果、保存来源 | 用 AI 自评分替代核查 |
| 跨页恢复 | 对象、版本、视图与必要位置 | 通过列表序号定位可能已变化的对象 |

### 18.3 数据请求与渲染

项目、查询、对象或版本变化时，取消或忽略过期请求。流式事件按真实顺序与标识合并，重连不能重复追加结果。避免频繁重建整段长正文，导致选择丢失、焦点跳动或滚动位置漂移。

非关键区域失败时，保留其余可用区域；页面级错误边界保留全局壳与导航。大表格和长列表按需要分页或虚拟化，实施时保留键盘访问、屏幕阅读和定位能力。

长文本、链接、图像和数学内容按真实类型渲染。外部 Markdown/HTML 的呈现遵循现有安全处理，不能使来源内容成为页面指令或执行脚本。链接名称说明目的；外部打开行为明确。

### 18.4 文案与本地化

基线语言为简体中文，按钮使用具体动作，状态使用用户可理解的结果。内部 API、枚举、模型 ID、运行路径和原始错误串不进入普通正文；技术标识只在确实需要核对的领域位置显示，如 DOI、PMID、NCT。

| 应避免 | 建议表达 | 条件 |
|---|---|---|
| “系统正在执行智能推理链” | “正在比较所选研究” | 该动作确实正在发生 |
| “任务已交付” | “打开报告” | 已有可读报告 |
| “核对 37 条” | 在对应结论处显示核对结果 | 用户需要判断具体依据 |
| “暂无数据” | “没有符合这些条件的结果” | 确为筛选无结果 |
| “未知错误” | “连接中断，已保存的内容仍可查看” | 已确认保存内容可读 |
| “AI 可信度 92 分” | 展示具体来源与待核对项 | 没有经过校准的概率含义时 |

界面自行撰写的中英文和数字之间遵循现有空格规范；引用原文与 AI 生成正文不做会改变内容的批量替换。时间显示区分发生、发布、测量与更新；定时任务始终注明使用的时区。格式化数字保留必要精度，不为整齐而隐藏有意义的差异。

### 18.5 帮助信息的放置

不增加解释系统机制的页面副标题、重复提示或“为什么入选”模块。帮助信息应在真实决策处出现：字段单位、删除后果、缺失材料、指标口径、来源局限和权限范围。

常规路径通过好名称和结构即可完成；少见操作可以使用就地帮助。临床限制、错误恢复或收费后果不能因页面追求简洁而被移到无法发现的位置。

## 19. 无障碍与性能目标

### 19.1 无障碍基线

目标为 WCAG 2.2 AA，并沿用现有更高对比度、强制颜色和减少动态效果支持。以下是优先核查项目，不是完整合规认证清单。

| 项目 | 要求 |
|---|---|
| 文字对比度 | 普通文字至少 4.5:1；符合标准定义的大字至少 3:1 |
| 非文字对比度 | 识别控件与必要图形的信息至少 3:1，按标准例外处理 |
| 焦点 | 可见且不被固定层完全遮挡；不只依赖 box-shadow |
| 点击目标 | AA 的最小目标按 24 × 24 CSS px 或相应间距/例外规则核查 |
| 触摸舒适度 | 主要触摸操作以 44 × 44 的点击区域为产品目标，不将其误称为 AA 的统一要求 |
| 重排与放大 | 普通内容在等效 320 CSS px 下可重排；文字放大至 200% 仍可使用；宽数据表按必要的二维内容处理 |
| 输入 | 有标签、错误关联、可纠正路径；不能仅凭颜色提示 |
| 操作 | 键盘可完成关键路径；拖动有非拖动替代；隐藏层不接收焦点 |

标准依据：[WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)、[目标尺寸最小要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[重排要求](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

每页提供跳到主要内容；标题与区域关系正确；图标按钮有名称；对话框有标题并管理焦点。动态状态使用适当的 live region，但不能逐字朗读整段流式回答。科学图表有解释和等价数据，图片替代文本说明其作用。

### 19.2 性能目标

以真实用户数据的第 75 百分位分别评估桌面和手机：LCP 不高于 2.5 秒，INP 不高于 200 毫秒，CLS 不高于 0.1。这是拟采用的页面性能目标，不能由单次 Lighthouse 分数或一次快速网络测试宣称已达成。[Web Vitals](https://web.dev/articles/vitals)

AI 任务时延另行记录：提交到服务端确认、首次可用内容、首份可读成果、最终结束和恢复耗时。必须同时记录失败与取消，避免只统计成功任务而美化体验。

### 19.3 感知性能

导航、菜单与本地筛选应立即反馈；长请求保留当前内容并显示真实状态。图片区预留比例，列表刷新不跳动；不为延迟显得自然而人为等待。

登录、导航与基础阅读不应被重型图表、编辑器或可视化依赖拖住。按路由和交互需要加载资源；报告中的大图按需加载，但首屏关键内容优先。长任务运行时仍可阅读、复制和导航。

## 20. 设计交付与验收

### 20.1 每项设计应交付什么

一个页面或功能的设计交付包括：用户任务与成功条件、入口和返回位置、对象与项目范围、主次操作、数据与状态来源、桌面与手机布局、空错慢状态、键盘路径，以及可复现的验收案例。

已有组件足够时不再发明变体。确需新增组件时，先说明与现有组件的区别和跨页用途，补齐主题、状态与可访问性，再接入页面。视觉调整附变更前后截图，组件变化同时更新浅色和深色基准。

### 20.2 页面覆盖矩阵

| 页面组 | 必须覆盖的状态或对象 |
|---|---|
| 导航与项目 | 展开/收起、同名项目、项目切换失败、旧深链、跨项目对象 |
| 对话与任务 | 新输入、历史读取、运行中、断连、部分结果、完成、取消、失败恢复 |
| 前沿动态 | 精选、热榜、搜索无结果、与你相关、关注空态、事件有效/失效、简报有刊/无刊/失败 |
| 证据专区 | 目录、有内容主题、空主题、解读、来源不可用 |
| 知识库 | 上传、重复资料、部分解析、预览失败、长文件名、大表、变量含义修正 |
| 成果阅读 | 长报告、依据浮层、来源缺失、引文待核对、导出、打印、局部修改版本 |
| 记忆与定时任务 | 空态、冲突/过期、编辑失败、计划启停、执行历史、无新发现和失败的区别 |
| 科研工具与扩展 | 能力选择、输入不足、安装中、不可用、项目配置、权限差异 |
| 虚拟临研与 GEO | 有效对象、无效对象、可读结果、指标口径、阶段失败、数据受限、窄屏 |
| 通知与设置 | 通知深链、保存失败、额度限制、主题、时区、数据源不可用 |
| 边界页面 | 登录失败、404、无权限、模块未开放、服务错误、模拟交易 |

不要求机械生成所有维度的笛卡尔积。用具有代表性的真实或明确标记的固定测试数据覆盖关键组合；缺少有效业务实例的详情页必须记录覆盖缺口，不能以无效 ID 页面代替正常流程验收。

### 20.3 跨页面验收案例

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A01 | 从事件发起深入研究 | 原事件、来源、项目和草稿保留；明确提交前不运行 |
| A02 | 阅读报告并查看某条依据 | 定位到对应来源；关闭后回到原结论与阅读位置 |
| A03 | 任务运行时刷新或离开再返回 | 不重复提交；状态可重新读取；已有成果仍可访问 |
| A04 | 任务断连后执行恢复动作 | 区分连接失败与任务失败；按钮作用与名称一致 |
| A05 | 有成果但部分检查未通过 | 成果可读；真实问题就近显示；不整体扣留 |
| A06 | 切换项目且旧请求稍后返回 | 新项目不显示旧项目的数据、草稿或错误 |
| A07 | 手机关闭侧栏后连续 Tab | 焦点只到可见交互；重新打开和关闭可预测 |
| A08 | 在长列表打开对象，再返回 | 筛选、排序、位置与原对象可找回 |
| A09 | 表格横向滚动或查看行详情 | 关键标识、单位、来源和状态可访问；整页不横向溢出 |
| A10 | 更新来源或修改报告局部内容 | 旧版本保留；影响范围明确；人工改动不被静默覆盖 |
| A11 | 简报当天没有内容或更新失败 | 两种情况不混淆；显示真实日期与可读往期 |
| A12 | 同一 GEO 指标在概览与详情查看 | 数值、分母、时间与样本口径可对应 |
| A13 | 虚拟临研显示阶段完成 | 有对应成果入口；没有结果时状态不冒充完成 |
| A14 | 切换深色、放大文字、减少动态效果 | 内容与操作不丢失；焦点和图表可读 |
| A15 | 生成式视图渲染失败 | 回退内容可读，来源、版本与操作权限不丢失 |
| A16 | 对象删除、权限撤回或模块关闭后打开旧链接 | 给出具体原因和有效返回；不泄露原内容 |

### 20.4 视口与数据样本

核心流程至少覆盖 1440 × 900 桌面、768 × 1024 平板和 390 × 844 手机；普通内容补充等效 320 CSS px 重排检查。浅色与深色均检查，系统主题切换至少验证一次。

数据样本包括：空、单条、正常量、足以触发分页或虚拟化的大量内容；超长名称、中文和英文混排、缺失值、真实零值、撤回来源、损坏链接。长报告检查目录、图表、引用、打印与返回位置。

### 20.5 检查方式

- 交互检查验证任务完成、恢复、版本和权限范围，不能只比较截图。
- 视觉检查在同一构建、视口、字体与主题条件下记录，注明页面、状态与数据样本。
- 自动化用于稳定且重要的行为、语义与数据契约；低影响文案调整不新增只镜像实现的测试。
- 性能用真实用户指标与针对性实验检查；无障碍自动检测结合键盘和辅助技术抽查。
- 完成一轮集中检查后批量修复，再做一轮针对性确认；发现新的实质问题才扩大检查。

### 20.6 设计有效性的衡量

| 目标 | 优先指标 | 防止误判的补充 |
|---|---|---|
| 更快开始有效工作 | 从入口到首次有用操作的时间、上下文重填次数 | 任务是否选错、是否误启动 |
| 更容易理解结果 | 正确解释结果和限制的比例 | 不能只问“看起来是否专业” |
| 更容易核查 | 找到匹配原文的成功率和耗时 | 区分打开引用与真的找到支持 |
| 更容易恢复 | 恢复成功率、丢失内容比例、重复任务率 | 同时检查额外费用和版本混乱 |
| 简报更有用 | 有效阅读后的相关内容识别与后续使用 | 不以停留时长或点击总量单独判定 |
| AI 协作更有效 | 成果质量、发现错误能力与总操作成本 | 与现有流程比较，保留失败样本 |

上线前记录同类任务的基线，设定产品目标并说明样本与评估方法。本文不虚构改版后能够提升的百分比。

## 21. 迭代次序

### 21.1 先处理可信与可恢复

先复核线上审查中涉及核心研究入口、状态与成果不一致、指标口径和隐藏焦点的问题。若仍可复现，优先修复；解决后保留对应验收案例，而不在新规范里永久认定某模块不可用。

| 次序 | 交付范围 | 依赖 | 完成判断 |
|---|---|---|---|
| 第一批 | 历史与成果可读、错误恢复、状态一致、项目切换隔离、移动端焦点 | 真实运行与成果契约 | A03—A07、A12—A13、A16 通过 |
| 第二批 | 页面首屏、导航与筛选层级、简报目录、来源标签、表格窄屏 | 现有组件与内容数据 | 代表页面达到首屏与阅读验收，A02、A08—A09、A11 通过 |
| 第三批 | 上下文交接、局部版本、来源变化、可编辑数据含义 | 对象版本与影响范围 | A01、A10 通过，旧成果可复现 |
| 第四批 | 变化摘要、分支比较、受控生成式视图和个性化简报 | 前三批的稳定对象与状态 | 同任务对照显示实际价值，A15 通过 |

每批应选择一条完整工作路径交付，例如“事件 → 研究 → 报告 → 依据 → 回到事件”，而不是一次只改所有页面的按钮颜色。

### 21.2 需要明确产品决策的变化

本规范直接延续现有视觉与入口约定。若未来需要更换品牌、改写全局导航顺序、改变标题打开原文的行为、引入全局命令面板、扩大持续任务权限或让 AI 自行生成执行型界面，应作为独立设计决策，说明受影响路径和替代方案。

局部布局、间距、列表密度、错误文案和组件一致性可以在现行约束内改进。设计令牌、领域口径与跨模块状态改变时，同步更新权威定义及消费者，不让本文成为第二份实现事实源。
