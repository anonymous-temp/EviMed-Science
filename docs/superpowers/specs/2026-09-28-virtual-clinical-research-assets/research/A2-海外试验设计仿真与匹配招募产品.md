## 1. 结论先行

1. **虚拟试验应交付「设计空间」，而不是逐个跑情景。** Cytel 的 Solara（2020-10 发布，2024 年与 East 合并更名 East Horizon）一次生成「数万个试验模型、数千个参数变体」，数据表公开了它的五种视图：设计 × 情景热图（颜色表示稳健性评分）、散点图（帕累托设计以绿色圆环标出）、收藏设计箱线图、雷达图（在同一情景下比较功效、成本、平均时长、平均样本量、首次期中分析时间）、各情景里程碑时间线；另有「最优设计推荐」——由申办方先选优先级，平台据此生成评分函数 [1][4][7]（见图 01、02）。Berry FACTS 同样以「情景网格 + 设计比较」为主流程 [10]。**方案改动：** §9 增加「设计网格」对象和上述五种视图；排序前必须先保存一个带版本号的「选择目标」对象（约束 + 权重，且必须包含零效应情景），排序对象只能是设计，不能是效应假设。这与 §9.3「不自动挑选最有利结果」一致，同时吸收了 Cytel 的评分函数做法。
2. **入组和事件里程碑要给出概率，而且实际数据进来后要重算。** Cytel Enforesys（2015 年起）用 Monte Carlo 给出「按期达到里程碑的概率」，并提供激进 / 平衡 / 保守三档风险偏好；2026-07-31 起通过 Enforesys 4.0 接入 Citeline 的历史中心数据 [8][9]。Lokavant Spectrum 主打开研前建模加研究期间持续重算，2025-09-15 被执行平台 ProofPilot 收购 [40][41]。nQuery 最高档（Expert）的卖点正是入组与事件里程碑预测 [12]。经典统计模型是 Poisson-Gamma（Anisimov & Fedorov, 2007）[42]。**方案改动：** §9.2「招募运营」家族的默认输出改为：末例入组日期分布、指定日期达标概率、分位数扇形图；时间-事件终点另外输出「达到目标事件数的时间」分布（这决定读出时间）。风险档位只是承诺哪个分位数。真实入组事件一到就触发重算，旧预测按 AC-23 保留时间戳，用于校准。
3. **方案应当是结构化对象，负担和成本由确定性代码算出。** Medidata Protocol Optimization（2025-05-29 发布）接收方案草稿、SoA 或 USDM 数字化方案，输出患者负担指数（覆盖约 5,000 种操作，按疼痛、有创性、有害暴露、时长、焦虑打分）、中心负担、成本、复杂度、入组与修订风险，并与相似历史研究对标；它称数据来自 38,000+ 个试验、1,200 万患者 [21][22]。Faro 提供可实时量化负担、成本和复杂度的设计器，可经 API 或 USDM JSON 对接下游，几分钟生成中心预算 [24]；它与 Merck 合作的 SoA 精简方法已在同行评议期刊发表 [25]。**方案改动：** §5.3 结构化方案增加 SoA 矩阵（访视 × 操作）和操作概念库（时长、有创等级、采血量、禁食、影像、参考成本）；负担指标以 `calculated` 来源存储；USDM JSON 导出列入 V1.x。
4. **V1 先例库只靠公开注册数据就能起步，但要老实标出注册数据缺什么。** 我们直接调用 ClinicalTrials.gov API v2 核对了 NCT04368728：记录里有入组人数及 ACTUAL/ESTIMATED 标记；开始、主要完成、完成日期都带类型；有资格标准原文、年龄、性别；中心列表（该试验 175 个，含经纬度）；结果模块包含受试者流、基线、结局和不良事件 [36]。AACT 每天全量同步，拆成 40 多张关系表 [37]。**注册数据里没有筛选失败率、每中心入组数和中心启动日期**。**方案改动：** §5.4 的 V1 数据源确定为 CT.gov v2 + AACT + WHO ICTRP（含 ChiCTR）+ EU CTIS，国内药物临床试验登记平台另行接入。「每中心每月入组」这类派生值标为粗算的 `calculated`；估计值（ESTIMATED）不得进入历史基准；缺失字段显示为「来源未提供」，不当作 0。
5. **匹配结果按 TrialGPT 的「逐条标准三元组」保存，资格判定和临床优先级分开。** TrialGPT 对每条标准输出解释、病历中相关句子的编号和资格标签。纳入标准的标签是：满足 / 不满足 / 信息不足 / 不适用；排除标准的标签是：符合排除 / 不符合排除 / 信息不足 / 不适用 [43]。错误分析显示，常见错误之一就是把「信息不足」和「不适用」混为一谈 [43]。TrialGPT 2.0（2026-09-01 arXiv）进一步按患者的临床需要和工作流优先级排序，并做了 6 个月的前瞻性肿瘤 MDT 部署 [45]。**方案改动：** §11.1 的每条标准评估记录为：「适用性（适用 / 不适用 + 理由）」+「状态（满足 / 不满足 / 未知 / 待定）」+ 证据定位 + 解释 + 模型身份。「不适用」只作为适用性字段，不作为第五种状态。排序拆成两个字段：确定性的资格汇总和模型给出的临床优先级，后者标注「不是获益概率」。
6. **匹配精度的公开证据远弱于营销口径，验收必须用我们自己的裁定集。** TrialGPT 在 1,015 个患者-标准对上的准确率为 87.3%，专家为 88.7%–90.0%；但其用的是 183 个合成患者，「节省 42.6% 时间」来自 6 个试验 × 6 个半合成病例、2 名专家的试点 [43]。Triomics 在真实 EHR 上的 PRISM 研究中，逐条标准准确率 OncoLLM 为 63%，GPT-4 为 68%，而医生之间的一致率只有 64%–70% [53]；合作机构介绍页引用的「约 95%」，实际是复核后「前 3 名中含合格试验」的试验级指标，并不是逐条判定的准确率 [53][54]。Massive Bio 在 3,804 例前瞻性病例中报告 F1 0.82，每位患者的匹配时间从约 120 分钟降到约 30 分钟 [55]。**方案改动：** §19 匹配验收采用合作方真实病例、双医生独立裁定，并以医生间一致率作为可达上限；分别报告各标签混淆、未知率和错误排除率；节省时间用「有/无工具」交叉设计测量。不设统一准确率门槛，与 §19.1 一致。
7. **「试验→患者」方向应当呈现逐条标准的漏斗计数，中心能力做成可核查的档案。** TriNetX LIVE 用条件构建器实时给出总体和分中心的患者数 [51]；Deep 6 AI（2025-03-11 被 Tempus 收购，SEC 披露对价 1,740 万美元）挖掘结构化与非结构化 EHR 找人 [49]；Inato 的中心卡片列出可及患者区间、PI 在该适应症的试验经验、多样性比例、「要求满足率」以及「稳定入组」「响应快」等标签 [59]（见图 05）。**方案改动：** 虚拟队列的入排流程图（§6.3）和试验→患者匹配共用一个「标准漏斗」组件，未知人数单独一列。§11.2 的中心档案增加「方案要求满足率」（用中心能力逐项对照方案要求，确定性计算），以及只能由我方转诊台账计算的响应时长和转化率；每个标签都要显示分母。
8. **招募模块 V1 只做「转诊台账 + 预筛问卷 + 材料草稿」，不做面向患者的市场或广告投放。** 海外招募已分成三类：一是中心网络（Inato 6,000+ 个中心，对中心免费 [59]；Tempus TIME 先匹配患者再启动中心，有案例约两周完成启动、30 天内首例入组 [50]）；二是面向患者的平台（Antidote、Carebox、TrialX；SubjectWell 已并入 Clariness，原域名直接跳转 [56][57][58][60]）；三是 AI 材料生成（Formation Muse [63]）。招募服务商常按结果里程碑计费，例如 1nHealth 按签署知情同意或随机化收费 [61]。**方案改动：** §11.2 从结构化标准自动生成预筛问卷，每道题回链到标准编号，答案以「患者自述」来源进入证据；招募材料按人群和渠道出多个草稿版本，审批前不发布。消费者端市场、投放和 EHR 实时接入不进 V1。
9. **每个 AI 结果都要能复现、能缓存、不被悄悄改写。** Paradigm 的 Matcha（2026-08-06 公开）用参数、模型设置、提示词和输出模式生成确定性的「算法键」，只有显式声明兼容的旧版本才能复用；证据链接到文档 ID 和字符偏移；失败记成结构化错误、不写进缓存；先写输出再记完成；模型负责评估，工作流往哪走由确定性代码决定 [48]。Formation 的 Delphi 在试验结果揭晓前把预测写成不可改的带时间戳记录，有新证据就另起一个版本 [19]。**方案改动：** §15.3 的缓存键在方案原文基础上写明为：患者快照哈希 + 方案版本 + 标准规范化版本 + 模型 ID + 提示词/输出模式版本 + 截至时间；证据指针统一为「来源文档 ID + 字符起止」。入组预测、设计推荐与匹配评估都进入同一个预测登记表。
10. **商业模式：研究端按组织订阅 + 算力额度 + 付费验证文档包；运营端按活跃方案计费，不按人数计费。** 公开价格锚点：nQuery 企业版每用户每年 995–7,795 美元 [12]；PASS 一年订阅 1,195 美元，永久许可 4,995 美元 [13]；FACTS 提供 3 个月免费评估许可 [10]；rpact 本身开源免费（LGPL-3），正式验证文档和支持需付费购买 [14]；情报数据按企业订阅收费；招募服务按结果收费 [61]。**方案改动：** §20.3 增加两项：一是给每个统计方法包出售「验证文档包」（学 rpact 的做法）；二是提供限时限算力、功能完整的评估许可。匹配与招募按「活跃方案 × 月」计费，不按生成患者数、候选数或转诊数计价，避免与「生成记录不是证据」冲突。

## 2. 逐家分析

### 2.1 设计与仿真

**Cytel Solara → East Horizon（Explore / Design）**
- 对应：虚拟试验（统计设计、运营时长）；报告与决策。
- 做什么：2020-10-06 发布 Solara，称数分钟内生成「数万个试验模型、数千个设计变体」，针对治疗效应、入组速度等数十种不确定性做压力测试 [1]；2021-03-28 全面开放，同时提供 SaaS 和面向无统计团队的生物技术公司的咨询服务 [2]；2023-02-07 与 GSK 签三年协议，称前 20 大药企中已有 300+ 用户 [3]。2024 年并入 East 的统计检验，更名为 East Horizon [6]，2024-09-30 发布，模块包括剂量递增、剂量探索、固定样本、成组序贯、多重性和适应性设计，可嵌入 R 代码 [4][5]。Explore 支持固定样本、成组序贯、Promising Zone、MAMS II 期、无缝 II/III 期、重复测量；终点覆盖单/双生存终点、生存 + 二分类混合、连续、二分类、计数；可以用 R 自定义疗效反应和入组函数 [7]。
- 界面：见结论 1；所有视图共用同一套排序、标注、筛选，并有与热图联动的表格 [7]。
- 宣称与证据：「平均缩短时长或降低成本 10–20%」「比写代码快 5–10 倍」均为厂商自述 [1][5]，未见独立评估。
- 商业：软件许可（官方商店）加咨询，未公开价格 [5]。
- 借鉴：设计 × 情景网格、帕累托标注、跨情景稳健性、里程碑时间线、可插入自定义入组函数。
- 不借鉴：只给「最优设计」的交付口径。我们交付的是在已声明目标下的完整权衡，由人做决定。

**Berry Consultants FACTS**
- 对应：虚拟试验（后续的适应性、平台、剂量探索设计）。
- 做什么：包含核心引擎、剂量递增、剂量探索、适应性 III 期、无缝 II/III 期、平台试验、多终点、富集设计等引擎；输出各情景下的运行特征，并可导出每一次模拟的数据 [10]。FACTS 7（2023-04-12）自称是首个商用且经过验证的平台试验设计软件 [11]；现行版本为 7.1 [10]。
- 界面：分步定义设计 → 情景网格 → 设计比较 → 内置图表 → 导出。图 04 展示剂量反应模块的界面：左侧填参数和先验，中间显示模型公式，右侧是先验反应曲线，公式与参数放在一起。
- 宣称与证据：称前 20 大药企过半、30 多家学术机构在用（厂商自述）。
- 商业：商业许可，3 个月免费评估，未公开价格 [10]。
- 借鉴：执行包附上每次重复的原始摘要，方便审阅者复算；参数旁直接显示模型公式，让假设看得见。
- 不借鉴：V1 不做贝叶斯适应性和平台试验（与 §18.1 一致），以后可评估接入 FACTS 作为授权引擎。

**nQuery / PASS / rpact（样本量与成组序贯计算器）**
- 对应：虚拟试验（解析计算）；模型与验证（数值基准）。
- nQuery 官方价格（企业版，每用户每年）：Base 995 美元（固定设计），Plus 1,495 美元（加贝叶斯），Pro 4,995 美元（加成组序贯、样本量重估、MAMS、MCP-Mod、I 期设计），Expert 7,795 美元（再加入组、事件的指数 / Weibull / 分段里程碑预测）；学术版价格为企业版的 48%–86% [12]。
- PASS 2026 新增 52 个程序，总计 920 多个有文档的程序；一年订阅 1,195 美元，永久许可 4,995 美元（仅含当年版本）；试用版限制 α 值 [13]。
- rpact 是开源（LGPL-3）且经过验证的 R 包，支持固定与多阶段设计、inverse normal / Fisher 合并、均值 / 率 / 生存 / 计数、多臂适应性、富集以及带样本量重估的模拟；正式验证文档只提供给付费客户，另有 RPACT Cloud 学习工具和付费支持 [14]。
- 借鉴：①解析值与 Monte Carlo 估计并排显示，解析值作为交叉校验；②把 PASS、nQuery 文档中的公开算例和 rpact 示例的数值作为 AC-10/AC-11 的验收参考值；③以后扩展成组序贯时，以 rpact 为参考实现；④卖「验证文档包」。
- 不借鉴：把每个公式做成独立页面。我们按终点族和方法包来组织。

**QuantHealth（补充）**
- 对应：虚拟试验（疗效预测）、方案与先例。
- 做什么：宣传语是「预测任何患者对任何疗法的反应」；称拥有 3.5 亿人的多模态数据、含 10 万个药物数据元素的知识图谱、18 万个以上带整理结果的试验；功能包括方案优化（入排标准、给药方案、剂量、终点）、结局预测、入组预测（队列定义 + 中心级数据）；列出的合作方有 IQVIA、Sanofi、Astellas、Pfizer、Lilly [15]。
- 宣称与证据：首页没有公开精度指标，**未核实**。
- 借鉴：「入组预测 = 队列定义 × 中心数据」的组合方式。
- 不借鉴：「任何患者 × 任何疗法」式的通用疗效预测口径，与 §9.1「新药疗效不由标准治疗预后模型推断」相冲突。

**Unlearn TrialPioneer**
- 对应：方案与先例、虚拟试验、报告与决策。
- 做什么：2024-02-27 作为免费的设计探索工具首发 [17]；2026-01-28 重新发布为上游规划工作台，把证据、假设、历史基准和情景评估放进同一个工作流。其中 Scout 负责先例审阅，汇集 PubMed、ClinicalTrials.gov、Drugs@FDA 等来源；强调假设显式、可追溯，设计情景可以横向比较 [16][18]。
- 宣称与证据：只有产品描述，没有效果数据；官网只有示意插画，没有真实界面截图。
- 借鉴：先例 → 参数 → 情景的连贯链路，正对应我方 §12 的假设对象和 §17 的旅程 A；Scout 的来源组合（论文 + 注册库 + 监管审评文件）可以直接作为我方先例库的来源清单。
- 不借鉴：默认把厂商自己的疗效模型当作对照来源（属于 A1 范围，需要按使用情境单独验证）。

**Formation Bio：Delphi 与组织记忆**
- Delphi 预测「资产达到主要终点的概率」：多个智能体分别负责靶点、资产、临床先例和人类遗传学，按安全性和有效性两条轴给出分项评分；提示词模块化组装，每次预测都能追溯到确切的提示词版本；预测在结果揭晓前写成不可改的带时间戳记录，有新证据就生成新版本 [19]。**文章没有公布校准度或 Brier 分数等定量表现**，只举了一个个案。
- 组织记忆：认为员工要花 20–30% 的时间做「数据考古」，主张花 5% 的时间在工作发生时就把信息结构化记录下来（结构化会议纪要、可复用数据资产）[20]。
- 借鉴：预测登记（与 AC-23 一致）；把决策和理由结构化记录下来（与 §12 一致）。
- 不借鉴：用未公布表现的公司内部预测体系作为「成功概率」对外展示。

### 2.2 方案与试验先例情报

**Medidata Protocol Optimization（Dassault Systèmes）**
- 对应：方案与先例、虚拟试验（运营）。
- 做什么：2025-05-29 在 ASCO 发布 [21]。输入为方案草稿、SoA，或数字化为 USDM 的方案；输出患者负担指数（约 5,000 种操作，按疼痛、有创性、有害暴露、时长、焦虑打分）、中心负担、成本、复杂度、入组风险、修订风险，以及与可比历史研究的对标；有「Virtual Twin」方案模拟和情景分析；称数据来自 38,000+ 个试验、1,200 万患者 [22]。2026-02 获 SCOPE Best of Show [23]。
- 宣称与证据：减少修订、降低成本均为厂商自述；数据是私有的跨申办方数据，外部无法复核。
- 商业：企业订阅，未公开价格。
- 借鉴：「草稿 → 相似研究对标 → 负担与风险」三联视图；以操作为单位给负担打分。
- 不借鉴：黑箱风险分。我们的每个分数都要能展开到具体操作和具体先例。

**Faro（原 Faro Health）**
- 对应：方案与先例（SoA、负担、成本、USDM、预算）。
- 做什么：Study Design 实时指出可以降低负担、成本和复杂度的地方，称每条建议都附有来源数据和参考文献；Document Authoring 快速生成方案草稿；Workflow Automation 通过 API 或 USDM JSON 对接下游，称可把 EDC 搭建提速数周、几分钟生成中心预算 [24]。与 Merck 的研究在同行评议期刊发表：从最精简的 SoA 起步，每增加一项评估都必须按设计原则说明理由，再量化其影响 [25]。
- 宣称与证据：「发现 3 亿美元以上潜在节省」为厂商自述 [24]；Merck 方法论文属于少数公开了方法的案例 [25]。
- 借鉴：操作概念库；「新增一项评估必须写理由」的审阅字段；USDM JSON 作为交换格式。
- 不借鉴：直接套用美国的成本基准。国内成本由客户或合作方提供。

**Phesi Trial Accelerator**
- 对应：方案与先例、入组预测、虚拟队列。
- 做什么：2022-10-18 发布，有四个视图：患者画像、试验表现（模拟入组周期和最优中心数）、国家表现、研究中心表现（按启动、入组、数据质量排名）[26]；2025-01-29 发布 v2，称数据覆盖 1.32 亿患者 [27]；另有 Patient Burden Score [28]。称可生成「数字对照组 / 外部对照组」[26]。
- 宣称与证据：「每个 III 期试验平均节省 700 万美元」为厂商自述 [26]。
- 借鉴：国家 / 中心表现视图，以及「最优中心数」这个问题本身。
- 不借鉴：把数字对照组作为方案设计工具的默认输出（与我方 §8 的路线分离原则冲突）。

**Citeline（Norstella：Trialtrove / Sitetrove / Pharmaprojects / Patient Intelligence）与 Evaluate**
- 做什么：Trialtrove 称汇集 6 万多个来源，整理设计、入组时长、人群、终点和结局；Sitetrove 称覆盖 50 万以上研究者、19 万个中心、185 个国家 [29][32]。2026-09-10 发布 Patient Intelligence，把患者数据与试验、中心、管线情报合并用于可行性评估和方案规划 [29]。2026-02-26 与阿斯利康旗下 Evinova 合作 [30]，此前推出基于 LLM 的 SmartSolutions [31]，2026-07-31 数据接入 Cytel Enforesys 4.0 [9]。同属 Norstella 的 Evaluate 以共识销售预测、管线事件和流行病学数据为主，自带 AI 分析助手 Ask Ella [33]，与试验设计距离较远。
- 借鉴：先例字段的切分方式；「数据商 + 模拟引擎」的分工，说明我方引擎应能接入任何先例数据源。
- 不借鉴：V1 采购。成本高、以海外数据为主，对国内试验的覆盖**未核实**。

**Clarivate Cortellis Clinical Trials Intelligence**
- 称覆盖 68.9 万+ 个试验；可按主要终点完成、入组日期等里程碑与竞品对标；有中心级入组预测，并整合流行病学和中心可用性数据 [34]。
- 借鉴：对比表并列显示计划日期与实际日期。不借鉴：同上，V1 不采购。

**WCG / IQVIA**
- WCG 官网列出 ClinSphere 平台、Total Feasibility、Total Enrollment、Study Ready Feasibility Services（在方案设计阶段降低风险）和 WCG Site Network，没有公开量化指标 [35]。IQVIA 的相关页面拒绝我方抓取，**未核实**。
- 结论：大型 CRO 和数据商把「可行性评估」主要当作「数据 + 专家服务」来卖，而不是自助软件。这正是我方「平台 + 项目服务说明书」组合的空间。

**公共数据层（V1 先例库的底座）**
- ClinicalTrials.gov API v2：见结论 4 [36]。另有 `derivedSection` 提供 MeSH 映射，`hasResults` 标记是否有结果。
- AACT：由 CTTI（Duke 大学与 FDA 共同发起）维护，每天同步 ClinicalTrials.gov 全库，拆成 40 多张关系表，可云端查询或整库下载 [37]。AACT 历来提供中心数、实际时长等预计算字段，但官网已改版，旧的发布说明页返回 404，**当前字段名本次未能核对**，接入时以当前 schema 为准。
- WHO ICTRP：汇聚各国一级注册库，ChiCTR 是其中之一 [38]。字段较少，各库更新频率不同。
- EU CTIS：2025-01-31 起欧盟试验必须全部迁入；2024-06-18 起新的透明度规则取消了 7 年延迟公开的选项 [39]。
- 映射：ESTIMATED 对应我方的 `assumed`，ACTUAL 对应 `observed`；中心数和持续时长属于 `calculated`。

### 2.3 入组预测

**Cytel Enforesys**
- 用历史中心数据代替主观估计，用 Monte Carlo 评估数千种入组情景；输出达到里程碑的概率、入组曲线、国家 / 中心组合比较；提供激进 / 平衡 / 保守三档风险偏好 [8]。2026-07-31 发布的 4.0 版接入 Citeline Trialtrove / Sitetrove 的历史表现数据，考虑中心启动时间、筛选失败和区域差异 [9]。
- 借鉴：概率化的里程碑；「风险偏好 = 承诺哪个分位数」；中心启动计划作为一等输入。

**Lokavant Spectrum（2025-09 起归 ProofPilot）**
- 2025-04-23 发布 v15，称基于 50 万个历史试验，结合机器学习、生成式和因果模型预测末例入组；可在开研前按国家 / 中心组合建模，研究期间持续重算纠偏；称把 5 周的人工工作缩短到 5 分钟 [40]。2025-09-15 被 ProofPilot 收购 [41]。
- 宣称与证据：「预测准确度提升 70 倍」「减少 70% 不合规事件」「80% 以上置信度」都是口径不明的厂商自述 [40]。
- 借鉴：持续重算与「预测 vs 实际」对照；它被执行平台收购，说明预测要接上实时运营数据才有价值。
- 不借鉴：口径不明的「置信度」。我们报告的是预测区间的实际覆盖率。

**方法与其他**
- Poisson-Gamma 模型：各中心的入组率服从 Gamma 分布，入组过程为 Poisson 过程，可在研究期间用贝叶斯方法更新；这是多中心入组预测的经典统计框架 [42]。
- nQuery Expert 把入组 / 事件里程碑预测放进设计软件 [12]；Phesi 的试验表现视图模拟入组周期和最优中心数 [26]；Tempus TIME「先有患者、再启动中心」的做法改变了预测问题本身 [50]。

### 2.4 患者匹配与招募

**NIH TrialGPT 与 TrialGPT 2.0**
- 对应：患者匹配（患者→试验）。
- 做什么：分三个模块。Retrieval 用 LLM 生成关键词做混合检索，用不到 6% 的候选集召回 90% 以上的相关试验；Matching 对每条标准输出三元组（解释、相关句子编号、资格标签，标签体系见结论 5）；Ranking 把逐条结果汇总成试验级分数，包括线性汇总（各类标签占比）和 LLM 汇总（相关度 0–100、资格 −100 到 100），两者结合时 NDCG@10 为 0.7275 [43]（见图 03）。
- 证据：纳入标准的准确率 0.899（专家 0.876–0.916），排除标准 0.859；在 26 个错误中，最多的一类是推理错误（30.7%），即明明可以推断却判成「信息不足」[43]。作者自列的局限包括：依赖闭源 GPT 模型、用户研究样本小 [43]。TrialGPT 2.0：在 288 例回顾病例中，约 91% 的病例前 10 名推荐里至少有 1 个医生推荐的试验，筛查时间减少 55.0%；在 6 个月的前瞻性精准肿瘤 MDT 部署中，可及试验机会增加 90.9%；测试集 NIH-TrialBench 含 126 个合成病例 [45]。
- 工具定位：NCBI 网页工具的 FAQ 明确说它是实验性的发现与研究系统，不是临床决策支持；候选试验范围可以限定为合作项目自己的试验组合；输出内容包括支持证据、潜在冲突和缺失信息 [44]。
- 借鉴：三元组结构；支持证据 / 冲突 / 缺失信息三栏展示；把检索召回率、逐条准确率和节省时间作为三个独立指标；候选范围先限定为合作方的在研试验。
- 不借鉴：把 LLM 汇总分当作资格结论；把合成病例上的精度当作真实世界的承诺。

**Paradigm Health（Matcha）**
- 对应：患者匹配、中心协作、研究执行。
- 做什么：2025-12 完成 7,800 万美元 B 轮融资，并收购 Flatiron Health 的临床研究业务，平台覆盖 45 个州、166 家医疗机构、2,100 个诊疗地点 [46]；2026-04 宣布与 FDA 合作，在进行中的 II 期和 Ib 期试验里试点实时审阅 [47]。Matcha 的工程原则见结论 9：证据定位到字符偏移，算法键确定、失败结构化记录，模型负责评估、确定性代码决定流程走向 [48]。
- 借鉴：工程原则整体借鉴，与我方 §13、§15.3 高度一致。
- 不借鉴：以 EHR 深度集成和研究执行基础设施为前提的交付形态。我方 V1 的数据由合作方提供。

**Tempus（TIME 网络 + Deep 6 AI）**
- TIME 自 2019 年运行，网络中有大量社区医院；先在网络内找到合适的患者，再快速启动该中心。案例：Nimbus 9216-101 试验约两周完成中心启动，30 天内首例入组；I 期的 TIME Precision Network 有 40 多个中心 [50]。
- 2025-03-11 收购 Deep 6 AI（10-K 披露对价 1,740 万美元，含现金 430 万美元和股票 1,310 万美元），后者挖掘实时的结构化与非结构化 EHR 数据来匹配患者 [49]。
- 借鉴：以后可以加「有候选再启动中心」的触发式任务。不借鉴：由基因检测业务驱动的匹配闭环（我们没有这个入口）。

**TriNetX / BEKhealth（从 EHR 侧做可行性和找人）**
- TriNetX 称覆盖 3.09 亿患者、20 多个国家；TriNetX LIVE 用条件构建器实时给出总体和分中心的患者数，数据直接来自合作医疗机构 [51]。
- BEKhealth 把病历抽取、可行性评估和招募放进同一个流程，并公开了定价 / ROI 页面 [52]。
- 借鉴：逐条标准漏斗 + 分中心计数（见结论 7）。不借鉴：机构级 EHR 网络的建设路线。

**Triomics（OncoLLM / PRISM）**
- PRISM 发表于 npj Digital Medicine（2024-10-28），与 Medical College of Wisconsin 合作，是单中心研究：从 50 名患者约 1 万份病历中标注了 720 个问题，排序评估用了 98 名患者。逐条问题准确率 OncoLLM 63%（去掉「信息不足」类问题后 66%），GPT-4 68%（72%），GPT-3.5 53%；医生之间的一致率 5 人平均为 64%，两名入选医生之间为 70%；在 10 个候选试验中把真实入组试验排进前 3 的比例为 65.3%，复核后「前 3 名中含合格试验」约 95%；答案正确时解释正确率 90.91%，引用完全正确 86.71%；每个问题输出问题解释、回答推理、是 / 否 / N/A（N/A 指信息不足），以及 1–5 级置信度；每个患者-试验对的成本约 0.17 美元，GPT-4 为 6.18 美元 [53]。合作机构 CI4CC 的介绍页把它概括为「约 95% 准确」[54]。
- 借鉴：同一流水线支持两个方向（以患者为中心 / 以试验为中心）；输出置信度等级；「单对成本」作为运营指标。
- 不借鉴：用试验级、复核后的指标来宣传逐条判定能力；它把「信息不足」记为 N/A，而 TrialGPT 把「信息不足」和「不适用」分开，这正说明标签定义必须在我方评测前写清楚。

**Massive Bio**
- 在 ESMO Real World Data and Digital Oncology（2026）发表前瞻性研究：3,804 例转移性肿瘤患者（2024 年的常规诊疗），处理 15.7 万页文档；采用神经符号多智能体方法和肿瘤知识图谱，F1 0.82，敏感度与特异度均为 0.84，每位患者用时约从 120 分钟降到 30 分钟，各亚组差距不超过 10 个百分点；所有匹配都经肿瘤医生确认 [55]。
- 借鉴：「医生确认的匹配」作为计数口径；报告亚组表现差异。我方匹配指标按「系统候选 → 人工确认 → 转诊 → 正式筛选 → 入组」分层，每层单独声明分母。

**Carebox / Antidote / TrialX（结构化标准与预筛问卷）**
- Carebox Connect 用 AI 加人工监督，把 ClinicalTrials.gov 的资格标准原文变成可检索的结构化索引；提供几十种语言、按疾病组织的预筛问卷；匹配引擎通过 OAuth REST API 嵌入第三方系统；称已服务 100 万以上患者 [56]。
- Antidote 是双边市场，面向患者的 Match 搜索引擎可以嵌入合作方网站；与 Inspire（120 万成员）、SEQSTER 合作；称某试验中其来源占美国全部随机化的 60% [57]。
- TrialX 自 2008 年运营，产品有 AI 简化的多语言试验列表、研究网站与数字预筛器、志愿者库，以及让中心和申办方同时看到转诊状态的转诊管理门户 [58]。
- 借鉴：由结构化标准生成预筛问题；转诊状态对中心和申办方双向可见。

**Inato（中心网络）**
- 2016 年成立于巴黎，连接 50 多个国家的 6,000+ 个社区研究中心；对中心免费，向申办方收费；把早期规划、AI 选中心和 AI 预筛放在同一平台 [59]。界面（图 05–08）：中心卡片列出可及患者区间（如「20 例 IVC，最多 40 例」，IVC 的含义页面未解释，**未核实**）、PI 在该适应症的试验数、专科、多样性比例、「要求满足率」（未满足项用 ✗ 标出）以及经历摘要；申办方仪表盘按试验列出状态（设置中 / 待审中心数 / 已预筛人数 / 已入组人数）；有「帮我找合适中心组合」的对话助手；有预筛进度曲线。
- 借鉴：中心卡片的字段和状态仪表盘。
- 不借鉴：没有分母的营销标签。我方的标签只能来自台账事实。

**Clariness（已合并 SubjectWell）/ 1nHealth / Leal Health / Clara Health**
- Clariness：subjectwell.com 已 301 跳转到 clariness.com，官网称两家已合并；称累计 42,000 例随机化、覆盖 400 多个适应症和 60 多个国家（含在中国的运营）[60]。
- 1nHealth：从研究启动到末例入组全程负责，直接面向患者在线招募；按「签署知情同意、随机化」等里程碑计费 [61]。
- Leal Health（原 TrialJectory）：对肿瘤医生免费；「预测性患者旅程」会提前匹配疾病进展后可能适用的试验 [62]。
- Clara Health：官网拒绝我方抓取，**未核实**。
- 借鉴：Leal 的「未来线」思路（见 4.5）。不借鉴：按转诊或随机化计费（对我方平台而言会产生错误的激励）。

**Formation Bio Muse**
- 2024-11 与 Sanofi、OpenAI 联合发布，用于生成招募策略、面向不同亚群的材料和预筛问卷，称从数月缩短到数分钟；Sanofi 首先用于多发性硬化 III 期 [63]。
- 借鉴：从审阅过的研究定义出发，按人群和渠道生成多个版本。不借鉴：以内容生产速度衡量招募成效。

## 4. 对方案的具体建议

### 4.1 虚拟试验（§9）
1. **新对象「设计网格」**：设计维度（样本量、分配比、α、分析时点或随访时长、中心数、中心启动节奏）× 情景集（效应量，必须包含零效应；对照组参数；脱落；入组速率；筛选失败率）× 重复数 × 种子 × 方法包版本。每个格子是一次不可变的执行。
2. **结果视图**：运行特征表（功效、I 类错误、偏倚、覆盖率、期望样本量、时长、成本，均附 Monte Carlo 标准误）；权衡散点（帕累托标注，被全面劣于的设计置灰）；设计 × 情景热图（稳健性 = 跨情景的最差值）；最多 3 个设计的雷达对比；里程碑时间线（首例入组、末例入组、读出时间的分位数）。
3. **「选择目标」对象**：先声明约束（例如设计假设下功效 ≥ 80%、零效应下 I 类错误 ≤ 2.5%）和权重，保存版本后才显示排序；最终选定必须写决策记录。
4. **解析值并列**：固定设计给出闭式或近似公式的结果；若与模拟值的差距超过 3 倍 MC 标准误，就发出提示（提示级，不阻断）。
5. **入组与事件预测**：采用 Poisson-Gamma 类中心级模型，输入中心启动计划、每中心入组率先验（来自先例快照或合作方漏斗历史）和筛选失败率；时间-事件终点额外输出达到目标事件数的时间。所有预测进入预测登记表。
6. **验收参考值**：用 PASS、nQuery 公开文档中的算例和 rpact 示例的数值作为 AC-10/AC-11 的参考值；执行包附带每次重复的摘要（Parquet 格式）。

### 4.2 方案与先例（§5.3–5.4）
1. 结构化方案新增 SoA 矩阵和操作概念库；按受试者、按访视计算负担指标（均为 `calculated`）；新增一项评估时必须填写理由字段（借鉴 Faro 和 Merck 的做法）。
2. 「方案对标」页：列出相似先例，列包括注册号与来源、阶段、适应症（MeSH）、分组与盲法、主要终点原文、计划与实际入组（区分 ESTIMATED 和 ACTUAL）、中心数（计数所得）、开始到主要完成的实际时长、入排条目数、是否有结果。每次检索保存为快照（检索条件、截至日期、来源版本）。
3. 派生值「每中心每月入组」标为粗算：因为中心不是在整个周期都处于启动状态，这个数会偏低。先例进入假设登记册时，必须链接到具体快照行或文献定位（借鉴 TrialPioneer）。
4. 数据源优先级：CT.gov v2 → AACT（批量）→ ICTRP / CTIS → 国内登记平台。商业情报库只作为客户自带许可时的适配器。
5. 内部方案模型对齐 USDM 实体，V1.x 提供 USDM JSON 导出。

### 4.3 患者匹配（§11.1）
1. 评估记录包括：标准编号（含版本）、方向（纳入 / 排除）、适用性（适用 / 不适用 + 理由）、状态（满足 / 不满足 / 未知 / 待定）、证据列表（来源文档 ID、字符起止、事实 ID、来源类别）、解释、模型 ID + 提示词版本 + 输出模式版本、截至时间。
2. 排序拆成两部分：一是确定性的资格汇总（按状态计数；经人工确认「不满足」的试验进入「已排除」区并显示原因；仅由模型判为「不满足」的，进入「待复核排除」区，不静默丢弃，以便统计错误排除率）；二是模型给出的临床优先级（TrialGPT 2.0 的思路），标注「不是获益概率」。
3. 候选范围先用合作方的在研试验组合，其次才是公共注册库；试验→患者方向使用标准漏斗。
4. 评测：合作方真实病例、双医生独立裁定，报告医生间一致率、各标签混淆（重点看「未知」与「不适用」的混淆）、错误排除率、未知率；节省时间用「有 / 无工具」交叉设计测量。
5. 缓存与证据指针按结论 9 执行；模型、提示词或标准版本任何一项变化，都把旧评估标记为「已被取代」，不覆盖旧记录（对应 AC-05、AC-21）。

### 4.4 招募与中心协作（§11.2）
1. 中心档案字段：可及患者区间（注明来源与核实日期）、本适应症既往试验数、专科能力、方案要求满足率（逐项列出未满足的要求）、竞争研究、响应时长和各阶段转化率（来自台账，显示分母）、最后核实时间。
2. 申办方或项目视图：按研究显示「待审中心 / 已预筛 / 已转诊 / 已筛选 / 已入组」，参照 Inato 的仪表盘，但每个数字都能下钻到台账记录。
3. 预筛问卷与材料：由结构化标准生成，每题回链到标准编号；答案按「患者自述」来源存储；材料按人群和渠道出多个版本，审批前一律是草稿。
4. 不进 V1：消费者端市场、广告投放、按转诊计费、EHR 实时接入。列为后续：「有候选再启动中心」的触发式任务（借鉴 TIME）。

### 4.5 随访（§11.3）
1. **预期复评任务**：患者当前不满足，但存在可预期的变化（例如洗脱期结束、治疗线变化）时，生成带日期的复评任务，到期重新评估；在此之前绝不预先标记为满足（借鉴 Leal 的「未来线」思路，并遵守 §11.1）。
2. **预测对照**：入组预测与台账中的实际事件自动对照，在概览页展示校准情况（预测区间的实际覆盖率），不展示「准确度」这类单一数字。
3. 退出后的观察期与匹配证据分开存储；退出事件不改写已有证据（与原方案一致）。

### 4.6 商业模式（§20.3）
1. **研究端**：组织订阅（席位）+ 透明的算力额度（按模拟重复数或计算时长计）+ 付费的方法包「验证文档包」+ 项目服务说明书。
2. **评估许可**：功能完整、限定期限和算力（学 FACTS 的 3 个月评估许可），不像 PASS 那样限制关键参数。
3. **运营端**：按「活跃方案 × 月」计费；不按生成患者数、候选数、转诊数或随机化数计价。
4. **先例库**：基于公开数据的基础版随订阅提供；商业情报库通过客户自有许可接入，我方不转售。
