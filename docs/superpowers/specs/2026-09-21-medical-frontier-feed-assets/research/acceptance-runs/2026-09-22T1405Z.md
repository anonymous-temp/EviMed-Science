### 1.5 导读数字核对（100 条）

**抽样方法（可复现）**：总体是已发布且有中文导读的 1,502 条（13:41Z）。按 `md5(public_id || ':accept-2026-09-22')` 排序，取前 100 条。每条的 `item_texts.model_input` 重新算 sha256，与库里存的值 100/100 一致。样本构成：passed 75、repaired 25；英文 93、中文 7。

**平台核对器重跑**：`checkNumbers({title_zh(中文信源不查), summary_zh, reason_zh}, model_input)`，调用方式与 `frontierEditor.mjs` 第 457 行完全相同。

```
{ sample: 100, itemsWithNumbers: 79, numbersChecked: 296, itemsWithMissing: 0,
  itemsWithUnitMismatch: 3 }   // 4365e34d3b091378「15」、d13eb8992e7e90a5「80%」「60%」、bcc2ae9364f83490「3」
```

这 3 条单位提示在语义上都是对的：「15 至 65 倍」对应 15- to 65-fold；「超过 80% / 不足 60%」对应 LaTeX 写法的 `$80\%$`；「每周 3 次」对应 thrice-weekly。

**独立复核**：核对器只能证明「这个数字在原文里出现过」，证明不了「它说的就是那件事」。所以我把 296 个数字的上下文和原文出现处逐一并排读了一遍。遇到原文用英文数词写的（Thirteen / sixteen / five / two / one in five / 35 million-plus 等），也逐条核对到了。结论：

- 错数：**0**。
- 指代轻微偏移：**1** 条，`6c4bc9d2fa14026d`。导读写「共记录 3,455 次处方就诊」，而原文的 3,455 是「有诊断记录的处方就诊」，占总数的 99.9%，实际总数约为 3,458。
- 另有几处核对器是靠巧合放行的，但人工核对后语义正确：`bcc2ae9364f83490`「每周3次」、`6fab8aab1e96c2d9`「1所医科大学」（匹配到了注册号里的数字）、`9eb815850346edb4`「8 个模型」（原文是 3 个开源加 5 个专有，匹配到的是「8B」）。

**顺带核对事件综述**：35 条综述用同一个核对器、以成员条目的输入作原文，8 条报「缺数」。缺的全是对成员条数的计数，如「两篇报道」「3 条公报」「7 款药物」。平台核对综述时用的原文是枚举了各篇报道的提示词，所以这些计数是能核到的，不算错；但错并事件的综述会把错误的框架写出来，见 F1。

## 复跑

只读 SQL 的包装脚本，会话强制只读并设 60 秒超时：

```bash
#!/usr/bin/env bash
# q.sh <db> < file.sql
db="${1:-evimed}"
{ printf "SET default_transaction_read_only = on;\nSET statement_timeout = '60s';\n"; cat; } | \
  ssh -o BatchMode=yes -o ConnectTimeout=20 evimed "sudo -n docker exec -i web-evimed-postgres-1 psql -U evimed -d ${db} -qAt -v ON_ERROR_STOP=1"
```

几条关键 SQL（原文照录）：

```sql
-- 1.4 按时间线日统计精选
SELECT (timeline_at AT TIME ZONE 'Asia/Shanghai')::date, count(*) FILTER (WHERE selected), count(DISTINCT lane) FILTER (WHERE selected), count(*)
FROM evimed_frontier.items WHERE state='published' GROUP BY 1 ORDER BY 1 DESC;
-- 1.5 抽样
SELECT i.public_id, i.lang, i.title_zh, i.summary_zh, i.reason_zh, t.model_input, t.model_input_sha256
FROM evimed_frontier.items i JOIN evimed_frontier.item_texts t ON t.item_id = i.id
WHERE i.state = 'published' AND i.summary_zh IS NOT NULL AND i.summary_zh <> ''
ORDER BY md5(i.public_id || ':accept-2026-09-22') LIMIT 100;
-- 1.3 近 24 小时读成功（evimed_knowledge）
WITH f AS (SELECT source_id, bool_or(outcome IN ('ok','not-modified','empty')) ok FROM evimed_knowledge.fetches
           WHERE fetched_at > now()-interval '24 hours' GROUP BY 1)
SELECT count(*), count(*) FILTER (WHERE f.ok) FROM evimed_knowledge.sources s LEFT JOIN f ON f.source_id=s.id WHERE s.enabled AND s.retired_at IS NULL;
-- F3 安全警示条目及其来源的当前配置
SELECT i.public_id, i.primary_source_id, s.safety_feed, s.lane AS src_lane, i.lane, i.evidence_type, i.evidence_basis, i.selected_rule, i.title_zh
FROM evimed_frontier.items i JOIN evimed_frontier.sources s ON s.id=i.primary_source_id WHERE i.safety_alert ORDER BY 2;
-- 1.7 首次接入时交付的旧条目（evimed_knowledge）
SELECT count(*) FILTER (WHERE e.published_at < s.first_contact_at - interval '8 days') FROM evimed_knowledge.entries e
JOIN evimed_knowledge.sources s ON s.id=e.source_id WHERE NOT e.backfill;
```

其余步骤：

- **1.2**：两侧各导出 `json_agg(entry_id|plugin_entry_id, revision, seq)`，在本地按 `id#revision` 求集合差。
- **1.5**：本地执行 `import { checkNumbers } from OpenScience/apps/server/src/frontierNumbers.mjs`，逐条调用 `checkNumbers({title_zh(非中文信源), summary_zh, reason_zh}, model_input)`。
- **1.6**：插件侧读 `entry_texts.enrichment->'publication_types'`，平台侧读 `entries.plugin_entry_id → items`，本地调用 `frontierEvidenceFromPublicationTypes`。
- **接口**：用 Node 脚本以 `cdss-access` 登录，密码从 `.evimed-local/secrets/bootstrap-password` 读取，不打印；只发 GET。别名请求用 `redirect:'manual'`。结束时 `POST /api/auth/logout` 带 `X-Open-Science-CSRF`，之后 `/api/me` 返回 401。本人登录 2 次（13:47Z 接口核对、13:59Z 深入研究核对），两次都确认了 401。
- **测试**：命令和退出码都在 1.1 与 1.9；干净副本的做法是 `git archive ce647b892 OpenScience .github docs/…/contract | tar -x`，再把 node_modules 用符号链接接回来。
