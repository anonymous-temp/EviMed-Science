# Linux isolation follow-up, 2026-11-02

## Observed boundary

The DSH runtime is per project. Concurrent sessions currently share its project workspace, runtime filesystem, `/tmp`, and `/dev/shm`. `deploy/runtime-dsh/evimed-landlock-run.sh` grants tools read access to `/` and write access to the bound workspace and those temporary locations. A separate session cwd does not make another run's data inaccessible, and replacing it without resolving native workspace registration, attachments, follow-up state and output import would not be a safe implementation of run isolation.

The production runtime image was not present in the local Docker image inventory. The host data volume had approximately 16 GiB available and reported 99% used. A full image build installs R, Chromium and substantial scientific Python dependencies, with intermediate build layers. No existing user images, volumes or caches were removed and the full build was not attempted on that volume. A production-like candidate still needs a suitably sized isolated Linux build host or an independently obtained matching runtime image, then a separate local control plane and database. Provider keys must remain in the control plane, never the runtime. Neither the product nor production was deployed or modified.

## Executed Linux checks

The existing local `evimed-analysis-replay:20261026` image was used for an offline analysis-script check, not as a DSH runtime or platform candidate. The container ran as UID/GID 65534, with no network, a read-only root, a bounded temporary filesystem, all Linux capabilities dropped, no-new-privileges, and memory/process limits. Only the statistical capability, its mirrored skill, evaluation files and a temporary Python test runner were mounted, all read-only. No production data or provider keys were mounted.

On Python 3.12, `test_analysis_checks.py`, `test_analysis_session.py` and `test_run_analysis.py` reported **96 passed, 2 skipped and 24 subtests passed**. This checks the deterministic analysis helpers and session records under Linux; it does not establish model behavior, browser upload, DSH isolation, full engine execution or the skipped cases. An earlier attempt without a test dependency and mirrored skill mount failed during setup; it was corrected before this result.

## Remaining acceptance

- Implement a per-run execution boundary covering filesystem reads and writes, scratch locations, child processes and runtime services, with explicit safe input snapshots and output promotion; handle simultaneous edits, cancellation, retries, session continuation and provenance without overwriting project files. Test the native workspace/session and upload contracts against the pinned kernel before enabling it.
- Build or obtain a verified matching Linux DSH image in an isolated environment with sufficient disk; validate the actual Landlock and network boundaries and ensure no provider key enters the runtime.
- Run the candidate through browser upload and actual DeepSeek/DSH turns for data analysis, managed bibliometrics, Meta literature retrieval and manuscript upload. Independently check scientific results and artifact provenance; retain failures and raw evidence.
- Fix and retest any defects found, including the native Markdown link rendering issue recorded in the preceding live findings. Passing the offline Python suite is not a substitute for these gates.

## Candidate data-analysis continuation: observed mismatch

A real candidate DSH + model run uploaded the public WDBC CSV and compared `mean radius` between malignant (`breast_cancer_yn=0`, n=212) and benign (`=1`, n=357) observations. Its mean difference 5.32 and 95% CI 4.85–5.79 agree with the previously independently computed 5.316306379 and 4.845165154–5.787447604 to the displayed precision. Its follow-up scaled the values by 10 and correctly reported difference 53.16 and interval 48.45–57.87 with the same n, t and p.

The follow-up reply listed several statistics under “only check, do not recompute,” but the actual `continuation/scale-x10/scale_x10.py` re-executes Welch t, Mann–Whitney, Shapiro, Levene and a 10,000-iteration bootstrap on the scaled observations. Recalculation can be a legitimate independent cross-check, but it must be described as such; its presence cannot support a claim that those quantities were not recomputed. The output demonstrates reuse of the original results and data alongside recomputation, not selective execution of only affected calculations. A regression replay must independently inspect the executed script and receipt and compare them to both reply and report; numerical agreement alone does not establish the reuse claim.

The revised statistical skill was copied into a second local candidate image and a third turn in the preserved real session requested a 100-fold scaling without explicitly pointing out the wording error. It reported 531.63 (95% CI 484.52–578.74), consistent with the independent original estimate and bounds multiplied by 100. Both the reply and generated addendum explicitly said the invariant tests had been recomputed for verification; inspection of `scale_x100.py` confirmed it reran t, rank, Shapiro, Levene and bootstrap calculations. This is a passing example of accurate disclosure, not evidence that the agent selectively avoids unnecessary recomputation or that every future reply will be correct. The control-plane image differed from production in its base layer, and the control plane was not deployed.

A Python 3.10 peer-review service was then built from the specialist Dockerfile, started on the candidate-only internal network without a provider key, and reached a healthy state. A second browser run submitted the uploaded manuscript and received managed job `review-20261102035619-8e9b6f79eb9d`; its persisted state was `succeeded` and `modelRoute: gateway`. The parent run completed after approximately 13 minutes 36 seconds.

The underlying managed result was degraded: 4 of 19 quotes were not located and their findings were demoted, and the engine recorded that it does not independently recompute statistics. Its raw report overstated the statistical consistency of a 95% confidence interval and p value without qualifying the test, and described an adjusted odds ratio as a relative decrease. The parent reported additional arithmetic errors and an invented ethics section, and its delivered report corrected the unsupported claims and recalculated key values. The parent also discovered files from the earlier review in the shared project workspace and moved them aside; this demonstrates continued shared-workspace ambiguity, not run isolation. A completed job, a parent repair or one case is not a general scientific-quality pass.

## Candidate bibliometrics and Meta: observed boundaries

A real managed PubMed bibliometric job on the unmodified specialist returned 98 cleaned records from 100 retrieved and 340 hits for the requested 2022–2023 search. Independent counting of its `cleaned_records.csv` gave issue years 2022: 3, 2023: 73 and 2024: 22. `search_metadata.json` states publication-date filtering, issue-year analysis and relevance truncation; the sample is not the population of all eligible papers. NCBI MeSH lookup logged a text-as-XML parse error, and its SGLT2 descriptor was absent. The first native-turn start was rejected with `engine_model_session_unowned` before run registration; a later retry was accepted. A controlled delayed-adoption replay subsequently showed that the active-run ledger projection omitted the native turn identity needed by the resolver; the corrected projection was tested against a real ledger and in the real kernel with a forced initial miss, where the exact pending call and same native turn were rechecked before the job was admitted.

After replacing the specialist's MeSH parser in a candidate-only image, a real managed job with the normalized topic `SGLT2 inhibitors AND chronic kidney disease` returned the SGLT2 descriptor and 622 hits with the same two-year publication-date and 100-record limit, without the zero-result fallback. The changed search is broader; the different relevance-truncated cohorts are not comparable estimates of temporal trends. A preceding run supplied a concatenated synonym phrase, got zero hits for its formal query and used a recorded fallback; the model corrected and reran it. This is a separate remaining query-construction risk. Generic member-drug synonyms and unindexed records remain an incompleteness risk even with MeSH present.

The real Meta candidate ran a managed job for SGLT2 inhibitors versus placebo in adults with HFrEF, naming DAPA-HF and EMPEROR-Reduced. The generated start request set `maxPapers=40` despite no user-requested cap. The job finished with `releaseStatus: blocked`: 7,863 records identified, 40 title/abstract screened, 10 sent to full text, six assessed and zero included; neither named primary report was assessed. The user-facing answer accurately declined to invent a pooled estimate. This run does not show the evidence is absent; it establishes that retrieval/screening constraints and the generated manuscript prevented an answer. Both the request budget choice and relevant-study retrieval/ranking require remediation and independent replay; a changed limit alone cannot prove comprehensive systematic-review coverage.

The Meta skill was updated to omit `maxPapers` unless the researcher explicitly requests a screening cap and to disclose the engine's actual limits and the assessment status of named trials. In a new candidate project, the exact same natural-language request was submitted; the new managed job `meta-20261102052129-a24294fb4f45` started with `maxPapers: null`, rather than the earlier unrequested 40. This is a passing check of the generated start parameter, not of retrieval, screening or release quality. The job remains running. The bounded engine retrieval and screening policies still apply; omission of an explicit cap does not make the search exhaustive or ensure the named trials are found.

A further 20-record candidate replay showed that a reported country mismatch compared `raw_records.json.country` (PubMed journal publication country) with `cleaned_records.csv.countries` (countries inferred from author affiliations). These are different fields, not automatically contradictory. For the prior 19-record sample, an independent count of the cleaned affiliation countries agreed with the top-country table (US 4, Denmark 2), while raw publication-country values were different. The specialist now records both field definitions in `search_metadata.json` and states the distinction and affiliation incompleteness in its Chinese and English methods. In the real candidate job `bibliometric-20261102053140-0a63ee59e504`, those definitions appeared in metadata and the generated methods report. This does not validate every country extraction or make a relevance-truncated 20-record sample representative.

The follow-up browser-driven candidate review of the 20-record search finished with 19 cleaned records. Its final report explicitly distinguished journal publication country from countries inferred from author affiliations and reported US 4 and Denmark 2, matching the cleaned country table, rather than treating the raw journal field as a conflicting author-country count. This is one observed successful interpretation, not general validation of affiliation parsing or bibliometric representativeness.
