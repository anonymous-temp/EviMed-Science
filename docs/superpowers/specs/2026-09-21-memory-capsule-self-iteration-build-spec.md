# 第一篇　它是什么，值什么

## A1. 一句话

**记忆胶囊，是把"一个人怎么干活"变成一件可以积累、可以看见、可以带走、可以借给别人的数字资产。**

它由三个动作组成：

| 动作 | 用户感受到的 | 背后的机制 |
|---|---|---|
| **记住** | 说过一次的要求，以后不用再说 | 只从你的原话里记；每条带来处；自动生效；一步撤销 |
| **学会** | 用得越久，它越像你 | 从你完成的工作和你的纠正里提炼"你的做法"，下次自动带上；变差了自动撤下 |
| **借出** | 把我的路子给你，你把你的给我 | 做法和标准打成签名、加密的包；对方试用一次、一键启用、一键停用 |

## A2. 它解决的四个问题

1. **AI 每次都像第一次见你。** 背景、口径、格式、禁忌，每个新任务都要重新交代一遍。
2. **高手的经验留不下来。** 一个人真正值钱的不是他知道什么，而是他"怎么做"。这些做法散在一次次任务里，人一走就没了，新人只能重新摸索。
3. **千人一面。** 同一个工具给所有人同一个答案。而医学，尤其是中医，恰恰是因人、因派、因病而异的。
4. **不敢让 AI 记。** 看不见它记了什么，记错了改不了，不知道什么时候被用上——于是干脆关掉。

## A3. 用户看到什么：一页看板

（原图 1 画的是记忆胶囊的一整页，自上而下就是下面这张表的区块；图已不在仓库，页面构成以下表和第 10.1 节为准。）

一页，从上到下回答用户会问的五个问题：

| 区块 | 回答的问题 | 要点 |
|---|---|---|
| 标题下的一句定义 | 这页是干什么的？ | "EviMed 自己记下的……资料本身在知识库"。10 秒内看懂 |
| 两个开关 | 我能不能关掉？ | 一个总开关，一个"本项目不用"。没有第三个 |
| **EviMed 眼中的你** | 它到底怎么理解我？ | 三行话：你和你的方向、你的做法、这个项目。**每句都由下面的具体条目拼成，点得回去；没有依据的话不出现** |
| 最近变化 | 它最近动了什么？ | 记下了、改了、被新的替代、一条做法开始生效——每条一步撤销 |
| 记下的内容 | 具体记了哪些？ | 一个搜索框、五个筛选；三种条目混排，用来处标签区分 |
| 收到的胶囊、分享 | 别人给我的、我给别人的 | 整包启用或停用 |

**全页没有一个要填写的表单。** 想固定一个要求，在对话里说一句就行；想纠正，对话里说，或者在那一行点「改」「忘记」「不对」。

每一行都说清四件事：**这句话是什么、从哪来的、有多可靠、用过没有。**

（原图 2 画的是展开一条记忆后看到的依据、版本、曾经如此和用在哪；图已不在仓库，构成见第 10.2 节。）

- **从哪来**用标签说：你说的 · 你确认过 · 你改过 · EviMed 推断 · 来自研究 · 来自资料 · 我的做法 · 来自某人的胶囊。这个标签终身不变，推断出来的东西永远不会冒充"你说过"。
- **有多可靠**用次数说："在 4 次研究中观察到"。不出现"置信度 85%"这种没人知道怎么来的数字。
- **曾经如此**：观点变了，旧的不删，留在这一条的历史里——"3 月到 9 月你只看 RCT，之后接受高质量队列研究"。这就是一个人的变化与成长。

## A4. 它怎么越用越好

（原图 5 画的是自迭代回路：研究结束 → 触发 → 提炼成候选方法 → 生效并标「新」→ 下次挂载 → 归因 → 夜间整理 → 降级；图已不在仓库，文字版见第 8.1 节。）

三点值得对外讲：

1. **全自动。** 触发学习的是你正常的工作——交付了一份东西、在对话里纠正了一句、同类任务做到第三次。不需要你点"采纳"，不需要你填"经验总结"。
2. **先生效，后评测。** 学到的做法当晚就用上，标一个「新」，写成一句你看得懂的话："Meta 分析先报 GRADE 再报效应量（从你的 3 次研究学到）"。后台的对照评测只负责一件事：发现它让结果变差了，就当场撤下来。
3. **你始终说了算。** 停用、回到上一版、或者在对话里说一句"不对"。这句"不对"本身，就是下一轮学习的信号。

## A5. 可交换、可分享：这是它和所有"AI 记忆"最不一样的地方

记忆如果只属于一个账号，它就只是个功能。**做法能在人和人之间流动，它才是资产。**

（原图 7 画的是胶囊在人与人之间怎样流通、凭什么被信任：发送方打包签名，接收方验签、扫描、试用、启用；图已不在仓库，文字版见第 9 节。）

**发送方**只做三步：选范围、看一眼"对方会看到什么"、设口令。

（原图 3 画的是发送方的预览页：选范围、看对方会看到什么、设口令；图已不在仓库，见第 9.3 节。）

- 默认只分享**工作方式**：你的做法 + 你明说过的标准与偏好。个人背景、项目知识是可选的加项。
- **永远不会进包**的：系统推断而你没确认过的、来自你资料库的、敏感的、任何原始对话和文件。分享的是"怎么干活"，不是"干过什么活"。

**接收方**的体验是"像装一个插件"：

（原图 4 画的是接收方的验证、自动检查、试用与启用；图已不在仓库，见第 9.4 节。）

- **来源已验证**：包带着发送者的数字签名，确认是他发的、中途没被改过。
- **自动检查**：内容里如果有一句不像"描述做法"、而像"指挥助手去做什么"，当场剔除并告诉你。
- **试用一次**：开一个临时对话按他的路子跑一遍，不影响你的任何记忆。
- **启用 / 停用**：整包生效，整包退出。对方的内容永远不会混进你自己的记忆里；你明说的要求永远优先于对方的。
- **版本**：对方改进了做法可以推送新版，你看到差异再决定升不升；对方撤回后，之后的版本不再提供。

## A6. 和常见的"AI 记忆"有什么不同

| 常见做法 | 记忆胶囊 |
|---|---|
| 记零散事实 | 记事实，更记**做法** |
| 黑箱，用户不知道记了什么 | 一页看板，逐条有来处、用过几次、可撤销 |
| 模型觉得是就记 | **只认用户原话**，代码逐字核对引文；资料和网页最多成为"带出处的事实"，成不了你的偏好 |
| 锁在一个产品里 | 开放格式，可导出；有对外接口，能挂到别的产品上 |
| 只属于个人 | 个人的，也可以交接给弟子、同事、科室、另一家机构 |

## A7. 价值

**对使用者**：少交代、少返工。小样本对照里，带记忆的研究用时更短、证据更完整，方向一致，但样本还小，不作为对外宣称的数字。真正可感的是第二周——说过的话它都记得，而且你看得见它记得。

**对专家和团队**：经验第一次有了载体。它可以**署名**（签名）、可以**授权**（加密、指定接收人）、可以**更新**（版本链）、可以**停止分发**（撤回）。带教不再只靠口传心授，新人第一天就能按团队的标准产出。

**对机构**：标准统一，人员流动而经验不流失；本机构自己的习惯和共识被沉淀下来，而不是被一个通用模型抹平。

**对平台**：

- **留存来自价值而不是锁定。** 胶囊可导出，这反而是用户愿意放心让它记的前提；用得越久胶囊越厚，离开的代价是真实的。
- **网络效应。** 每一个被分享出去的胶囊，都把一个新用户带进来，而且是带着明确使用场景进来的。
- **内容生态。** 流派、专病、名医、科室——这些胶囊由拥有这些知识的人生产，不由平台编写。平台提供的是格式、信任机制和货架。
- **跨产品复用。** 同一套记忆与学习能力，通过接口挂到科研工作台、中医 CDSS 和任何外部智能体上。
- **难以复制的部分**不是"存记忆"，而是：只认原话的写入规则、做法的学习与自动撤下、签名与检查的信任链、以及临床场景下的治理方式。

# 第二篇　专病与流派：为什么这套东西天然适合中医

## B1. 中医知识的三个特点

1. **同病异治，各家学说。** 同一位病人，经方家先找方证眼目，脾胃派先问饮食与大便，温病家先辨卫气营血。"正确答案"不唯一，但每一家内部自洽。
2. **经验长在人身上。** 名老中医的价值在加减的分寸、问诊的次序、什么时候不用某个方。这些靠跟师、抄方、整理医案来传，周期长、覆盖窄。
3. **专病专科化。** 脾胃病、肾病、失眠、不孕……每个专病门诊都有自己成熟的路径，基层医生很难一一掌握。

**推论：一个"统一口径的中医 AI"注定平庸。** 它需要的不是一个更大的模型，而是一位位**可以切换的老师**。胶囊正是"老师"的载体。

（原图 9 把同一位病人在两个流派胶囊下得到的不同追问与候选方并排画出；图已不在仓库。）

## B2. 四类胶囊

| 类型 | 里面装什么 | 谁来生产 | 谁来用 | 价值 |
|---|---|---|---|---|
| **流派胶囊** | 核心理论、辨证重点、问诊要点、组方风格、代表方、适用边界与禁忌 | 流派传承人或学术团队撰写，内容治理终审 | 想按这一派思路看病的医生 | 学术传统第一次有了可签名、可更新的数字载体；同病异治可以并排对照 |
| **专病胶囊** | 某个病种的问诊路径、分型、主方与加减规律、随访节点 | 专病门诊、重点专科 | 基层、全科、低年资医生 | 专科能力下沉；一个病种一个"随身上级医师" |
| **名医 / 个人习惯胶囊** | 从真实改方里学到的用药习惯和加减偏好 | **系统自动学**，归医生本人所有 | 本人；经本人授权的弟子 | 名老中医经验传承从"整理医案"变成"日常工作的副产品"；个人效率 |
| **院内 / 科室胶囊** | 协定方、科室共识、本院目录内的用药习惯 | 科室汇总，中医师终审 | 本院全体医生 | 沉淀本院自己的那一派；新人同质化 |

科研工作台里有完全对应的一组：**专病研究胶囊**（某个病种的检索策略、纳排标准、结局指标偏好、证据分级口径）和**课题组胶囊**。同一套机制，两个产品。

## B3. "我的用药习惯"：医生自己的看板

（原图 10 画的是医生自己的「我的用药习惯」看板：一句话一条习惯，带次数，可停用；图已不在仓库。）

- 学的是**医生改了什么**：系统给了候选方，医生把党参换成了太子参、加了两味安神药——这个差异，比任何问卷都真实。
- 写成一句医生看得懂的话，带上次数，随时可停用。
- **有些东西永远不学**：涉及毒性药、涉及剂量的模式，一律不沉淀为习惯。剂量只由药典边界、院内目录和审方决定。

## B4. 意义

- 对**名医和流派**：经验不再只存在于人和纸上，而是一个可以署名、授权、迭代的活的载体；传承的对象从几个入室弟子扩大到愿意启用它的每一位医生。
- 对**基层**：不是得到一个标准答案，而是看见高手"先看什么、为什么这样加减"。这是带教，不是替代。
- 对**医院**：在同一套安全底线之上，容纳多个学术传统，并长出自己的那一个。
- 对**产品**：中医 CDSS 从"一个会辨证的系统"变成"一个承载各家学说的平台"，内容由行业里真正拥有知识的人来供给。

# 第三篇　挂到中医 CDSS 上：匹配度与集成方式

## C1. 灵犀中医 CDSS 现在是什么样

- 门诊中医"副驾驶"，建议性质。流水线 **M01 采集 → M02 追问 → M03 辨病辨证 → M04 候选方药 → M05 风险评估与随访**，外加灵犀审方。对内是 `/diagnosis` 页面，对外是给甲方 HIS 的接口。
- **已经上线了一套"流派卡"**：默认档加五个流派（经方、温病、丹溪滋阴、温补、扶阳）。每张卡有代表医家、著作、核心理论、辨证重点、组方风格、代表方、适用边界、禁忌、治理版本和审核人，并配有各自的问诊策略。规范里写明："诊疗思路偏好只影响辨证视角、方源和加减；安全永远优先。"
- 甲方原本要 13 档。**脾胃、孟河、岭南、海派、院内优先等 8 档在 2026-08-07 被砍掉**，原因是线上可用的结构化方剂太少，"宁可不做假的"。同一份建设方案把"医院/科室自定义流派，沉淀**本院用药习惯**"列为后续方向。
- **没有医生身份**（只有机构级租户和共享令牌）、**没有数据库**（病例在浏览器本地加密保存）、**医生的任何决定都没有留存**（改方、采纳只在浏览器里；最终医嘱在甲方 HIS，CDSS 看不到）。
- 安全层是确定性的，只读病例事实：红旗、妊娠与儿科、十八反、剂量上限、处方权限。模型输出绕不过它。

## C2. 匹配度：零件几乎一一对应

| 记忆胶囊的零件 | 中医 CDSS 里已有的对应物 | 说明 |
|---|---|---|
| 胶囊的"临床面"（一个做法包里写什么） | **流派卡的字段结构** | 医家、著作、核心理论、辨证重点、组方风格、代表方、边界、禁忌——直接作为胶囊清单的临床部分 |
| 把胶囊内容交给模型 | **流派卡的注入函数**，已接通 M02、M03、M04 三个阶段 | 新增一个与它并列的块即可，三个阶段一次接通 |
| "只作参考，不可被当作证据引用" | **专家决策卡通道**，每行带标记、引用校验逐行跳过 | 胶囊正文走同一条通道 |
| 内容治理与版本 | 流派卡的**治理字段**：草稿 / 审核中 / 生效 / 退役，作者、审核人、生效时间 | 与胶囊的签名、版本链天然对齐 |
| 学习信号 | **审方端点**：全系统唯一同时拿到"原候选方"和"医生改后的方"的地方 | 在这里算出结构化差异 |
| 输出侧的说明 | M03/M04 已有的"流派适配说明"字段，HIS 方案里已回显流派标签 | 复用，显示"按《某胶囊》视角" |
| 外部服务的接法 | 审方、证据检索的**出站客户端范式**：默认关、失败降级、限时、限长、只加不减 | 记忆服务照此接入 |

**缺的只有三样**：医生身份、决策事件的留存、外来内容的临床治理流程。第一样需要甲方配合传一个标识，后两样由本方案补上。

**一个必须说清的限制**：被砍掉的 8 个流派，缺的是结构化方剂基础，胶囊不会凭空变出来。胶囊带来的是"怎么看、怎么问、怎么加减"；**到剂量级的候选方，仍然必须落在受治理的方剂目录里**。所以每个胶囊在启用前显示一个指标——"代表方有几首在受治理目录内"（原图 8 的例子是 14/16）——目录外的部分只作为视角和加减建议出现。

## C3. 医生看到什么

（原图 8 画的是诊疗思路一栏挂上胶囊后的货架：可导入的流派、专病、名医胶囊和可沉淀的个人与本院胶囊，每个胶囊标出「代表方 14/16 在受治理目录内」，底部一条绿色横幅写「安全结论与不选胶囊时一致」；图已不在仓库。）

今天的"诊疗思路"是 6 个固定选项；挂上胶囊后，它变成一栏可以**导入**（流派、专病、名医）和**沉淀**（我的用药习惯、本院胶囊）的货架。选中一个胶囊，变化的只有三处：追问的侧重、辨证的视角、主方倾向与加减建议。底部那条绿色横幅是硬承诺：**安全结论与不选任何胶囊时完全一致。**

## C4. 集成方式

（原图 11 画的是中医 CDSS 与胶囊服务的集成：独立服务、四个接入点，CDSS 不落库；图已不在仓库，文字版就是下面的表。）

记忆胶囊作为**独立服务**部署（仅接口模式），中医 CDSS 是它的一个调用方。CDSS 保持"无数据库"，身份和记忆都由胶囊服务持有。四个接入点：

| # | 接入点 | 做什么 | 关键约束 |
|---|---|---|---|
| ① | **身份** | 甲方 HIS 在请求头里传一个不透明的医生标识；记忆的主键 = 机构 + 医生标识 | 不传则退化为机构（科室）级胶囊，个人习惯不可用 |
| ② | **取用与注入** | 辨证请求到达时，在现有的并发预取批里向胶囊服务取"该医生的习惯 + 已启用胶囊中与本病种/证候相关的条目"，拼成一个与流派卡并列的块，放进 M02/M03/M04 的患者后缀 | 默认关；3 秒超时；失败即"无胶囊"，不影响诊疗。**只进后缀不进公共前缀**（保住前缀缓存）；**绝不写进病例字段或对话**（那里的文字会被安全扫描读到，可能造出假红旗）；占用字符预算有上限；走"不可引用"通道 |
| ③ | **学习信号** | 审方端点算出"候选方 → 医生改后的方"的结构化差异（换了什么、加了什么、减了什么、对应的证候与所选思路），**去标识后异步**上报；M02 的作答与跳过顺带上报 | 患者事实不出 CDSS；上报不在响应路径上；涉及管制毒性药和剂量的差异在 CDSS 侧就丢弃，不上报 |
| ④ | **胶囊管理与治理** | 导入、试用、启停、版本；看板（我的用药习惯、科室视图、胶囊货架） | 见 C5 |

另外两处工程细节：胶囊的**编号与版本要绑进辨证结果的签名**（现在流派偏好已经绑在里面），防止"用 A 胶囊辨的证，拿去配 B 胶囊的方"；新路由要登记进现有的路由分类表，新上游要登记进上游守卫测试，胶囊服务**不进入**严格就绪检查。

## C5. 临床场景下的三条加严

科研工作台的原则是"自动生效、事后可撤"。临床处方属于重大安全事项，所以在中医 CDSS 上加严三条：

1. **外来胶囊先终审，后上架。** 医生个人的习惯胶囊对本人自动生效；但流派、专病、名医、院内这四类要给别人用的胶囊，必须经中医师终审（沿用流派卡现有的"审核中 → 生效"状态）后才出现在全院的选项里。签名验证和自动检查照做，但不替代终审。
2. **胶囊不携带剂量，也学不到剂量。** 导入时剂量信息剥离；学习时毒性药与剂量模式不沉淀；候选方的方名、出处、剂量核验仍由服务端确定性编译。胶囊只影响视角、排序和加减建议。
3. **开关对照是发布门槛。** 同一批回归病例，胶囊开与关，安全结论必须逐位一致；任何一例不一致，胶囊功能不发布。这条加入现有的确定性回归注册表。

## 1. 范围与建成标准

**三件事是一个系统，不是三个功能：**

| 面 | 它回答的问题 |
|---|---|
| 记忆 | EviMed 知道我什么？ |
| 自迭代 | EviMed 从我的研究里学会了什么做法？它越用越好了吗？ |
| 展示与分享 | 我怎么看见、纠正、带走、借给别人？ |

**不做的事**（定论，不再讨论）：

- 不让用户填表写记忆、写方法。想固定一个要求，在对话里说一句。
- 不逐条审批。没有"待采纳"队列，没有"确认后生效"。
- 不做无痕模式，不在对话里加"本次用到的背景"面板或任何新控件。
- 不训练模型。经验只以文本形式存在：事实是句子，做法是 SKILL.md。
- 不做组织共享、不做多人同时编辑。分享是点对点的快照。
- 知识库的检索不归这个系统管。它只接收知识库读完资料后产出的"带出处的事实"。

**建成的标准**（全部可在真实会话上观察）：

1. 在对话里说"以后报告先给结论再给证据"，下一条对话的回答就照做；记忆胶囊里出现这一句，标「你说的」，能点回那条对话。
2. 第一次打开记忆胶囊页的人，10 秒内说得出这页是干什么的；全页没有一个要填写的表单。
3. 做完三份同类研究后，页上出现一条「我的做法」，标「新」，写明"从你的 3 次研究学到"；下一次同类研究的运行账本里记着它被挂载；点「停用」后下一次不再挂载。
4. 用户 A 导出"我的做法"，用户 B 导入、试用一次、启用；B 的同类研究按 A 的做法走，回答里说明"本次参考了 A 的做法"；B 点停用后恢复原样。
5. 任何一次自动改动都能一步撤销，撤销本身也能撤销。
6. 索引服务停掉，对话照常，召回退到词法匹配；索引清空后一条命令重建。

## 2. 十条铁律

这十条是结构性的，每一条都对应代码里的一个不可绕过的位置，不是提示词里的一句话。

1. **记录只有一个家。** 权威记录在 PostgreSQL。索引是派生品，永不持有记录，每次命中都回库复核；索引过期最多提名一条已不存在的记录，那条被丢弃。
2. **来处标签终身不变。** 你说的、你确认的、你改过的、EviMed 推断的、来自研究的、来自资料的、来自别人胶囊的——写入时定下，之后只有你本人的动作能把它升格。推断永远不会变成"你说过"。
3. **只有你本人能成为"怎么做事"的来源。** 偏好、纠正、画像必须逐字引用你自己的话。工具结果、网页、助手的话、上传的资料，最多成为带出处的事实。这是对"往记忆里投毒"的结构性防御。
4. **自动生效，所以必须可撤销。** 每次改动都是一条修订，带原因和时间；一步撤销；撤销可再撤销。
5. **生成者不能给自己盖章。** 蒸馏出方法的那次运行不能决定方法的状态；状态由服务端按账本重新计算，接口上没有"批准"这个入口。
6. **没判定过的内容不挂载。** 能被运行时当技能读到的，只有状态生效、非推断、已扫描的条目。运行中随手记的笔记永远洗不成方法。
7. **胶囊是上下文，不是权限。** 任何记忆、任何方法都不能放宽交付契约或安全规则。
8. **数数不靠断言。** 强度用可数的事实（说过几次、在几次研究中观察到、用过几次），不让模型打百分比。
9. **语言判断交给模型，闭集判断交给代码。** "这句话是不是一条长期偏好"由模型判断；"引文是不是原话的子串""文本里有没有平台标识"由代码判断。没有模型就不抽取，不退回关键词规则。
10. **唯一的人工关口是用药安全。** 命中临床安全规则的画像类记忆先挂起等你看；其余一律先生效。

## 3. 概念模型

### 3.1 一个胶囊里有什么

```
记忆胶囊（一人一个，注册即有）
├── 理解        关于你、关于项目的事实        —— 一句一条
├── 我的做法    从你的研究里学到的方法        —— SKILL.md，一条一份
├── 来自资料    知识库读完资料后沉淀的事实    —— 带出处，永不出门
├── 经历        每段研究一条摘要              —— 只进时间线，不参与召回
└── 收到的胶囊  别人分享来的包                —— 整包启用/停用，永不并入以上四类
```

用户只看到前三类混排在一张清单里，用筛选区分；"经历"只以「最近变化」和每条记忆的"来自哪次对话"出现。

### 3.2 每条事实的四个维度

| 维度 | 取值 | 说明 |
|---|---|---|
| 类别 kind | profile · preference · behavior · correction（画像类，跟人走）；project_fact · decision · follow_up（项目类）；stance · expertise · writing_style · tooling · tension（画像扩展）；run_summary（经历） | 画像类必须账号级，且必须引用用户原话 |
| 范围 scope | user · project · session | 默认项目不写项目类事实，它是个杂物间，写了会被下一段无关对话覆盖 |
| 来处 origin + basis | explicit（你说的）· manual（你改过）· confirmed（你确认过）· inferred（推断）· system（来自研究）· source（来自资料）· import（来自某人的胶囊） | basis 在读取时由 origin 和你的动作算出，不存 |
| 状态 status | active · pending（仅用药安全）· superseded · archived | 被取代的不删除，挂 `superseded_by` 与 `invalid_since` |

### 3.3 三个容易混的词，定义印在页面上

- **知识库**：你放进来的资料——文献、方案、数据。EviMed 回答和做研究时会去读。**你写，它读。**
- **记忆胶囊**：EviMed 自己记下的——关于你、你的项目、你的做法。自动生效，每条看得到来处，随时能改能忘。**它写，你看。**
- **来自资料**：知识库读完某份资料后，把其中带出处的事实放进胶囊，句子自带"据资料《……》"。它不是第二个文件库。

## 4. 总体架构

总体架构分三层（原图 6，已不在仓库）：看得见的（一页看板、对话、对外接口）；控制面里的一个功能模块（写入、存储、召回、学习、分享）；派生与外部（语义索引、重排与嵌入、模型网关、运行时）。

分层规则：

- 控制面是一个标准功能模块：服务 + 路由 + 租约 worker + 一个总开关 `OPEN_SCIENCE_MEMORY_ENABLED` + 自己的迁移。关掉它，对话照常工作，记忆胶囊页隐藏。
- 运行时只有一个记忆端口：`capsule` 插件。它只认一个内部网关地址和一个工作负载令牌；地址没配就记一条降级、干净退出。
- 索引、重排、嵌入都是"外部服务"层：版本钉在 `deps-version.json`，有契约夹具，换供应商不换消费者。
- 抽取、扫描、蒸馏的模型调用一律走模型网关并进用量账本，标明用途（`memory-extraction`、`capsule-scan`、蒸馏走内核运行）。

## 5. 数据模型

### 5.1 事实表 `evimed_memory.records`（全系统唯一的事实存储）

| 字段 | 说明 |
|---|---|
| `user_id, id` | 主键 |
| `holder` | `own` 或 `pack:<packId>`。收到的包的条目也在这张表，靠它整包启停、永不并入本人事实 |
| `scope, scope_id` | user 时 scope_id 必须为空，CHECK 保证 |
| `kind, key` | key 是稳定的英文小写点路径 `^[a-z0-9][a-z0-9._/-]{0,254}$`，同一事实下次还会选到同一个 key；唯一键 `(user_id, holder, scope, scope_id, kind, key)` |
| `value` ≤100 000 字 · `summary` ≤2 000 字 | 用研究者自己的语言写；summary 就是页面上那一句 |
| `origin` | explicit · manual · inferred · system · source · import |
| `status` | active · pending · superseded · archived |
| `importance` 0–1 · `sensitive` | 敏感的照存、打标、永不自动调取、永不出门 |
| `evidence` jsonb ≤64 | `{sourceType, sourceRef, quote≤4000, observedAt, weight, fingerprint}`；sourceRef 形如 `sessions/<sid>/messages/<n>`；fingerprint = sha256(类型‖引用‖引文) 前 32 位，不含时间，同一句再次被引用不算新观察 |
| `revisions` jsonb ≤32 | `{version, value, summary, status, changedAt, reason, by: extraction·user·system, runId}` |
| `version` | 比较并交换；并发两次编辑不会悄悄丢一次 |
| `superseded_by, invalid_since` | 事实变了就取代，旧的留着 |
| `expires_at, last_confirmed_at` | 推断类 90 天不再出现就淡出，再次观察续期；你说的不过期 |
| `unscanned` | 仅 `holder=pack:*`：模型没判到的条目，可作上下文，不挂载 |
| `anchor` | 仅 `origin=source`：资料 id + 页/段锚点 |

旁表：

- `record_usage(user_id, record_id, used_count, last_used_at)` 加 `record_usage_sessions(record_id, session_id, used_at)`（每条保留最近 20 次），支撑"用过 7 次，上次 9月18日"和展开后的"用在这几次对话"。派生数据，可丢可重算。
- `settings(learning_paused, recall_paused, paused_projects[])`。
- `sessions(user_id, project_id, session_id, trial_pack_id)`：只为"试用一次"服务。

### 5.2 方法账本 `evimed_product.documents(kind=method)` + 修订表

一条做法一份文档，id `method:learned:<name>`。

- 正文是 SKILL.md：frontmatter（name、description ≤1024、whenToUse、role、applies_when、not_when、derived_from、depends_on: `name@sha256:…`）加七节正文（Purpose / When to Use / Inputs / Workflow / Verification / Constraints / Output），≤500 行。Verification 与 Constraints 两节只增不减。**医学事实不入方法**，方法只写怎么做。
- `contentDigest`：正文哈希。**正文一变，计数清零，状态回到候选。** 改写不继承前任的信用。
- `learning`：`counts{eligible, loaded, invoked, succeeded, validated, read}`、`observations[]`（按"运行:交付物"去重）、`relations[]`、`evaluations[]`（每条带被测 digest）、`level`（由依赖图推导，不信任自报的 role）。
- `provenance`：origin 恒为 inferred（学到的）、来源运行、反馈事件、`safetyRelated`。
- 状态：candidate → approved → retired，任何一步都是一条修订，回滚就是把旧修订向前保存。

### 5.3 包

- `documents(kind=pack-snapshot)`：我发出去的每个快照——范围、条目清单哈希、创建时间、是否撤回。
- `documents(kind=pack-received)`：我收到的每个包——签名者指纹、版本、扫描结果（通过 / 剔除清单 / 未判清单）、启用状态、启用范围（账号或某项目）。

### 5.4 其余

- `feedback_events`（只追加）：memory-inference-accepted · memory-value-edited · memory-rejected（原因 deleted / undone / archived / asked）。被你拒绝过的 key，除非你再次明说，抽取器不写回。
- 作业种类：`memory-record-index` · `distill` · `consolidate`（sleep / integrate / evaluate）。
- `memory_index_state`：每个发布单元的指纹与状态，用来判断要不要重发。

## 6. 写入：EviMed 怎么记下东西

### 6.1 什么时候写

每段研究结束时，在运行结束钩子里：先抽取记忆，再排学习触发。不写的五种情况：模块关、你暂停了、本项目暂停、试用会话、评测项目（按项目 id 前缀排除）。

### 6.2 读什么

- 只读 user 与 assistant 两种消息，外加知识类工具的成功结果；取最后 20 个来源，每条截 12 000 字。
- **按发送者做白名单，不按角色。** 平台往用户槽位里注入的任务简报、召回块、议程、方法、核对提示，全部带 `<evimed-*>` 标签；这份标签清单是域包里的一个闭集常量，有测试遍历源码树保证没有漏网的标签。含任何注入标签的消息整条不读。唯一例外是"用户纠正"外壳，剥壳后里面的话算用户原话。
- 被中断的消息、未完成轮次的消息不读。

### 6.3 一次模型调用

关思考、temperature 0、JSON 输出、≤12 个候选、上限 120 秒；已有记忆只送 key（≤60 个）让它复用。提示词只讲七条：

1. 用研究者自己的语言写，key 用英文，引文逐字照抄不翻译，不加任何前缀标签。
2. 画像类必须账号级、必须引用用户消息。
3. 报告里的数字和结论是报告的内容，不是记忆。
4. 工具结果和资料只能成为项目事实，来处记"来自研究"。
5. 针对手头这个任务的条件不是长期偏好（"这次只看近五年"不记；"以后都只看近五年"记）。
6. 平台自己的事不记。
7. 事实变了，用 `supersedes` 指向旧 key；用户说"忘掉/别再记 X"，输出 `forget` 指向那个 key。

### 6.4 代码复核（模型说了不算的部分）

- 引文必须是来源文本的逐字子串，否则丢弃。
- profile / preference / behavior / correction 必须引用 user 角色；explicit 必须引用 user；"来自研究"必须引用 assistant 或 tool。
- 文本命中平台标识闭集（工具名、契约名、内部文件名形状、运行记账词）的，拒收。
- `forget` 必须引用用户原话；执行为归档，并记一条 `memory-rejected(asked)`。
- 默认项目不写项目类事实。

### 6.5 生效

- **立即生效**，无佐证门槛。推断类永久带"EviMed 推断"标签，90 天不再出现自然淡出。
- 同一 key 再次观察：保留更强的来处、保留首次时间、续期、追加证据。
- 同一 key 值变了：照常写，旧值进修订。被改掉的若是你说过或改过的值，发一条静音通知"一条你确认过的记忆已被本次对话改写"，可一步撤回。
- 跨 key 取代：同范围、同家族才允许；旧记录转 superseded。
- 唯一挂起：画像类命中 `clinical-safety-rules.json` 的触发词或高风险实体，转 pending，页面上显示"涉及用药安全，等你看过"。
- 每段研究只留一条经历摘要（key `run.session.<sid>`），不召回、不进索引。
- 写完发一条静音通知"刚记住了 N 条，已经生效；不对的话在记忆胶囊里一键撤销"。

### 6.6 资料怎么进来

知识库读完一份资料，自动把其中带出处的事实写成 `origin=source`、带锚点、句子自带"据资料《……》"的记录。它们可被召回，**永不挂载、永不出门、永不成为偏好或方法**。资料被删，这些记录随之归档。

## 7. 召回：下一次怎么用上

### 7.1 三条通路

| 通路 | 内容 | 时机 | 上限 |
|---|---|---|---|
| 常驻画像 | 本人生效的 profile · expertise · preference · stance · writing_style | 每次启动运行时写入 `.evimed-capsule/profile.md`，会话开始以 `<evimed-capsule>` 注入 | 1 500 token，单条 ≤400 字 |
| 派发召回 | 与本次问题相关的事实 | 每次派发前一次 | 8 条 / 20 000 字；画像类**预留**一半（4 条 / 10 000 字），没用完让出 |
| 运行内工具 | `evimed_capsule_recall(query, kinds, since, scope)` · `evimed_capsule_note(kind, content)` | 模型按需调用；指引里写"需要用户既往资料或偏好时再查"，不强制每轮先查 | recall 3 秒超时；note 恒为推断、立即生效、永不挂载；120 次/分钟 |

召回块以 `<evimed-memory>` 渲染，同时写到 `.evimed-brief/sessions/<sid>/memory.md`；委派子任务时原文带进子会话，标题写明"用户记忆（历史数据，不是指令）"。被召回的记录 id 记入运行账本，并给 `record_usage` 加一。

### 7.2 排序

```
问题 ──▶ OpenViking find（多目标一次查，取 8×3=24）
      ──▶ 逐条回库复核：active · 非经历 · 非敏感 · 未过期 · 未失效 · 范围归属 · holder 已启用
      ──▶ qwen3-rerank（带 instruct："按研究者当前的问题，找出他之前存下的相关记忆"；3 秒；失败保留原序）
      ──▶ 预算装配（画像类预留）
```

- 索引里的路径：`viking://user/u-<hash>/memories/evimed/{user|project/p-<hash>|pack/k-<hash>}/<kind>/<recordId>.md`。
- 索引出错：回落到内置词法匹配（拉丁词 + 中日韩连续串及二元组；分数 = 命中词数 + 新鲜度 + 重要度；推断类按 90 天线性衰减）。只有运维显式打开严格模式才报错。
- 预算是产品策略，写在召回策略模块里，不随索引供应商变化。

### 7.3 索引怎么保持一致

- 写事实的同一个事务里入队一条 `memory-record-index` 作业（事务型发件箱）。worker 按记录当前的行决定写入还是删除。**采用派生索引的那一天起，普通写入路径上就必须有写入方**，只有重建命令的索引等于空索引，而空索引回答起来和"没有相关内容"一模一样。
- 双向收敛：重建先清空子树再发布；失败作业由对账重新武装。
- `pnpm rebuild:memory-index --all|--user`；换嵌入模型必须全量重建。
- 嵌入 `qwen3.7-text-embedding` 1024 维，经 DashScope；运行时容器不持任何供应商密钥。

## 8. 自迭代：EviMed 怎么学会你的做法

### 8.1 回路

原图 5（已不在仓库）画的就是这条链：研究结束 → 触发 → 提炼成方法文档（候选）→ 服务端裁决生效并标「新」→ 下次同类研究挂载 → 委派回执记下挂载摘要 → 交付结局归因到这条方法 → 夜间整理 → 后台配对评测只做降级。

### 8.2 四个触发器（全自动，不需要任何点击）

| 触发 | 条件 |
|---|---|
| 纠正 | 研究过程中你插话纠正了，或抽取器写下了一条 correction |
| 修复后通过 | 研究成功，且某份交付物提交了不止一次 |
| 交付完成 | 研究成功且有产物 |
| 惯例 | 同一科研工具第 3、6、9…次成功；带上最多 2 次同类的先前研究作对照 |

不触发：评测运行、主动科研运行、内部工具、你暂停了学习、试用会话、转录不完整。幂等键 `distill:<runId>:<trigger>`。

### 8.3 蒸馏

以一次有界的内部研究运行执行（工具 `method-distillation`，契约 `method-candidate`），读这次研究的转录窗口、最多 8 条相关的现有方法、最多 4 次同类研究；敏感消息直接丢弃并计数。它只能提出四种操作：create · amend · merge · no_change。产物的来处强制为"学到的"，它自己说什么都不算。

写给用户看的那一句必须是**观察到的行为**，不是规章："Meta 分析先报 GRADE 再报效应量（从你改过的 3 份报告学到）"。

### 8.4 裁决（定论：先生效，后评测）

- 候选由服务端按账本重新计算裁决，**当晚生效，标「新」14 天**。唯一的拦截条件是存在未解决的"与另一条做法冲突"关系。
- 修订过的方法回到候选，由当晚整理重新裁决。
- 配对评测在后台跑，是**降级信号**不是准入门槛：结论为"更差"且被测 digest 等于当前 digest，当场停用并写进最近变化；"无结论"不动。
- 评测成绩绑定被测 digest。开始评 A、期间改成 B、A 的成绩回来——这条成绩作废，不记到 B 头上。

### 8.5 归因

以委派回执里的"挂载摘要"为准，按交付物归因：一次过 / 修复后通过 / 被退回；没有结局的不计；挂载摘要与账本 digest 不一致的不计（那是改写前的文本）。"被调用"的定义是子会话里 skill 工具成功完成。不委派的问答线路只记"被读过"，够用来防止一条天天在用的方法被当成闲置。

### 8.6 挂载

每次启动运行时整目录重建 `capsule-methods/`，文件 0444。挂载三样东西：你学到的做法；已启用的包里的做法；每个已启用的包一份"标准与偏好"汇总文件（你自己的标准与偏好走常驻画像，不重复挂载）。预算 **32 条、32 KiB** 三者共用，已启用的包先占，学到的做法 ≤16 条。可挂载的谓词：生效 ∧ 已扫描 ∧ 在源头不是推断笔记。一条都没挂上而本应有，要在运行账本里留一条记录，不能无声。试用中的候选排最前且不被截断——否则一次悄悄量了两遍基线的评测会永远报告"无差异"。

### 8.7 夜间整理与停用

- 每项目每晚一次（22:00–09:00，时区显式配置为 `Asia/Shanghai`），只有一条方法也照常做裁决和停用检查，只跳过找关系这一步。找关系：最多看 40 对、分 6 组、每组 2–8 条；关系类型 shared_part · subset · merge · abstract_pattern · conflicts_with · supersedes；方法总数上限 100。
- 停用规则：

| 条件 | 处置 |
|---|---|
| 牵涉已确认的事故 | 立即停用 |
| 评测"更差"且 digest 相符 | 立即停用 |
| 挂载 ≥20 次且贡献 (成功−失败)/挂载 ≤ −0.1 | 提议停用 |
| 强度 Σe^(−天数/30) < 0.5、近期没被读过、且已被另一条生效方法取代 | 提议停用 |
| 标了安全相关 | 永不因闲置提议 |
| 生效总数超过 50 | 按贡献从低到高提议 |

- 预算：每日 ¥5、每周 ¥20、每次 ¥1，取它们与用户花费上限中的较小值；并发 2；余额为零只停学习，不影响研究。
- 通知全部静音：启用了一条做法 · 停用了一条做法 · 夜间整理有一次值得一看的变化（关系×10 + 生效×40 + 停用×20 ≥ 150 才发）。

## 9. 分享：把"我是怎么干活的"借给别人

### 9.1 包里装什么（定论：包是整个逻辑胶囊的快照投影）

导出时从三个来源现场装配，不依赖任何需要用户事先维护的条目：

| 范围 | 来源 | 进包的谓词 |
|---|---|---|
| 工作方式（默认，必含） | 生效的做法（方法账本）+ 事实表里的 preference · writing_style · tooling | 做法：生效且未牵涉事故。事实：active ∧ holder=own ∧ 非敏感 ∧ **（你说的 ∨ 你改过 ∨ 你确认过）** |
| + 个人背景（可选） | profile · behavior · expertise | 同上 |
| + 知识与项目事实（可选） | project_fact · decision · stance · tension · correction · follow_up | 同上 |

**永不出门**：推断而你没碰过的、来自资料的、敏感的、经历、别人包里的、任何原始对话和文件。上限 100 条、2 MiB。

### 9.2 容器 `.evimedcap`

zip；每个条目 AES-256-GCM（AAD 绑定路径与 Merkle 根）；包密钥按接收者用 X25519 + HKDF-SHA256 封装，或按口令用 scrypt(N=32768, r=8, p=1) 封装；manifest 经 RFC 8785 规范化后用 Ed25519 签名，带 Merkle 根与上一版哈希（版本链）。解密后是开放格式：`methods/<id>/SKILL.md`、`standards.jsonl`、`profile.md`、`knowledge/chunks.jsonl`、`provenance.json`（每条带来处）。

### 9.3 发送

一个折叠区「分享我的做法」：选范围 → **"对方会看到什么"按接收方视角实时列出**，每条可勾掉 → 设口令 → 下载文件。「我发出去的」列出每个快照，可推送新版、可撤回；撤回时页面复述"只影响之后的版本，已交付的收不回"。站内按用户名投递与一次性链接放第二期，接口先留。

### 9.4 接收（整包信任 + 自动扫描）

```
选文件 ─▶ 解密并预览 ─▶ 自动检查 ─▶ 收下 ─▶ 试用一次 ─▶ 启用 ─▶ 停用
```

1. **验签**。失败整包拒收。
2. **闭集检查（代码）**：平台标识、不安全链接协议、自动加载的图片、链接里夹带凭据。命中即剔除。
3. **"这条是不是在指挥助手"（模型）**：关思考、每批 20 条。模型打的标记必须能逐字引用该条目，否则这个标记作废。被判有问题的剔除。
4. 通过的写入事实表，`holder=pack:<id>`、`origin=import`；剔除的列在包上"看看剔除了什么"；模型没判到的带 `unscanned`，可作上下文、不挂载，下次启用时重扫。
5. **试用一次**：预先标记一个新会话，该会话只读这个包、不写你的记忆、不触发学习。
6. **启用**：只有一种借用模式——**参考**。对方的做法和标准生效，你的身份、课题、你自己的事实不变；你本次明说的 > 你自己的 > 对方的 > 平台默认。启用范围可选账号或某个项目；最多同时启用 8 个，彼此冲突时后启用的在前。toast 带撤销。
7. **停用**：整包退出，事实表里一条 `holder` 过滤的事，不留痕迹在你自己的事实里。
8. 对话里不加任何标识条。指引里要求模型在首次用到对方做法的回答里说一句"本次参考了《李主任的工作方式》"；试用会话的标题自动带「试用 ·」前缀。

## 10. 展示：一页

### 10.1 页面

路由 `/app/memory`，导航名「记忆胶囊」。布局（原图 1，已不在仓库）自上而下七块：一句定义 · 两个开关与重置 · EviMed 眼中的你 · 最近变化（最近 5 条）· 记下的内容（搜索 + 排序 + 五个筛选 + 三种行混排）· 收到的胶囊 · 折叠的「分享我的做法 / 导入胶囊」。展开一行的构成见第 10.2 节，发送与接收见第 9.3、9.4 节。

### 10.2 每一行的构成（定论）

- **一句中文**，就是库里的 summary 原文；「眼中的你」也只用已存记录的原文拼，不经模型改写，所以每句都点得回具体条目。
- **来处 chip**：你说的 · 你确认过 · 你改过 · EviMed 推断 · 来自研究 · 来自资料 · 我的做法 · 来自〈某人〉。
- **强度用次数**："在 4 次研究中观察到"。不出现百分比。
- **来自哪次对话**，可点回去。
- **用过几次、上次何时**；展开后列出"用在这几次对话"，每条可点。
- 状态标记只有三种：「涉及用药安全，等你看过」（配一个「是这样」）·「敏感 · 不会被自动调取」·「短期 · 某日前有效」。
- **依据与改动**（折叠）：最近 3 条逐字引文 + 最近 5 个版本，每个版本写明谁改的、为什么、何时；被取代的事实在这里显示为"**曾经如此**：……（3 月到 8 月）"，这就是你的变化与成长。
- 动作：改 · 忘记（归档，30 天可恢复，toast 带撤销）· 不对（仅推断类；删除并阻止再推断回来；这是全页唯一要二次确认的动作）· 撤销上次改动 · 恢复。做法行：停用 · 回到上一版。

### 10.3 搜索

一个框，250 毫秒防抖，服务端执行：关键词结果与语义结果取并集，搜句子、来源对话标题、项目名。命中行高亮命中词。排序可选最近使用 / 最近更新。

### 10.4 时间线

没有单独的时间线页。「最近变化」读时从已有账本派生（事实修订、取代、方法状态变化、包的启停），**没有第二个写入方，所以不会有"忘了写"的空洞**。事实类每条带撤销。

### 10.5 对话里的触点（定论：不加控件）

- 你说 → 被记下。"以后……""别再……""忘掉……"都在对话里完成。
- 模型说 → 首次按一条新做法或别人的做法执行时，回答里说一句，你回一句"不对"就是纠正，会触发学习。
- 写后提示只在记忆胶囊页以 toast 出现；收件箱里的相关通知全部静音，可点到具体条目。

### 10.6 样式与词表

- 跟随内核的字号、间距、色阶，控件用站内统一的开关、chip、折叠、toast，不为本页新造组件。
- 用户词表：记忆胶囊 · 我的做法 · 来自资料 · 忘记 · 停用 · 撤销 · 试用一次 · 启用。
- 不得出现在界面上的词：置信度、候选、approved、SKILL.md、YAML、digest、蒸馏、无痕、本次用到的背景、写一个方法、放进胶囊、采纳、我改过。由一条遍历前端源码的测试守住。

### 10.7 知识库页

一页一个文档列表，每行自带解析状态；"整理进度"只在有事要处理时出现一行提示；每行一个「所有项目可用」开关（个人资料库，只读挂载到每次研究）；折叠区「上传与浏览原始文件」。页头印着 3.3 的定义，与记忆胶囊互相指向。

## 12. 安全与隐私

- **投毒路径全部结构性封死**：发送者白名单（6.2）→ 只有用户原话能成为偏好（铁律 3）→ 资料只能成为带出处的事实（6.6）→ 收到的包验签 + 双层扫描 + 未判定不挂载（9.4）→ 运行时笔记永远洗不成方法（铁律 6）→ 推断而你没碰过的不出门（9.1）。
- 敏感内容：照存、打标、不召回、不进索引、不出门。患者可识别信息在资料入口处理，不进胶囊。
- 租户隔离：所有表以 user_id 为主键前缀；索引路径含用户哈希与项目哈希，回库复核再查一次归属。
- 运行时不持任何供应商密钥；嵌入与重排的密钥只在索引服务和控制面。
- 试用会话：只读、不写记忆、不触发学习、不计入方法观察。
- 每次包的启用、停用、导出、撤回写审计日志。

## 14. 建设顺序

每个里程碑都以**真实会话上的可观察行为**收尾，不以单元测试收尾；已有的回归评测（`evals/memory-recall`）作为回归检查保留，不新增决策性实验。

| 里程碑 | 内容 | 收尾标准 |
|---|---|---|
| **M0 地基** | 事实表 + 迁移 + CAS + 修订 + 取代 + 撤销；总开关；`/api/memory` 的读写；平台标签闭集与遍历测试 | 手工写入一条事实，改、撤销、再撤销，修订史完整 |
| **M1 写入** | 抽取器（输入过滤、模型调用经网关、代码复核、生效规则、forget、拒绝记忆、经历摘要、安全挂起）；写后通知 | 建成标准 1 的前半：说一句偏好，库里出现「你说的」一条，引文是原话 |
| **M2 召回** | 常驻画像、派发召回、预算与预留、词法匹配、`capsule` 插件两个工具、跨委派、`record_usage` | 建成标准 1 的后半：下一条对话照做，该条"用过 1 次" |
| **M3 索引** | OpenViking 适配、事务型发件箱、对账、重建命令、重排、契约夹具 | 建成标准 6；`memory-recall` 回归不低于现有数 |
| **M4 一页** | 记忆胶囊页七块、搜索、行组件、最近变化派生、知识库页定义与互指、词表测试 | 建成标准 2、5 |
| **M5 自迭代** | 方法账本、四触发器、蒸馏运行、服务端裁决、挂载、归因、夜间整理、停用规则、预算与窗口、静音通知 | 建成标准 3；学习看板上四个计数都不为零 |
| **M6 分享** | 导出装配（三来源投影）与预览、容器、验签、双层扫描、`holder` 启停、试用会话、指引里的那一句 | 建成标准 4，用两个真实账号走一遍 |
| **M7 后台评测与对外** | 配对评测接成降级信号（成绩绑 digest）；外部 agent API、key 管理、MCP 适配器；站内投递与一次性链接 | 一条被评为"更差"的方法当场停用并出现在最近变化 |

M0–M4 是一条串行主线；M5 可在 M2 之后并行；M6 依赖 M4 与 M5；M7 最后。

## 15. 总验收：一条链走到底

1. 新账号，对话里说两条长期偏好、一条只针对本次的条件。→ 库里两条「你说的」，没有第三条。
2. 开新对话问同类问题。→ 回答照两条偏好做；两条都"用过 1 次"，展开看得到是哪次对话。
3. 对话里说"其实队列研究也可以"。→「最近变化」出现"被新的替代"；旧事实在新事实的"依据与改动"里显示为"曾经如此"；点撤销，恢复原状；再点撤销，回到新状态。
4. 上传一份指南到知识库。→ 读完后清单里出现若干「来自资料」，句子带出处；它们不出现在导出预览里。
5. 完成三份同类研究。→ 出现一条「我的做法 · 新」；第四次研究的运行账本记着它被挂载、被调用；点停用，第五次不再挂载。
6. 导出"我的做法"。→ 预览里有那条做法和两条你说的偏好，没有推断的、没有资料的。
7. 第二个账号导入、试用一次、启用。→ 回答里出现"本次参考了……"；该账号自己的事实一条没多；停用后回答恢复。
8. 停掉索引服务。→ 对话照常，指标显示回落；恢复后对账把积压发完。
9. 关掉总开关。→ 记忆胶囊页隐藏，对话照常，运行时插件记一条降级后退出。

九步都留下截图、运行账本行和对应的库内记录，才算建成。
