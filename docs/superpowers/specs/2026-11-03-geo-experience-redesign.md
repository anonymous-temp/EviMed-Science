# 循证 GEO 体验重构：竞品调研与设计方案

调研日期：2026-11-03。本文是产品设计方案，不是已经完成的界面或已验证的实现。

## 1. 结论

把循证 GEO 从「三个分别成立的页面＋很多图表」重构为「一个项目、一个连续的工作区」。项目列表负责找项目；项目工作区负责当前目标、证据和下一步；AI 对话是同一项目中的一种工作方式，和当前资料、问题、回答、稿件与监测结果保持关联。八个步骤仍是唯一的业务主线，既可按顺序走，也可从诊断或已有稿件直接进入。

核心变化是页面关系和任务关系，不只是颜色、间距或换一套组件。默认呈现一个工作对象和其处理动作；复杂分析、历史与配置在有需要时进入。桌面优先横向组织，较窄屏幕使用同一上下文的单栏替换或抽屉，不能把三个 300px 窄列强塞进普通笔记本。

- **线上只读查看**：2026-11-03 在已登录账号中查看现有新项目的项目列表、总览、问题和诊断入口，以及分析下拉菜单；未创建项目、提交对话、启动采样、修改设置或部署。项目此前已有，当前没有完成诊断。

## 4. 我们现在到底乱在哪里

### 4.1 项目列表：列表和预览都在讲进度

左侧选中项目、右侧展示项目进度是可用基础，不需要推倒。但右侧既给「打开项目」「在对话中继续」，又有「继续当前工作」，并把 0/8 和八个「未请求」逐项重复。用户不知道应该选哪个入口，也容易把「0/8」理解为必须完成全部步骤。覆盖窗口和项目周数与真实监测是否开启是不同事实。

### 4.2 项目总览：堆满动作，反而没有工作区

标题与步骤、停测提示、筛选条、当前工作、按钮组合和「已有资料与结果」依次堆叠；同一件事被「在对话中开始」「补充产品与任务」「诊断/修改/制定方案」反复表达。新项目还未有数据时仍能看到分析入口。当前线上这一个空项目足以证明上述布局现象，但不能证明有数据项目的所有页面也完全相同。

### 4.3 诊断和分析：入口与结果不在用户预期的位置

点击「诊断」到准确与安全，开始诊断却在问题整理里；这是必要的题库准备与测量动作被分散，而不是八步不能共存。页面有全局 27 项「数据分析」，加上「分析视图」、当前步骤及范围筛选，用户必须先理解内部分类，再找想看的问题。准确性页面“未测”和“没有测到讲错”同时出现是明确的状态矛盾。

### 4.4 对话：跳转不断，输入框位置也不自然

此前线上是进入对话页面；新 main 已有结果＋原生对话分栏和底部收起栏，方向比硬切页好，但顶部八步、结果、栏位和大横幅并不自动构成清晰版面。并行规范的 DS23 要求页面底部 dock，而用户最新视觉反馈明确不喜欢全宽贴底输入。应对 GEO 的入口位置修订规范或提出模块例外，同时保留同一个原生会话、草稿、文件能力、权限与事件刷新。不能把静态草图里另画的 textarea 冒充真正接好的 AI 对话。

### 4.5 指标与动作的关系被藏起来

现有页面具备原题导入、分类建议、诊断启动、错误详情、信源、稿件、投放和监测等基础，但从「看到某个发现」到「选择处理、产出版本、看到观察变化」仍需要跨视图识别上下文。图表不缺数量，缺的是当前图表回答什么、和哪个对象相关、从哪里继续。

## 5. 三种可选结构

| 方案 | 描述 | 主要取舍 |
|---|---|---|
| A：保留现状做视觉整理 | 保留原来的入口、八步、多个分析菜单，仅修样式 | 改动小，但不能解决多套入口、长分析菜单和断裂问题。 |
| B：取消八步，按「分析/内容/监测」改主导航 | 接近通用营销分析 SaaS | 上手看似短，但隐藏了用户已确认的八步，也使按证据、旅程和稿件工作的定位变模糊，迁移成本高。 |
| **C：项目为中心的单工作区（推荐）** | 保留八步为唯一业务导航；对话作为工作方式；把分析、详情和操作安放回所属步骤 | 需要重排已有结果组件、调整原生对话栏位置与导航状态，但能继承已有业务对象和 URL。 |

## 6. 推荐的信息架构

```
循证 GEO
└─ 项目列表 ── 项目概览／继续当前工作
               └─ 项目工作区
                  ├─ 证据  → 产品资料、证据结论及出处
                  ├─ 旅程  → 人群、阶段及其信息需求
                  ├─ 问题  → 原题、问题群、测量版本
                  ├─ 诊断  → 一轮结果、回答、错误与竞品
                  ├─ 信源  → 引用来源、内容机会、目标和投入方案
                  ├─ 内容  → 问题关联稿件、版本、对话修订
                  ├─ 投放  → 稿件版本、渠道、预算、实际发布
                  └─ 监测  → 范围、轮次、趋势、变化与新发现

同一个项目原生对话可在任一步展开；总览是项目摘要，不是第九步。
```

- 八步是可点击的工作入口，不代表用户必须做满，也不等于后台必须按八步执行。初始只显示名称；真正排队、执行、等待用户或失败时在对应步骤标记状态。
- 正在查看的步骤与后台正在运行的步骤独立表达；例如正在浏览「诊断」时后台可继续写稿，不能把浏览位置切走。
- 现有 `overview / visibility / accuracy / questions / sources / actions / plan / evidence` 保留为兼容地址和内部组件，不再构成第二套同级导航。
- 地址保持项目、步骤、对象、轮次和筛选；返回、刷新与老链接打开同一个对象。安全边界、租户隔离、既有权限不变。
- 项目成果、知识库资料与 DSH 会话使用现有平台对象；不新建 GEO 知识库、稿件文件系统或独立记忆系统。

## 7. 三个主要版面

### 7.1 项目列表：找到项目并继续

桌面左侧为列表：项目名称、产品/适用场景（已有时）、一句真实状态、最近活动；选中后右侧预览只显示「当前在做什么 / 下一步 / 已有结果」。未请求的八步不逐个加“未请求”；只有与用户决策有关时显示进度摘要。新项目从一个明确动作开始，避免重复生成同名空项目；项目创建与会话创建的幂等和中断恢复需由实现验证。

预览的主操作统一为「继续工作」：未开始时到项目工作区并展示开始方式；已有未完成工作时返回原项目和对应上下文。对话作为同项目内可见方式，不能形成另一条身份不明的项目。已有项目仍可单击进入，列表与工作区通过相同投影显示状态。

### 7.2 新项目／项目总览：让用户马上知道怎么开始

桌面横向分为**项目准备／当前工作**与**AI 工作区**；准备区域最多显示现有记录能证明的产品名称、适用场景、材料状态与当前意图。尚未填写的资料可以自然语言说明或附文件，不强制创建新表单。任务入口只保留「诊断 AI 回答」「优化已有稿件」「制定方案」等真实意图，点击只填入同一对话草稿，不自动扣费或启动。

已有数据的总览改为一块主视图＋一块上下文面：主视图提供当前水平、变化与需处理发现；上下文面显示当前范围和下一件事。指标只放约定的核心数，点击可以打开原回答与样本；时间筛选和可比条件在这里完成周期回看，不另设复盘模块。没有数据时不画空卡片，不把项目周数说成已经监测的周数。

### 7.3 步骤工作区：对象列表与对象详情并排

桌面工作区采用「对象列表／所选对象详情」：例如诊断的左侧是待核查发现，右侧是完整回答、相关陈述、可适用证据和可做动作。信源左侧是域名或页面，右侧是该来源的引用和机会；内容左侧是稿件，右侧是正文版本、依据与发布状态。步骤切换保持项目范围和会话；选择某条记录后，“让 AI 处理”带入明确对象和版本。

大屏在空间足够时允许对象列表、详情、原生对话三栏；常见笔记本不强迫三栏。对话打开时缩起列表或在详情/列表间切换，保持至少一个可读的结果面；不足时对话覆盖结果并有明确返回。页面滚动不遮挡操作，手机按列表→详情→对话的同一路径前后切换。

**AI 输入的具体处理**：收起时入口放在工作区上下文中，以实际可用的内容宽度显示，不再在整个页面最下方横向拉满；打开时沿用既有原生对话和其输入框，保留同一 session 和未发送草稿。收起入口和展开输入不会同时出现为两个互相独立的 composer。具体宿主如何复用 `ConversationBar` / `WorkspaceSplit` 与 iframe，在实现前做技术样板验证；不能假设原生输入框能被随意抽取。范围不足的详情/只读用户只看到有权限的会话入口。

### 布局尺寸和折叠规则

下面是用于制作样板的初始约束，最终以真实浏览器、可读性和内容长度校验为准；计算的是除去平台侧栏、页面边距后的**实际可用宽度**，不是只看显示器总宽。

- 标题沿用平台 24px 角色、侧栏沿用现有宽度及用户保存值；项目标题、一步导航和一条必要的范围工具行优先合并，不额外堆叠多个状态条。新项目未请求的八项只显示名称。
- 可用宽度 ≥1280px，若用户同时打开详情和 AI，可放约 280–320px 的列表、至少 480px 的详情及至少 432px 的对话；未打开对话时将空间还给结果，不能填充无意义卡片。
- 可用宽度 960–1279px，默认列表＋详情；打开对话后显示详情＋原生对话，列表切换为可返回的选择面，保证结果和对话都可读。不能把三列一味缩窄。
- 可用宽度 <960px，显示列表、详情或对话中的一个主要面，通过清晰的返回和对象标题维持上下文；手机避免双滚动容器。所有宽度均需考虑长中文、放大字号和内核右侧面板，阈值只作样板起点。
- 同一时刻每个区域只出现一个主要实心按钮；用户必须立即处理的状态靠近其作用对象，常规运行状态不占满一整条醒目横幅。页内搜索和筛选靠近所筛选列表，未使用的高级条件收起但可发现。

### 三个版面的链接约定

- 项目列表行选中只改变预览；「继续工作」才进入同一项目的上次有效位置。新建项目进入同一项目准备工作区；会话初始化失败时保留项目并明确重试，避免再次创建。
- 项目概览的待办直接定位到对象；例如“某条回答的说明书适用人群待核对”直接打开该回答及证据，而不是仅跳到诊断页顶部。
- 步骤里的「让 AI 处理」带入当前项目、对象 ID、版本和可见范围，先填草稿；从对话返回时恢复对象、滚动位置和筛选。无权运行的用户仍能看已授权结果，不显示可执行按钮。
- 对话结束事件只刷新被影响的数据；用户正在看旧版时提示有新版本，不能静默替换。网络慢、失败或服务暂停时，不让页面看起来像项目空白。

## 8. 八步中每一步要实现的完整动作

| 步骤 | 主对象与默认内容 | 用户在这里能做什么 | 对下一步的交接 |
|---|---|---|---|
| 证据 | 产品身份、剂型/规格、适用范围、资料和证据结论 | 选择已有知识库材料、上传、查看原文、在对话中整理；显示来源及适用范围 | 给旅程、问句和医学核查提供有版本的依据。 |
| 旅程 | 患者/医生人群、阶段、信息需求 | 查看/完善人群与场景，选择某阶段的问题 | 把阶段关联到已有问句，不伪称模型生成问题均是真实用户问法。 |
| 问题 | 原题、编号、原分类、平台建议、版本 | 导入、预览、确认字段、核对重复、选择测量范围；AI 分类建议须保留原题和客户分类 | 显示版本、平台、题数、调用量和可能费用后启动诊断；按项目约定决定是否重复采样。 |
| 诊断 | 一轮采样、分平台结果、原回答、医学说法 | 在同一入口查看提及/推荐/准确性，进入某个回答核对依据，筛出待处理发现 | 将具体发现、对象及范围带到信源方案或内容任务。 |
| 信源 | 引用域名/网页、对应问题、来源类别和可选方案 | 看某个来源或问题群，查看内容缺口；基于已有数据拟定目标、渠道和投入情景 | 将选定的依据和目标传给内容与投放；目标是情景，不是承诺。 |
| 内容 | 稿件、对应问题、原文及版本、依据 | 用同一 DSH＋DeepSeek 对话生成或修改，打开/下载结果；切回时能找到同一文件 | 将明确的稿件版本交给投放；新稿与已发布版本分开。 |
| 投放 | 渠道、预算、订单/外链、状态 | 能力和权限允许时安排；外部发布事实由可核查记录表达；预算在这里或方案里设置 | 将发布对象、版本、时间和渠道交给后续观察。 |
| 监测 | 监测范围、轮次、趋势、变化和发现 | 显式开启、暂停、停止未来计划、筛选和查看原回答；记录已受理工作与计划的区别 | 把新发现带回证据、信源或内容；结果比较留在总览与监测。 |

输出既可用于完整方案，也可只完成用户明确请求的一部分；不能在没有许可时因为点击导航而自动采样、投放或发送。

## 9. 27 个分析视图如何归位

当前 27 项是已有代码注册的视图，不等于每项已有完整真实数据。入口按“用户正在解决什么”放到对应步骤，跨步骤仍可通过总览钻取，而不是全删除：

| 归属 | 视图 |
|---|---|
| 总览／监测 | V01 当前水平与目标、V02 指标趋势、V03 可比变化排序、V27 事件与采样观察。 |

| 诊断 | V04 平台指标、V08 竞品趋势、V09 推荐表达、V11 采集与判定覆盖、V12 正确性、V13 错误类型与严重程度、V14 临床主题条件、V15 处理历史。 |

## 10. 状态和数据真实性规则

1. **未测**：没有有效采样/判定时只显示「尚未测量」及可开始的方式，不能出现「没有错误」「100% 准确」「排名第零」。
2. **已测且为零**：需存在有效样本及适用判定，显示「在已核查的 N 条中未发现……」并可查看范围；筛选无结果则说明“当前筛选下没有记录”。
3. **部分/失败/暂停**：显示有效样本、失败/未返回、范围、刷新时间和能执行的恢复动作；展示保留结果，不把失败补零。监测服务暂停、用户未启用、部分引擎暂停和当前任务失败是不同状态。
4. **比较**：轮次、题库版本、引擎、采集方式、周期和可用样本不一致时显示不可直接比较或变化条件；不要暗示因果关系。
5. **医学结论**：产品/SKU、剂型、适用条件和证据版本必须随对象显示；“AI 判断”与已确认结论分开，必要时保留人工复核，不把品牌宣传材料自动当医学事实。
6. **建议与发布**：建议只代表基于当前数据的下一步；点击“让 AI ……”只准备草稿，点击“开始……”才执行，外部发布和费用按现有权限及交互约束处理。

## 11. 关键用户旅程与验收

### 旅程 A：第一次做诊断

进入 GEO → 新建或继续项目 → 说明产品、场景并附材料 → 导入或让 AI 协助整理问句 → 核对原题、引擎、采样规则和调用量 → 明确开始诊断 → 看到运行及部分失败 → 打开一次回答和依据 → 生成具体处理建议。每次跳转保留项目、题库版本、轮次和上下文；返回不重新创建项目，不重复提交。

### 旅程 B：已有稿件直接修改

打开项目 → 从内容进入现有稿件或附上文件 → 在原生对话中提出修改 → 查看并下载新版本 → 返回内容查看版本与原稿关系 → 如需发布，明确选择具体稿件版本。无须先跑完八步，不创建单独 GEO 编辑器。只有存在多个可能目标而无法区分时才要求选择对象。

### 旅程 C：监测发现触发后续工作

打开总览 → 日期筛选查看同口径变化 → 进入一条新发现 → 查看原问句、AI 回答、判定依据及引擎 → 发起信源分析或内容修订 → 看见处理结果与版本 → 返回监测观察后续结果。趋势相关不自动证明某次投放产生效果。

### 反例与交互验收

- 直接打开老链接、浏览器前进/后退、刷新、切项目，仍指向正确项目、步骤、对象、轮次和已选择范围；不存在的对象有明确恢复路径。
- 空项目、单步项目、执行中、已停止、已暂停、部分成功、无权限、无测量和有结果但筛选为空分别检查。原生对话仍能加载、输入、附文件、暂停运行并回到结果，草稿不丢；只读角色无写操作。
- 测量状态未知时不把诊断判成成功；点击准备草稿不发请求、不启动测量；费用或重复采样只能由清晰动作触发。
- 验证 1440×900、1366×768、1180 附近、1024 和 390×844，平台侧栏展开/收起以及用户保存宽度；无横向溢出、遮挡、死角或空白错误状态；键盘、焦点和深色模式可用。
- 用真实 DSH＋DeepSeek 跑 A/B/C 各一条，真实监测只在有条件且获授权的独享测试环境中执行；模拟数据图、组件测试、真实服务和线上部署各自单列证据。之前并行会话中 GEO producer 未派出、停止真实运行及 403 的问题仍需按本轮实际环境复核，不以原型或通用会话取消代替。

## 12. 底层能力与界面的边界

项目的八步是业务任务与结果的可见入口；原有 GEO skills、能力包、工具和执行器是实现这些任务的方法。用户不需要先挑选 51 个技能才能开始，也不应由页面根据关键词假装某个技能已经执行。发起的任务、调用到的方法版本、运行/失败、使用的材料和产生的文件应沿用平台现有执行记录；对用户首先表达“正在做什么、产出了什么、哪里需要处理”，按需展开执行详情。

GEO 继续使用已有共享知识库、项目记忆、方法学习与受控自迭代；是否能写入、下次能否实际读到以及租户和项目隔离，要通过具体记录和真实任务验证。连接函数、存在 skill、计数增加或文档里的预期，都不自动证明形成了学习闭环。本次设计没有重新逐个核验全部线上 skills 的准确性，也不声称它们都已修好。

## 13. 与现有代码对接及顺序

1. **P0 设计与状态基线**：记录线上当前版本与 main 差异；修订 GEO 页面对话入口的 DS23 适配；先复现未测/已测零/失败的状态矛盾。设计器只画案例数据，避免把虚构数值当真实测量。

## 14. 需要视觉样板解决的问题

文字线框不能证明页面好看，也不能证明操作走通。正式实现前，至少需要四种同一套视觉语言的样板：项目列表、未开始项目、已有数据的诊断详情、展开原生对话时的诊断工作区。每张都需包含正常、空、部分失败和窄屏中的代表状态；再对照用户提出的「上边挤下边空」「不要一长串上下堆叠」「输入框不要贴底拉满」检查。样板要明确标示示例数据、模拟交互和未连接的能力。
