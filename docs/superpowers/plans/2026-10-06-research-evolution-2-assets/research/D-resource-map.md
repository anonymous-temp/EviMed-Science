**Digest (read this, then the sections you need; the file is long because every claim carries file:line or the grep that found nothing)**

1. *External resources.* One pipe brings published literature into the platform: knowledge-source plugin -> `evimed_frontier.entries/items` (platform scope). Evolution reads only its `published` change stream (25 per tick, inside a scout job, <= 8 scouts a day) and makes its own Europe PMC/Crossref calls; the learning loop reads no external resource. Supplements stay in a run's workspace unless handed to the project library.
2. *User queries and outputs.* Stored per user/project only: a 160-character question preview and route reason in `runs.jsonl`, the full transcript per run (90 days), memory records, result versions. There is no platform-level store of queries, routing verdicts, `choice:` overrides or unsupported requests (the public topic-request list is the one user-authored platform record; the programme reads its counts); closed gap codes (`runtime-gap`, `autopilot-gap`, `handbook-gap`) are the only tenant-to-platform currency besides 5-reader-floor counts and gated text-only handbook lessons.
3. *Flywheel objects* (cards, change log, source-change fact, predictions, question bank, public pages) are platform-owned (`evimed_frontier`, publisher account `evimed-evidence-center`, project `evimed-evidence`, purposes `evidence` / `evidence-upkeep`); platform cards re-enter the frontier through a feed the plugin polls; corrections/withdrawals return to learning as `evidence-incident` documents.
4. *Loops closed in code at R:* evolution (tools only), account-level learning (harm test, rollback), GEO (measure -> error -> action -> re-measure), autopilot (rule verdicts), evidence upkeep (currency labels, challenges, retirement). *Constants + manual eval harness only:* frontier editor/threshold, routing, KB/data semantics, memory extraction, review, planner prompt.
5. *Inputs with no producer at R:* prediction registry extractor, recalculation `comparison`, `communication`/`virtualStudy` lead offers, `evals/evidence-incidents/cases/`.
6. *Budgets (CNY/day):* evolution 50 (run 10), frontier 10, GEO 20, evidence programme 30 (episode 10, challenges 5), agenda defaults 100/500/3000, learning and all account caps 0; nearly every platform-feeding module is off by default.

Two ledgers recur everywhere, so they are named once here:

- **Product ledger** `evimed_product.documents(user_id, kind, id, project_id, payload jsonb, revision)` + append-only `revisions` + leased `jobs`
  (`S/productPersistence.mjs:73-165`). Kinds are a closed list (`PRODUCT_KINDS`, :4-22: capsule, fact, method, source, source-unit, knowledge, profile,
  agenda, episode, digest, notification, preferences, plugin, price-list, method-trial, document-export, result-version, result-impact,
  result-revision, result-replay, extension kinds, dataset-semantics, source-change, programme-decision). Every row is owned by one `user_id`; platform
  modules store platform records under an operator or the publisher account (evolution: first of `OPEN_SCIENCE_OPERATOR_USERS`, project `EVOLUTION_PROJECT_ID`).
- **Run ledger** is not a table: `<project.metaDir>/runs.jsonl` per project (`S/agentRuns.mjs:130,186`), capped at 1000 runs / 1 MiB (`:153-154`).
  It keeps a 160-character `question` preview only (`:206,344`); the full brief is "held in memory ... Never serialized" (`:345-348`).

## Part 1 — Resource pipes

### 1. Published papers and supplements

**Produced / stored**
- External: the knowledge-source plugin (`evimed-knowledge-plugin`, its own service and database) is pulled by `seq` cursor; "the platform pulls and never pushes"
  (`S/knowledgePluginClient.mjs:13-17`). The only platform-to-plugin call is `POST /v1/lookups/${capability}` (`:711`); there is no source-request or
  "please add this source" channel (grep `source[-_ ]?request|sourceRequest|requestSource|suggest.*source` in `S/`: only unrelated kernel `sourceRequestId`).
- `S/frontierIngest.mjs:431` `INSERT INTO evimed_frontier.entries ... ON CONFLICT (plugin_entry_id, revision) DO NOTHING`, cursor in `evimed_frontier.meta`
  (`plugin_cursor`, :421-447) in the same transaction. Pipeline then promotes an entry to `evimed_frontier.items` (`S/frontierPersistence.mjs:152`: scores,
  `entity_keys`, `verification`, `editor_version`) with its text in `item_texts` (`:239`: `abstract_raw`, `body_excerpt`, `model_input`, `publication_types`, `mesh`),
  Crossref/PubMed notices in `item_links` (`:264`, kinds retraction/correction/expression-of-concern/withdrawal/preprint-of/new-version), and every reader-visible change
  as an `item_changes` row (`:389`, `seq`, `op`, `reason`).
- Run-side papers: a run's fetched sources are preserved in its workspace (`.evimed-sources/`); `publicSourceGateway.mjs` is a stateless egress boundary (host allowlist
  `S/publicSourceGateway.mjs:10-80`, named download `epmc-supplements` = Europe PMC supplementary-file zip `:628-632`) that stores nothing; only
  `S/sourceIntakeHandoff.mjs:35-43` turns preserved files (supplements, registry results) into project sources under `knowledge-base/open-access/<group>/`
  (`INTAKE_FOLDER`, max 40 files, "a paper's supplements, not a corpus").
- Owner scope: frontier tables = **platform** (no user column; `items`/`entries` carry no tenant). Run-preserved papers and handed-off supplements = **project/user**.

**Consumed by evolution**
- The frontier change stream is read by `EvolutionFrontierSignals.tick()` (`S/evolutionIntegration.mjs:340-370`), only when `config.frontierEnabled` (`S/evolutionComposition.mjs:336`)
  and only from inside a scout job (`:349` `scout: async (payload, context) => { await frontier?.tick(); return scout.scout(payload, context); }`):
  `SELECT c.seq, i.id, i.title_raw, i.canonical_url, i.published_at, i.identity_key, t.abstract_raw, t.body_excerpt FROM evimed_frontier.item_changes c JOIN ... WHERE c.seq>$1 AND c.op='upsert' AND c.reason='published' AND i.state='published' ORDER BY c.seq LIMIT 25` (`:355-358`),
  then `this.integration.publish({ id: \`frontier:${row.seq}\`, type: "frontier-publication", paper, origin: "literature" })` (`:364`).
  First look = present only, look-back capped at `EVOLUTION_FRONTIER_LOOKBACK_MS = 3 * 86_400_000` (`:332`).
- A `frontier-publication` event does three things (`:124-127`): `temporalObservation` (records `evolution-temporal-*` observations per active tool: eligible for the time-holdout only if
  `earliestPublic > modelReleased && earliestPublic > frozen`, `:276-299`), `matchProspectivePublication` (exact preregistered target identity, `:255-273`), and
  `scoutPublication` (`:145-164`): one scout job per paper, at most `evolutionMaxPaperScoutsPerDay` (8) per 24 h, never ahead of an admitted build/evaluation.
- Evolution also reads the literature directly, not through the feed: `measureEvolutionLiterature` re-queries Europe PMC `FIRST_PDATE:[24 months] AND SRC:MED`, `pageSize=5`
  (`S/evolutionScout.mjs:43-60`), reference-case curation fetches Europe PMC search + `fullTextXML` (`S/evolutionReferenceCuration.mjs:74,82`), temporal gold likewise
  (`S/evolutionTemporalGoldCuration.mjs:74,82`), publication identity via Europe PMC/Crossref (`S/evolutionPublicationIdentity.mjs:34,45`), decision refresh via Crossref
  (`S/evolutionComposition.mjs:168`). The scout run itself is a kernel run of capability `evolution-scout` ("Search current primary literature for frequently used research methods in the last 24 months", `S/evolutionScout.mjs:82`).
- Supplements: not consumed. grep `[Ss]upplement` over `S/` and `D/` finds only the download kind, the intake hand-off, `sourceMaterials.mjs:211-313` (supplement references in a source's structure summary) and the unrelated "handbook supplement" (owner-scoped capability text).

**Consumed by the learning loop:** not consumed. `git grep -E '[Ff]rontier|europepmc|literature' f394c3b33 -- S/learning*.mjs S/method*.mjs S/handbook*.mjs S/capabilityHandbooks.mjs` returns nothing.

### 3. Real user queries and follow-ups

**Produced / stored (owner scope: user + project; nothing is platform-wide)**
- Run ledger `<project.metaDir>/runs.jsonl` (see top): question **preview only** (`S/agentRuns.mjs:206-215,344`, 160 chars), `effectiveAgentId`, `effectiveRouteReason`, `corrections` counter
  (`:539`, steer saturates at `MAX_RUN_CORRECTIONS = 3`, `:180`), status, `verification`, notices, artifacts. Route reason is a closed-format string, `routeReasonPattern = /^[a-z][a-z0-9_.:-]{0,63}$/` (`:166`):
  `choice:<id>`, `session-binding`, `matched:...`, `llm:0.87`, `unrouted:open-domain[:classifier:<code>]`, `adopted:runtime-ui[:...]`, `autopilot:...`, `platform-evolution`
  (composed at `S/server.mjs:5981-6027`; failure provenance by `classifierFailureReason`, `S/specialistRouting.mjs:143`).
- Full conversation: one transcript file per finished run `<metaDir>/transcripts/<run>.jsonl` (`S/runTranscripts.mjs:44-60,106-111`: 8 MiB cap, 90-day retention, `completeness` + `missing[]`), written in the finish hook (`S/server.mjs:3298-3322`), plus child sessions.
- The routing classifier keeps nothing: `SpecialistClassifier.classify` returns `{agentId, confidence, reason:"llm:0.xx"}` or null and meters one `routing` call (`S/specialistClassifier.mjs:138-146,193`); its "none" verdict is held only in a per-call `trace` (`S/server.mjs:5985`).
  `POST /api/routing/decision` "decides nothing, refuses nothing, and records nothing" (`S/routingDecision.mjs:24-30`).
- Memory extraction (`S/memoryIntelligence.mjs`) writes `evimed_memory.records` (see 6). Reader interest: `frontier.profiles.noteConversation(userId, run)` (`S/server.mjs:3033`) marks the reader's 「与你相关」 profile due; the profile keeps at most ten phrases per reader with provenance
  `memory | question | frontier-item` (`S/frontierProfiles.mjs:24-39`, table `evimed_frontier.user_profiles`).
- Open-domain answers: the `open-domain-answer` line leaves no file; its trace is the transcript, the ledger row and (if it cites or names a medicine) one `evimed_review.reply_checks` row (`S/server.mjs:3404-3409` -> `review.service.considerReply`).
- Unsupported requests: **no record of "a request the platform could not serve".** The only closed-code traces: `runtime-gap` when a run fails with `errorCode === "runtime_tool_error"` (`S/server.mjs:3095-3098`, `S/evolutionIntegration.mjs:35`),
  `autopilot-gap` when the planner stops with a `resourceNeed` (`S/autopilotService.mjs:2091`), `handbook-gap` when >=2 runs of one account's handbook observed `method-missing` (`S/evolutionLearningCoupling.mjs:15-21`), `evaluation-gap` (`S/evolutionEvaluationGaps.mjs:30`).
  (grep `unsupported[-_ ]request|unmet[-_ ]demand|demandGap` over `S/` and `D/`: nothing relevant.)
- Corrections/steer: the steered text is not in the ledger (only the count); the text is in the transcript; a result correction (`result-corrected`) is a row of `evimed_product.feedback_events` (`S/feedbackEvents.mjs`; triggers `FEEDBACK_EVENT_TRIGGERS` = memory-inference-accepted, memory-value-edited, memory-rejected, deliverable-adopted, deliverable-edited, result-corrected, `S/productPersistence.mjs:43-51`) carrying the immutable original/successor result-version pair.
- Flywheel "question bank": the platform's **own** medication questions, not user queries: 60 questions = 10 classes x 6 (`D/geo/question-bank.json`, version 1), held as a locked question set of an internal GEO project of the publisher account (`S/geoQuestionBank.mjs:99-123`). User demand enters the flywheel only as counts: public topic requests + votes (`evimed_frontier.evidence_topic_requests`, `S/evidenceZonePersistence.mjs:195-205`; the one platform-level, user-authored record: a title any signed-in account may file, <= 5 a day; "the titles are matched to entities in code and never shown to the model", `evidenceProgramme.mjs:15-19`), page reads per card/day (`evidence_page_reads`, :189), zone follows, and distinct readers whose profile holds an entity (floor `OPEN_SCIENCE_EVIDENCE_PROGRAMME_MIN_DEMAND_USERS` 5, `C:428`).

**Consumed by evolution**
- Run failures: `evolution.integration.publish({ id: \`run-gap:${project.id}:${run.id}\`, type: "runtime-gap", gapCode, code: gapCode, track: "M", origin: "platform-inference" })` (`S/server.mjs:3097`) — only for non-internal projects and only `runtime_tool_error` (`evolutionRunGap`, `S/evolutionIntegration.mjs:35`: "Only the one closed code that names a tool or engine the run could not use is a gap").
- Feedback events: `server.mjs:1270` posts `type: "researcher-feedback"` to evolution; `EvolutionIntegration.consume` -> `observeFeedback` (`S/evolutionIntegration.mjs:77-80`, `S/evolutionFeedback.mjs:10-36`) turns adopted/edited/corrected into `accepted | repaired | rejected` observations **only on platform tools the run invoked** (`row.payload.toolId` from `use` records).
- Handbook gaps (above). Query text, routing reasons, the classifier's verdicts, steer text: **not consumed** (grep `effectiveRouteReason|routeReason` over `S/runMetrics.mjs`, `learningTriggers`, `evolution*`, `availabilityObservation`, `memoryIntelligence` finds only `evolutionRuns.mjs:94` stamping `"platform-evolution"`).

**Consumed by the learning loop**
- Transcript (retention 90 d) is the raw material of distillation. `learningTriggersFor` (`S/learningTriggers.mjs:230-314`) queues `correction` when `steered > 0 || extracted.length > 0` (`:250-264`), `repair_accepted`/`delivered` for a delivered run (`:269-283`), and `routine` at every Nth (N = `METHOD_INDUCTION_MIN_TRAJECTORIES = 3`, `D/constants.mjs:45`) successful run of one capability across the researcher's own projects within a 90-day period (`:285-311`). Answer-line runs are excluded (`routineCapability` returns null for `open-domain-answer`, `:131-135`).
- Routing reasons and the open-domain question text: not consumed.

## Part 2 — Existing small loops (signal -> change -> evaluation -> release)

Common pattern outside evolution and learning, stated once: the "change" is an edit of a **constant in code** (prompt text, threshold, vocabulary), the "evaluation" is an operator-run harness under `OpenScience/evals/<module>/` that calls the live model through the module's shipped class and commits a result JSON (principle 6, "every incident becomes an eval case"; control arm = another copy of the module via `--editor`), and the "release" is a code release. No worker triggers an eval and no policy is stored as data with a version and an arm. The server reads nothing from the committed results; the two exceptions are evolution, which imports `evals/paper-gold/*` as library code (`paperGoldEvaluator.mjs:14-18`), and the opt-in learning evaluation command whose stdout it reads. Every "missing" below is relative to that.

**1. Research tools / capabilities + evolution** (the one module that closes a loop on its own, behind `OPEN_SCIENCE_EVOLUTION_ENABLED`, default false, `C:2640`)
- Signal: frontier `published` stream (`evolutionIntegration.mjs:340-370`); module leads (`evolutionLeadSources.mjs`: evidence-programme `no_engine_receipt` only); `runtime-gap` (`server.mjs:3095-3098`); `autopilot-gap` (`autopilotService.mjs:2091`); `handbook-gap` (`evolutionLearningCoupling.mjs:15-21`); `dataset-ready` (`:67-73`); `researcher-feedback` (`server.mjs:1267-1272`); daily literature scan job (`evolutionWorker.mjs:121-122`).

- Evaluation: independent candidate evaluator on hidden reference cases curated from Europe PMC full text with an independent reviewer of another model family (refuses with `evolution_review_unavailable` when `reviewProvider` is DeepSeek, `evolutionComposition.mjs:134,151,160,179`); weekly time-holdout and scorer audit on Monday (`evolutionWorker.mjs:139-140`); release replay of every active tool per release (`:115-119`, `evolutionComposition.mjs:355-370`); prospective scoring; per-tool sequential harm test, one trial per account, <= 40 trials, "`harm` proposes; it does not retire" (`evolutionMaintenance.mjs:7-37`); monthly metrics record (`evolutionMetrics.mjs`).

## Cross-module facts the maps above rest on (no interpretation)
