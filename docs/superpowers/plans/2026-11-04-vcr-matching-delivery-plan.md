## 1. 目标和已定的原则

目标：把「患者匹配」做到可以直接交付，并在公开基准上用官方数据、官方评分脚本证明成绩。

业主 2026-11-04 已定：

1. 被测对象是 EviMed 的功能本身，分数只从功能保存的结果算。DeepSeek 是功能内部的模型，不单列实验组。
2. AI 算法驱动，不靠规则驱动，不做过度安全拦截。模型做语言判断，代码只做精确运算和工程边界。
3. 病历没写的条款由模型逐条判断，页面标「未见记载，按未排除」或「未见记载，需确认」。
4. 只做匹配，不做运营（联系患者、转诊、中心管理）。这与 2026-10-25 的决定一致。
5. 原生版先行：DSH + DeepSeek 打底，每加一样东西都要在调试集上证明有用。
6. Jev、重排模型和知识库作为插件协同工作。

这次调研改变了三件事：

- **不用自己造打榜工具。** TrialGPT 2.0 官方仓库 `TrialGPT2/TrialGPT2.0`（commit 1c5f9ebc3b98，美国国立医学图书馆，公有领域）公开了提示词、SIGIR / TREC 2021 / TREC 2022 / NIH-TrialBench 四套数据和评分脚本。功能的结果转成它的 `full_email_<patient_id>.json` 格式，直接用官方脚本评分。
- **官方提示词就是 AI 驱动的范本。** 它没有规则引擎，只有一段提示词，问的正是「好病历可能漏写吗」。常规化验、ECOG 缺失时不降分、只降把握度；诊断、分期这类前提缺失才降分。
- **不能预设代码判定一定差。** 斯坦福 VERDICT（commit a56e3ed09f10，Apache-2.0）让模型转写条款、求解器判定，F1 高于纯语言模型，错误主要来自「病历没写」的处理（31/59），转写错误只占 2.8%。所以保留一个“模型读、代码算”的对照组，由数据决定。

## 2. 现状

**能用的部分：** 一位患者、一段短文本、20 个以内的英文试验可以走通，每位约 ¥0.6–0.9、6–8 分钟。这只在冻结的 TREC 集合上测过，线上注册库没量过。结论几乎总是「证据不足」，基线 53 人只完成 31 人。

**不能交付的部分：** 用一份方案筛一批患者。300 份病历进不来，语言类条款没有批量路径，结果也导不出去。

| 级别 | 缺口 |
|---|---|
| 阻塞交付 | G1 没写的条款无路可走；G2 批量没有语言判断；G3 300 份病历进不来；G4 PDF/Word 不算患者记录；G5 追问会变成新患者，补事实不重算；G6 跑失败显示成“还没找过”；G7 表格里的 0/No/否 被读成“有”，造成错误淘汰；G8 没有导出；G9 页面只列 50 人、没有逐条漏斗；G10 ChiCTR 没有入排原文 |
| 削弱效果 | G11 线上深度只有 20；G12 排序不看相关性；G13 定位不到的条款被强制判未知；G14 完整度写死、一条坏条款丢掉整个试验；G15 不跟踪注册库变化；G16 失败显示为成功；G17 思考关闭、输出 2,000 token；G18–19 规模和长病历；G20–21 FHIR/OMOP/ADaM 只用了 subject 表；G22 10 人以下计数对模型隐藏；G23–24 页面不能启动、看不到进度和费用 |
| 打磨 | G25–29 理由字段、手机端表格、跳转链接、过时注释 |

**过度拦截的现状（业主认为是缺陷）：** 任何一条未知都不能算符合；定位不到的条款强制未知；一条坏条款退回整个试验；小格计数隐藏；扫描件被拒。

**已知风险：** 用 TrialGPT 原提示词时，Flash 的错放（信息不足判成有利）是 152 条，GPT-4 是 16 条。放开「病历没写」之后要盯住这个数字。开思考能否压下来，还没测过。

**还没解决的中文缺口：** 中文 ICD-O 文件、中文化验项目标准（LOINC 中文版除外）。

**接入原则不变：** 全部作为工具或上下文，查不到不阻断；每个来源都按第 6 节在调试集上证明有用才留。

## 4. 目标架构

```
对话（DSH + DeepSeek Flash，思考 high）
  理解需求 → 查知识、写检索词 → 发起作业 → 复核关键淘汰项 → 回答追问、补资料后重算
      │
      ├─ 检索插件：注册库 / 冻结集合 → 混合检索 → 重排（DashScope、Jev，按实测启用）
      ├─ 判定作业：患者 × 试验，两个方向同一个作业
      │     整体评估（匹配分、把握度、符合 / 不符合 / 缺失理由）
      │     逐条判定（标签、理由、证据句号，只对排名靠前的试验）
      ├─ 知识插件：术语、定义卡、说明书、指南、计算器，模型按需调用
      └─ 代码：切句和切条款、核对句号并回填原文、算术复算、保存、权限、预算
```

**模型决定：** 是否符合、病历没写怎么算、推断是否成立、相关性、检索词。

**代码决定：** 句号是否存在、原文回填、单位和日期算术、分数合成、权限和预算。代码发现矛盾只打标签，不改结论、不拦截。

**结构化表格筛人群** 保留现有规则引擎，这里规则本来就对。

**结论分四档：** 符合、可能符合（无冲突，列出待筛查确认项）、证据不足（诊断等关键前提不明）、不符合（有明确冲突及证据）。

**这些数字该怎么读：**

- **榜 A 是最干净的一张：** 同样的数据、同样的脚本、同样的对子。结论是与 TrialGPT 2.0 最好的版本统计上持平，点估计略低于 GPT-5.4 和 Gemini-3.1。对方的数是从论文图上读的，没有区间。花费 ¥161.7，约 ¥0.0022 一对。
- **榜 B 的 88.1% 不能说成判定模型比 TrialGPT 强。** 论文给所有配对打分，我们走产品路径：先重排取前 100，再判定。只用重排，Recall@10 已经是 86.5%，前 100 名没有漏掉任何目标；判定只再加 1.6 个点，Recall@1 反而从 43.7% 降到 36.5%。没有发现泄漏（打乱顺序的对照 0.8%，随机预期 1.3%）。这个数说明产品路径的效果好，也说明这张榜的搜索空间小（每例中位 747 个候选）。如要与论文严格同协议，还要再跑约 ¥370。
- **榜 C 低于 GPT-4，而且是在调过提示词的数据上。** 三版提示词都在这 1,015 条上调过，数字偏乐观。这份金标准又是专家看着 GPT-4 的输出标的，偏向 GPT-4。两点方向相反，不能抵消，只能都说清楚。错放 98 条是“病历没写就按未排除”这个决定的代价，需要业主知情。干净的逐条成绩看榜 F。
- **榜 E 的官方分对事后运行不公平，但这是官方分。** 官方评测把没人标注过的试验算 0 分，事后运行前 10 名里约一半没有标注。“只算有标注”是更公平的读法，但不能和榜单上的运行直接比，那些运行本身参与了标注池。2021、2022 的 NIST 成绩只有全体题目的均值，我们只跑了测试题。
- **榜 F 的主读法在打分前定好（2026-11-05 记入 STATUS）。** 读法 (c) 把“没写”算不符合，但英语和自主决策两条按符合算，这是标注指南的说法，也是方案 0.8293 那条线用的读法。这份测试集旧流程在 11-01 用过一次，方案本身没有拿它调过。条款标题里带了基准的名字，模型能看到。
- **所有榜都走判定作业，不经过对话。** 提示词、解析、作业、账本、模型网关和读取都是产品代码，但没有对话、技能和工作进程调度。对话路径另外抽样核对（见下）。榜上的排序只用整体评估，产品默认还对前 20 名逐条判定；有明确排除依据的试验在产品里排到最后，同样的行上差 -0.0045，小于重跑噪声（-0.0127）。
- **榜 G 只翻译了病历，试验还是英文。** 中文试验文本和 ChiCTR 不在任何完成的榜上。
