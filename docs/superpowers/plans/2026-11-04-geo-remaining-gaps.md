# GEO redesign: remaining release gaps

The November 3 Profound-based specification remains the acceptance target. This document records work that was investigated but is not established by the current candidate. A fixture walkthrough, an isolated DSH conversation, CI, main integration and deployment are different evidence.

1. **Project goal and agreement as native context.** A versioned/CAS implementation was prototyped and excluded from the candidate: appending the context to a user message makes the pinned OpenViking capture plugin merge it with the user's text, after which the memory gateway discards the entire message. Text-only tag removal also cannot distinguish a literal user-written tag. A producer-owned, separately injected context needs a request/session-bound durable proof, exact revision and membership checks, observable failure and a recovery protocol that preserves input when the pinned kernel has already claimed it. Verify owner and shared sessions, queue/steer, attachments, retries, revocation, stale versions, restart and the user's actual memory before exposing this feature.
2. **First-open native initialization.** Scoped navigation waits for its exact retained session. The scoped transport now holds the real workspace stream until the native client has retained that root; other streams continue, buffering remains bounded, and a timeout is visible and retried with a fresh frame. In an isolated pinned DSH + Chrome run, cold open, reload with the same session, a saved assistant response, and an intentionally delayed session-list timeout followed by retry all produced zero native `session/create` requests. This does not establish the behavior of every shared-member or child-session scenario. Settings, command/skill discovery and GoalBar still received scoped 403s in the isolated trace. The denied catalogue requests identify a session or agent; the GoalBar request was a read. The pinned client uses these catalogues for slash and skill-reference suggestions; an initial rejected GoalBar read has no snapshot and leaves the bar hidden. A synthetic keyboard exercise showed no visible slash/skill suggestion, but does not prove every local slash command fails. Determine their supported access and the effect of settings failures without widening authority. Complete delayed-list, reconnection and revoked-member checks on the real pinned client.
3. **Action-to-article completeness and concurrent placement.** The article catalogue and safety-review list search and page the project with a snapshot check and exact article deep links. For action derivation, `GeoSpine` now checks complete bounded reads of articles, choices, active errors, orders, owned links and sources (up to 10,000 each), and bounds the associated citation read; exceeding a bound produces an explicit error rather than treating a truncated list as complete. Other legacy callers retain their previous limits, other spine inputs still lack a count bound, and separate reads are not one transactional snapshot. Independently, the market can read skip/source choices and then read newly registered or reassigned articles as candidates; those articles were not in the earlier expanded choice IDs and could be planned despite the choice. The market's project lock does not cover choice writes or article registration, and reserving an order occurs in another transaction. Existing order recovery runs separately and must remain available. No real placement was made in this investigation. A nonblocking shared-lock prototype was withheld because its transient refusal can exhaust the current in-process import retries, leaving a delivered file or saved card without its GEO article registration. A separate durable-intent prototype has not been wired into production: it does not yet preserve all importer fields and update semantics, durable version proof after restart, exact plan outputs, or user-visible failure and retry. Design an atomic choice/candidate protocol with durable idempotent repair, then test registration and reassignment while a market tick is paused, skip/source changes, existing order recovery, and action-to-exact-version navigation beyond the old boundary.
4. **Analysis and journeys.** All registered views retain a business area, but several remain separately selected analyses rather than a single integrated metric or dimension within the original chart. Validate every view's filter, selection, export and return behavior against the approved mapping. A local synthetic project was created, a real DSH + DeepSeek response was saved, and a synthetic file was uploaded, parsed and read by DSH. This does not establish the three complete specification journeys: real diagnostic sampling and failed samples, article generation/revision/version/publication, and scoped finding-to-task-to-return. The consumer-AI probe and social collection services were outside the authorized available test environment.
5. **GEO skills.** This layout iteration has not independently revalidated all 51 deployed GEO skills or their actual runtime versions and tool grants. Do not label the redesign or its visual walkthrough as skill acceptance.

No production deployment was performed as part of this work.
