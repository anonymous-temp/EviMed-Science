# GEO redesign: remaining release gaps

The November 3 Profound-based specification remains the acceptance target. This document records work that was investigated but is not established by the current candidate. A fixture walkthrough, an isolated DSH conversation, CI, main integration and deployment are different evidence.

1. **Project goal, selections and memory.** A versioned/CAS goal implementation was prototyped and excluded from the candidate: appending the context to a user message makes the pinned OpenViking capture plugin merge it with the user's text, after which the memory gateway discards the entire message. The same limit applies to the existing GEO plan-selection and result-revision blocks. The revision block is now registered as platform context so it cannot be mistaken for a user's memory; until the transport is changed, a captured message carrying either block is withheld in full, including the user's own words. Text-only tag removal also cannot distinguish a literal user-written tag. A producer-owned, separately injected context needs a request/session-bound durable proof, exact revision and membership checks, observable failure and a recovery protocol that preserves input when the pinned kernel has already claimed it. Verify owner and shared sessions, queue/steer, attachments, retries, revocation, stale versions, restart and the user's actual memory before exposing persistent project context or claiming that these selected turns are learned.
2. **First-open native initialization.** Scoped navigation waits for its exact retained session. The scoped transport now holds the real workspace stream until the native client has retained that root; other streams continue, buffering remains bounded, and a timeout is visible and retried with a fresh frame. In an isolated pinned DSH + Chrome run, cold open, reload with the same session, a saved assistant response, and an intentionally delayed session-list timeout followed by retry all produced zero native `session/create` requests. One shared editor also opened the project and lost history access after revocation; a missing owner primary required the owner's explicit retry first. This does not establish every shared-member or child-session scenario. Settings, command/skill discovery and GoalBar still received scoped 403s in the isolated trace. The denied catalogue requests identify a session or agent; the GoalBar request was a read. The pinned client uses these catalogues for slash and skill-reference suggestions; an initial rejected GoalBar read has no snapshot and leaves the bar hidden. A synthetic keyboard exercise showed no visible slash/skill suggestion, but does not prove every local slash command fails. Determine their supported access and the effect of settings failures without widening authority.
3. **Action-to-article completeness and concurrent placement.** The article catalogue and safety-review list search and page the project with a snapshot check and exact article deep links. For action derivation, `GeoSpine` now checks complete bounded reads of articles, choices, active errors, orders, owned links and sources (up to 10,000 each), and bounds the associated citation read; exceeding a bound produces an explicit error rather than treating a truncated list as complete. Other legacy callers retain their previous limits, other spine inputs still lack a count bound, and separate reads are not one transactional snapshot. Independently, the market can read skip/source choices and then read newly registered or reassigned articles as candidates; those articles were not in the earlier expanded choice IDs and could be planned despite the choice. The market's project lock does not cover choice writes or article registration, and reserving an order occurs in another transaction. Existing order recovery runs separately and must remain available. No real placement was made in this investigation. A nonblocking shared-lock prototype was withheld because its transient refusal can exhaust the current in-process import retries, leaving a delivered file or saved card without its GEO article registration. A separate durable-intent prototype has not been wired into production: it does not yet preserve all importer fields and update semantics, durable version proof after restart, exact plan outputs, or user-visible failure and retry. Design an atomic choice/candidate protocol with durable idempotent repair, then test registration and reassignment while a market tick is paused, skip/source changes, existing order recovery, and action-to-exact-version navigation beyond the old boundary.

   Market decision, funding and reconciliation inputs now use bounded complete reads instead of silently using a prefix. Existing plans outside the first 5,000 candidate media are checked by exact media key before withdrawal. When a required 10,000-row bound is exceeded, the affected work fails explicitly; poll, publication verification and settlement do not yet have durable advancing cursors beyond that limit. Project identifiers for capacity diagnostics are restricted to operator-authorized metrics and are only retained for the current process's latest tick. Earlier successful independent reconciliation writes are not rolled back by a later capacity error. The candidate directory still limits new media to its first 5,000 rows, and no production-scale performance test is implied.
4. **Analysis and journeys.** All registered views retain a business area, but several remain separately selected analyses rather than a single integrated metric or dimension within the original chart. Validate every view's filter, selection, export and return behavior against the approved mapping. A local synthetic project was created, a real DSH + DeepSeek response was saved, and a synthetic file was uploaded, parsed and read by DSH. This does not establish the three complete specification journeys: real diagnostic sampling and failed samples, article generation/revision/version/publication, and scoped finding-to-task-to-return. The consumer-AI probe and social collection services were outside the authorized available test environment.
5. **GEO skills.** A private 3.1.0 archive was found in another local worktree and its archive digest, tree digest and 51 names match the previous handoff. The committed release receipt still binds 3.0.1; the newer archive is not part of the public repository or established on the build host. The 3.1.0 candidate contains conflicting legacy instructions and is under separate private correction. This layout iteration has not independently revalidated all 51 deployed GEO skills or their actual runtime versions and tool grants. Do not label the redesign or its visual walkthrough as skill acceptance.

No production deployment was performed as part of this work.
