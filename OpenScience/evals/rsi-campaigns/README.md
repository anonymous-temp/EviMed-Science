# Offline campaign runner

The closed adapter registry currently executes only `frontier-selection`, using the actual production candidate mapper and `frontierMixSelect` over complete frozen pools. Other surfaces return `campaign_consumer_not_qualified`; no model, DSH, cloud provisioning or production fallback exists in this runner. Consequently this version cannot incur paid stage spend. Adding a paid adapter requires the lab-owner `RsiCampaignBudget.reserve` / `beginSpend` / `settle` boundary and original run-reference recovery before registry admission.

```sh
node evals/rsi-campaigns/run.mjs plan manifest.json inputs.json
node evals/rsi-campaigns/run.mjs preflight manifest.json inputs.json deploy/rsi-campaign/config.example.json
node evals/rsi-campaigns/run.mjs run manifest.json inputs.json /run/rsi-lab/config.json
node evals/rsi-campaigns/run.mjs resume manifest.json inputs.json /run/rsi-lab/config.json
node evals/rsi-campaigns/run.mjs report manifest.json inputs.json /run/rsi-lab/config.json
node --test evals/rsi-campaigns/tests/campaignRunner.test.mjs
```

An unbound configuration returns `campaign_host_unavailable` before any checkpoint write or network call. A bound launcher supplies only `RSI_LAB_DATABASE_URL`; preflight reads PostgreSQL `current_user/current_database()` (the database must be `evimed_rsi_lab`), Alibaba instance metadata and the owner-mounted `/run/rsi-lab/purpose`. An instance declaration by itself is insufficient. Host identity must equal the configured lab instance. OSS/KMS bindings remain intentionally empty until the owner provisions them.

`runCampaign({manifest, inputs, configuration, store, attestLab, now, signal})` is the orchestration API. `inputs` contains `target`, `registration` and `sources` indexed by manifest source ID. Every source digest and the registration digest bind the exact JSON encoding; sources include complete pools and labels. Registration contains finite `baselineThreshold` and `thresholds`. It must be frozen before confirmation. Register `selection: {objective: "precision-desc", tieBreak: "threshold-asc"}`. Development rejects candidates that lose protected baseline picks or safety selections; among eligible candidates it freezes the highest precision, then lowest threshold. The policy JSON, digest and freeze time are checkpointed before confirmation, which executes only that policy and its baseline. Real confirmation requires distinct sealed source IDs, nonoverlapping registered source roots and row IDs. No selected-count proxy becomes CNY savings. Independent sealed confirmation provenance must be established by the evidence/registration layer; historical exposed gold cannot certify a fresh result. The runner never upgrades producer labels into independent evidence.

`productCampaignStore(database, labAccountId)` writes account-scoped normal ProductDocuments checkpoints with revisions. A session advisory lock serializes the campaign, and checkpoints bind manifest, datasets, labels, exposure, target dependency closure and registration. Completed stages verify stored result digests before reuse; running or paid uncertain stages park instead of dispatching another first answer. Deadline, cancellation and Beijing month rollover stop execution. Timer and incident-event launchers must reuse the immutable manifest ID to coalesce the same campaign; a changed manifest with that ID refuses resume.

`profiles/benign_fixture.mjs` supplies separate nonempty synthetic development/confirmation pools for the same orchestrator. Unit tests run the lifecycle without claiming medical benefit, cloud acceptance or signing authority. `run_frontier.mjs` retains historical-gold analysis separately. A runner report can contain the actual `qualified`, `not-qualified` or `inconclusive` fixed Python decision after a trusted independent evaluator supplies bound measured cost receipts and source checks. Without those it remains unqualified. `evaluateStatistics` invokes only the owned Python bridge, validates the returned input hash, limits output and runtime, and reports failure as unknown. The separate signing finalizer receives the bound report; no signing key enters this process.

The lab compose profile runs a frozen release-derived image as a nonroot user with a read-only base and one writable lab volume. The release image must contain this exact source tree and registered dependencies. It has no Docker socket, production key/mount or raw environment forwarding. The monthly systemd timer is day 1 at 02:00 Asia/Shanghai; owner-operated incident triggers invoke the same service with the same manifest identity. Nothing here installs or enables the units automatically.

Remaining qualification: real lab resource/role isolation and PostgreSQL lock integration, paid adapter recovery/budget wiring, independently sealed label provenance, real-population consumer qualification, live OSS/KMS and production serving activation are separate gates. This runner does not claim those gates passed.

## Trusted evaluator input

The optional fifth CLI argument is an owner-controlled evaluator profile under `/run/rsi-lab/`, with exactly `publicKeyPath`, `publicKeySha256` (Ed25519 SPKI DER SHA256) and `receiptPath`. Both files must be under the same owner mount. The receipt is `{payload, signature}`; the signature is Ed25519 over `canonicalRsiJson(payload)` and is verified before observation authority is returned. Payload type is `rsi-evaluator-receipt-v1`, with `expiresAt`, campaign `binding`, `frozenPolicyDigest`, `corpusDigest`, `registrationDigest`, `costProvenance: {type: "measured-normalized-cny", receiptId, complete: true}`, and complete `costs` rows (`group`, `arm`, `form: "original"`, `repeat: 0`, `cost`). Its `receipt.deterministic_qualification` is the independently issued finite-corpus qualification consumed by the Python contract. The launcher loads only public verification material; a model-supplied JSON file cannot grant the configured evaluator identity. The trusted signing finalizer later receives the checkpoint's candidate and evaluator receipt, never caller-provided signing/publisher attributes.

For this first adapter, `registration.statistics` supports deterministic finite-corpus groups, one `original` form with weight 1 and one execution per arm. Each registered group names nonoverlapping `rowIds`, a distinct `sourceRoot` matching actual pool `primary_source_id`, family and preregistered failure-slice membership. The consumer itself calculates quality as correct pick-vs-other classification over these frozen labeled rows. It never accepts caller-supplied quality scores. Statistical registration pins the consumer implementation digest and the complete confirmation corpus digest. Costs come only from the verified independent measurement receipt, including its documented normalization; zero model calls do not establish zero compute CNY. Synthetic tests can exercise a population-form interval with test-only external authorities; this is code-path evidence, never real population or medical qualification. Finite-corpus mode remains diagnostic and cannot be signed for serving. A paired-t registration with deterministicConsumer:true, the trusted-deterministic-consumer qualification and one original execution retains between-source-group sampling intervals. Other consumer/form/repeat combinations remain unqualified.

The Python bridge uses the registered RFC8785 digest codec shared with Node. Install only the pinned `requirements.txt` in the frozen image; the image's private `/opt/evimed/rsi-python` path is the CLI's evaluator dependency path. Missing dependencies, unknown cost, process failure or invalid output never become zero observations. Local tests use the private `.evimed-local/toolchains/rsi-python` dependency installation.


## Deployment records and verification

For an authorized incident, pass a sixth CLI argument naming a private transport profile under `/run/rsi-lab/`. It contains `role: "lab"`, the regional endpoint, two buckets and separate `identityRefs`; only the lab credential file is read. The campaign authorization includes `incidentId` and `incidentDigest` as well as agreement, run and source revision. Both runner and finalizer require the actual object and recheck its withdrawal. Do not pass an agreement ID as an incident stream.

Production uses the opt-in `deploy/web/docker-compose.rsi.yml` overlay with `OPEN_SCIENCE_RSI_CONFIG_HOST_DIR`. Without that binding the runtime creates no publisher project, starts no RSI polling timer and makes no cloud/model calls. Historical withdrawal journals remain addressable. The overlay mounts production credentials and public verification records only. No deployment is performed by the tests or this overlay's creation.

Local verification: install `requirements.txt` into `../.evimed-local/toolchains/rsi-python`, run `pnpm test:rsi`, and run the server's `rsi*.test.mjs` serially with a disposable localhost `OPEN_SCIENCE_TEST_POSTGRES_URL`. Tests cover actual runner-to-finalizer signing and real PostgreSQL staging/consumer witnesses/rollback. `reports/statistics-v4-qualification.json` records two seeds of 20,000 simulations per scenario; its mathematical scope is not a real frontier/evaluator certificate.

Only the frontier selector is an admitted execution surface in this version. Paid DSH adapters, skill/tool activation qualification and Harness2/GEPA arms remain closed until their independent measurement/supply gates are met. The repository's older experimental helpers are not reachable from the serving import graph; the old engine is not a lab fallback. Their final physical deletion and production window proof belong to cutover after the first accepted live campaign.
