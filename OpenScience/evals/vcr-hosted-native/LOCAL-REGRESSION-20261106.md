## Platform and test-environment findings

- macOS `/var` and `/tmp` aliases conflicted with exact-realpath checks, and long
  Unix socket paths failed. Replays under a real short temporary directory
  passed the relevant authorization, AgentBay, controller and workspace-entry
  checks. No production no-symlink, PID reuse or ownership rule was relaxed.
- Linux `/proc`, GNU `date`/`xargs`, Bash behavior and prepared native images
  are genuine execution prerequisites. The AgentBay test's macOS substitute
  produced an empty digest because BSD `xargs` rejects `-d`; the code safely
  retransferred the files rather than claiming reuse. These are not Linux
  guest passes and do not justify a weaker production hash check.
- The disposable Colima PostgreSQL clock led the macOS host by about 39 ms in
  direct client measurements. UTC alone fixed the civil-date cases. Separate
  private clock-offset probes explained GEO fact/metric ordering and memory
  reset assertions; those diagnostic passes are not acceptance evidence.
- Frontier faith checks mix database-written `lead_at` with application-written
  diagnostic times. Controlled offsets showed both redundant rechecking and
  a rewritten lead being treated as already checked. The observed deployment
  was the isolated cross-clock test environment; production impact is an
  inference, not an observation. A future fix should bind checks to the exact
  content/version under the row lock, rather than tolerate clock differences.
  No Frontier or GEO production freshness logic was changed in this VCR work.
- Cowork preparation-dependent tests require the workflow's separate native
  assessment inputs. Missing local inputs are recorded; they are not disabled
  or treated as successful. Final Linux CI prepares and runs them separately.
