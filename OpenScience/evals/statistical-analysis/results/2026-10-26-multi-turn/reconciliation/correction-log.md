## 2 更正清单

### C1 阳性预测值用了错误的人群比例（实质）

- 位置：第 5 节第 5 条。
- 原文：“本样本恶性占 37.3%（富集样本），PPV 0.984 是在这个比例下得到的；真实筛查人群中恶性比例低得多，同样的敏感度/特异度会给出低得多的 PPV。”
- 问题：PPV 0.984 是留出集 171 例算出来的，其恶性比例为 64/171 = **37.4%**；37.3% 是**全数据** 212/569 的比例，两者差 0.1 个百分点，但分母不是同一批人。用全数据的比例去“解释”留出集的 PPV，是把两套分母混在一起。
- 依据：`cohorts.held_out = {n: 171, malignant: 64}` → 0.374269；`ppv_selfconsistent` 用 0.96875 / 0.990654 在 37.43% 下还原出 PPV 0.9841，与混淆矩阵的 62/63 一致；结果文件自己的 `analyses[0].discrimination.testPrevalence = 0.3743`，也与 37.4% 一致。全数据 37.26% 只出现在 `profile.malignantPrevalence`。
- 改后：第 5 节第 5 条改为“PPV 0.984 是在留出集恶性占 64/171 = 37.4% 这个比例下得到的；全数据的 212/569 = 37.3% 是另一套分母，不能拿来解释留出集的 PPV”。
- 影响：结论方向不变（0.984 在全数据比例下换算也是 0.984），但读者不会再误以为 PPV 是全体 569 例上的性质。

### C2 阳性预测值缺分母、且与敏感度混在一起（口径）

- 位置：第 3 节表 2 之后（原文只给数值，未说口径）。
- 原文：“敏感度 0.969（95%CI 0.893–0.991），特异度 0.991（0.949–0.998），阳性预测值 0.984（0.915–0.997）……”
- 问题：没有说明 PPV 的分母是“被判为阳性的 63 例”，也没有把它与同段的敏感度（分母 64 例真实恶性）区分开；读者很容易把 0.984 与 0.969 当成同一件事的两种算法。

### C3 “两个漏诊靠移动切点救不回来”与同段数据矛盾（实质）

- 位置：第 3 节阈值敏感性段末。
- 原文：“降到 0.1 才多识别 1 例恶性，代价是假阳性增到 10 例。两个漏诊样本的概率分别为 0.115 与 0.016，靠移动切点救不回来。”

## 5 复算方法（可直接执行）

```python
import pandas as pd
from sklearn.metrics import roc_auc_score, brier_score_loss, confusion_matrix

p = pd.read_csv('data/prior-predictions.csv')
te = p[p.split == 'test']
y = (te.y_true == 0).astype(int)          # 数据字典：0 = 恶性，故 1 = 恶性

print(te.y_true.value_counts())            # 64 恶性 / 107 良性 → 37.43%
print(roc_auc_score(y, te.p_malignant))    # 0.9933
print(brier_score_loss(y, te.p_malignant))  # 0.0216
print(confusion_matrix(y, (te.p_malignant >= 0.5).astype(int)).ravel())
# [106  1  2 62] → TN 106, FP 1, FN 2, TP 62；阳性 63 例
print(62 / 63, 62 / 64)                    # PPV 0.984 vs 敏感度 0.969

for prev in (64 / 171, 0.05, 0.01):        # 留出集 / 换算示意
    print(round(prev, 4), round(se * prev / (se * prev + (1 - sp) * (1 - prev)), 4))
```
