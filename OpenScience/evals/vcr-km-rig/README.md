# 生存曲线图：数字化加重建，误差大概多少

这个台子回答一个问题：**“这种风格的图，误差大概多少？”**

做法是反过来：先用引擎自己的模拟器造出真值已知的试验，再把试验画成各种风格的图，然后让平台真实的数字化器读图，再让引擎真实的重建任务把读出的曲线还原成伪个体数据，最后拿还原出来的中位数、风险比、曲线、风险人数去和真值相减。它只量误差，不改产品代码；量的过程中发现的数字化器问题见“台子发现的问题”一节。

## 怎么量的

1. **真值。** `truth.R` 用引擎的生成器 `vcr_sim_tte` 模拟 5 个试验，每个 3 个组：T1 指数分布每组 300 人、两组差得开；T2 威布尔每组 180 人、尾巴长；T3 每组 120 人、曲线靠得近、每年 10% 失访；T4 每组 60 人、台阶少而大；T5 威布尔（风险递减）每组 600 人、台阶多而小。图上画出来的是**样本**的 Kaplan–Meier 曲线，所以“真值”是这个样本的曲线、中位数、总事件数、各时点的风险人数和 Cox 对数风险比（引擎自己的 Kaplan–Meier 与 Cox 代码算的）。分布的真中位数和给定的风险比也记在 `results.json` 的 `trials` 里，抽样误差和重建误差不要混为一谈。
2. **画图。** `styles.py` 用 matplotlib 画 33 种样式：先是只改一个因素（线宽、颜色、网格、风险表、删失标记、线型、组数、纵轴百分数、分辨率与 JPEG、坐标轴形状、置信带），再是 3 个组合（黑白期刊、网页图、survminer 风格）。
3. **数字化。** 跑平台真实的 `runtime/mcp/evimed-research/vcr_curve_digitize.py`（本次是 1.0.1），从它的容器入口（`main`：request.json、输入目录、输出目录）进去，请求和控制面（`vcrCurveDigitizer.mjs`）造的一样：声明的标定是每根坐标轴首末刻度的值（从真值读，也就是“run 把刻度标签读对了”这种理想情形），曲线按颜色指名（颜色也是精确的）；控制面对返回结果的检查（`checkDigitization`：点数、时间递增、生存率不上升且在 0 到 1 之间、不为负）也照做。数字化器若因“找到几个坐标框”而拒绝，就和 run 一样把它列出的最大候选框作为 `plotArea` 再试一次（这次一共用到 0 次）。
4. **重建。** 引擎的 `evidence.reconstruct_km`（方法 1.1.0）在**四个信息等级**上各跑一次：论文给了风险表和总事件数（等级 1）、只有风险表（2）、只有总事件数加各组起始人数（3）、只有曲线加各组起始人数（4）。风险表和总事件数都是真值的精确数，和论文印出来的一样。任务经 `batch_jobs.R` 运行（引擎的 `vcr_read_job`、`vcr_run_job`，和 `service/run_job.R` 做的事相同，只是引擎只加载一次）；台子在每个等级上抽一个任务，核对 `run_job.R` 写出的结果与伪个体表和它一致（时钟字段除外，`results.json` 的 `checks`）。
5. **评分。** 全部是减法，没有模型参与：
   - **数字化曲线 RMSE**：数字化出来的曲线和真曲线在 0 到曲线末端之间 721 个等距点上的生存率差的均方根，单位是“百分点”（0.30 就是 0.003）。
   - **重建曲线 RMSE**：同样的量，用重建出的伪个体算出的 Kaplan–Meier 曲线。
   - **中位数相对误差**：|重建中位数 − 真中位数| / 真中位数（两组都算；某组中位数没到达就不算）。
   - **log HR 绝对误差**：|重建的对数风险比 − 样本的对数风险比|。0.01 约等于风险比差 1%。等级 4（只有曲线）引擎规定风险比不可估计，所以没有这一项。
   - **风险人数误差**：重建出的各风险表时点（0 时点除外）的在险人数和真值之差，占该组人数的百分比。等级 1、2 因为重建被质检逼到和风险表对上，这一项是构造出来的小；等级 3、4 才是真正的误差。
   - **被重建拒绝**：重建的质检（风险人数、总事件数与原文差超过容许）不通过，引擎返回“不可估计”，不给任何数字；这种情况单独计数，不进误差平均。

## 坐标轴写错 10% 会不会被发现

模拟 run 把末刻度的值读错了 10%（时间轴或生存率轴，偏大或偏小），在三种能读的样式上各做一遍。三道关卡依次是：数字化器自己的告警（刻度间距不是整齐的数、曲线起点不是 1）、重建的风险人数与事件数质检、以及什么也不查的情形。

- 刻度能找到时（`base`、`axes_padded`），数字化器 5 张里 5 张报 `x_tick_spacing_unusual` 或 `y_tick_spacing_unusual`，生存率轴写错还会同时报 `curve_start_not_one`。**能被发现，但只是告警，不是拒绝**；数字化曲线的 RMSE 已经到 3 到 5 个百分点。
- 论文给了风险表时，重建的质检几乎总是把它拦下（时间轴×1.1 时 5 张里 3 张被拒，其余几种全拒）。
- **论文只有总事件数或只有曲线时，没有第二道关**：重建照常给出结果，中位数偏差 10% 到 15%，只有数字化器那条告警在提醒。
- 刻度找不到时（`ticks_in`），数字化器只报 `no_tick_marks_found`，这条告警在每一张这样的图上都会出现（声明对不对都有），**不针对写错的值**；此时靠风险表的质检拦截，没有风险表就拦不住。
- 对照：声明正确时，33 种样式上没有出现过一次“刻度间距不整齐”的误报。

## 台子发现的问题

**已修，在 `vcr_curve_digitize.py`（1.0.0 到 1.0.1），测试 `JournalFigures` 三条，每条在旧代码上都失败、新代码上通过（数字化器的测试文件共 29 条，全过）：**

1. **黑色加灰色的两条曲线，被拒绝。** 声明灰色时，数字化器先问“图里有没有带颜色的线”，没有（黑和灰都不带色）就以 `colour_not_found` 拒绝，而灰色那一支本来就写好了。改了顺序以后又暴露第二层问题：按“与白色的混合”去找灰色，黑线本身也算灰色的“更浓”版本，于是 `curve_ambiguous`。现在灰色曲线忽略比它暗得多的东西和它周围两个像素（黑线抗锯齿的边也是灰的）。黑白印刷是最常见的调色板之一；这个改动使 `col_black_grey` 和 `combo_journal` 从 5/5 拒绝变为 0/5。
2. **黑色曲线遇到粗的坐标轴和边框，被判为“有两条线”。** 裁剪区正好落在坐标轴线中间，分辨率一高，轴线粗到在区内留下一整行，被当成第二条同色的线。以前只把顶部和右侧的框线剔掉，且宽度写死 6 个像素；现在四边都剔，宽度随图的大小放大。
3. **曲线从零刻度左边半个像素开始，整张图被控制面拒绝。** 坐标轴比刻度长出一截（ggplot 风格）时，曲线第一个点的时间是负的（如 −0.025 个月），控制面的 `checkDigitization` 把负时间当作“结果前后不一致”（502），一张本来读对了的图整张丢掉。现在时间不小于 0。这个问题在 `axes_padded` 和 `combo_survminer` 上 5/5 出现（修之前这两种样式没有任何结果）。

**没修，列在这里：**

- **刻度朝内且坐标轴长出一截（`ticks_in_padded`）。** 数字化器只在坐标轴外面找刻度；找不到就把声明的首末值套在坐标轴两端，而轴比刻度长出一截，于是整条曲线错位：数字化 RMSE 2.8 个百分点（正常是 0.3），等级 3 的中位数差 8.5%，等级 1 有 4/5 被重建质检拒绝。它给了 `no_tick_marks_found` 告警。刻度朝内但轴不长出的图（`ticks_in`）没有问题。修法是往坐标轴里面也找刻度，但曲线起点的平台和网格线会和刻度连在一起，不是几行能修好的。
- **暗淡的颜色加低分辨率加重压缩的 JPEG（`combo_web`，72 dpi，质量 60，绿和紫）。** 调色板只认得其中一种颜色，另一种以 `colour_not_found` 拒绝（3 张），还有一张 `curve_ambiguous`。颜色的饱和度下限（`paletteMinChroma` 60）对这种图太严。
- **同色一实一虚（`col_black_dashed`）。** 设计上就拒绝（`colour_ambiguous`），文件头也写了“同色曲线靠像素分不开”；用线型把它们分开是个新功能，没做。
- **轴线厚度超过 6 个像素**（比如 600 dpi 的扫描）认不出坐标轴，以 `plot_area_not_found` 拒绝；这次的样式里没有，是写测试时碰到的。
- **曲线起点被另一条曲线盖住，或在第一个像素内就陡降**，数字化器报 `curve_start_not_one`。这是诚实的告警，误差没受影响（表里的数字已含），但它在 161 次成功的数字化（322 条曲线）里出现了 115 次，读的人容易把它当成标定出错。

## 台子没有覆盖的

- **真实的期刊图。** 这里的图都是 matplotlib 从精确数据直接画出来的：字体干净、没有扫描噪声、没有 PDF 栅格化的缩放、没有图例压在曲线上、没有多面板、没有手工标注。真实图只会更差，这些数字是**下限**，不是预期值。
- **曲线重叠。** 只有试验自己画出来的重叠（T3 两条曲线靠得近，但没有大段重合）。两条曲线大段重合、或置信带压在另一条曲线上，不在这里。
- **一个 run 读错东西。** 颜色是精确的，刻度值除了“写错 10%”这一种情形都是对的；真实的 run 可能读错颜色、读错单位、把轴的最大值当成最后一个刻度。
- **风险表数字。** 论文印的数字被当成精确值给了重建；真实论文里数字可能四舍五入、排版错位、与图不在同一时点。
- **试验的形态。** 时间单位只有“月”；删失只有管理性删失加一种失访；没有曲线被截断的图（纵轴不从 0 开始）；每图最多 3 条曲线。
- **下游。** `population.literature` 怎样使用重建出的数据，不在这里测。
